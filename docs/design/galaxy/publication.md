# galaxy — 发布

## 背景与目标

发布是本模块里唯一一个让内容**离开私有边界**的动作。在它之前，工程、草稿、版本与资产都只对拥有者可见；发布之后，一个不携带任何凭证的请求就能读到它。

正因为不可逆性只体现在这一步，本子模块承担了 galaxy 的大部分安全约定。

成功的衡量标准：

1. 发布后，**未登录的人**用发布地址能读到这个站点，且页面上的素材都显示得出来。
2. 发布物**自洽**：它引用的每一个素材都确实在公开区，不存在"发布成功但图裂了"。
3. 发布物**只**引用本工程的资产。内容里出现别处的取字节引用时，发布被拒绝并指出那一处——而不是发布出去之后由访问者发现。
4. 发布物里的脚本**跑得起来，但把数据发不出去**。
5. 发布物与主应用**不同源**，因此它的脚本碰不到任何人的会话。
6. 一个版本一旦发布过，此后任何时刻重新发布它，整组产物逐字相同。
7. 撤回发布后，**该槽的**地址立刻不可达，而另一个槽的地址不受影响。

## 功能行为

### 发布做四件事

| 阶段 | 做什么 |
|------|--------|
| 1. 受理与校验 | 判定这个版本能不能发布；不能则终止，不留任何痕迹 |
| 2. 媒体上架 | 把该版本文件组里的**资产条目**搬到公开区（已存在的跳过）。**文本不上架**——发布态由服务端从私有区读它 |
| 3. 产物落库 | 把解析/渲染产生的文本写成**内容对象**（已存在的按内容摘要跳过），并把产物**清单**（路径 → 内容摘要）存成一组记录 |
| 4. 切换与生效 | 把工程的发布指针指向这份清单；此后地址按它返回 |

**准入由两把闸门共同决定**：`galaxy.project.publish` 权限码（见 [README.md](README.md)）与工程归属（见 [project-versioning.md](project-versioning.md)）。**只能发布版本，不能发布草稿**——草稿是可变的，"发布一个可变的东西"没有意义。

### 校验规则

校验的规则集合**只有一个实现入口**（见 [README.md](README.md) 的"引用完整性的唯一入口"）。它的输入是**文件组**；`docs` 槽下还包含它渲染出的产物：

| 规则 | 不满足时 |
|------|---------|
| 每一处取字节的引用都落在本文件组的**某一条条目**上（文本或资产） | 拒绝，指出那一处所在的文件与位置 |
| `docs` 槽下，每一处文档间链接都落在文件组里 | 拒绝，指出是哪一份文件的哪一处 |
| 产物的总量与文件数不超过上限 | 拒绝，指出上限 |

**"引用完整性"要区分两类写法**，这是设计里最容易搞混的一处：

| 写法 | 例子 | 规则 |
|------|------|------|
| **取资源的引用** | `<img src>`、`<video src>`、`<audio src>`、`<link href>`、CSS `url()`、`srcset`、`<source src>`、脚本里取资源的路径 | 只能落在本文件组的某一条条目上。**发布物不得从本工程之外取任何一个字节** |
| **导航链接** | `<a href="https://example.com">` | 可以是任意地址。用户链到外部网站是他的意图，不是资源引用 |

这条区分同时回答了"只能引用资产管理里面的资产"到底在禁什么：**禁的是让页面去别处取字节，不是禁止用户写出一个外部链接。**

### 扫描不是边界，响应头才是

发布时那趟扫描**尽力**发现内容里的外部资源引用（`http://`、`https://`、协议相对地址、`data:` 等出现在取资源位置上的写法），目的是**给用户一条可操作的错误**："第 N 处引用指向了外部地址"。

但它是**尽力而为**，不是安全边界：**枚举 HTML 里"取资源"的写法不可能穷尽**——属性会新增、特性会演进，任何一份枚举清单都在它写完的那天开始过期。把边界建在枚举上，等于承诺一件做不到的事。

**真正的边界是交付时附加的内容安全策略响应头：**

| 指令 | 取值 | 挡住什么 |
|------|------|---------|
| `default-src` | `'none'` | 一切未显式允许的资源类型 |
| `img-src` / `media-src` / `font-src` | `'self'` + 公开域 | 图片、音视频与字体。**两个来源都要允许**：起点是本工程在发布域上的路径（一次重定向），终点是本工程的公开资产（见 [site-model.md](site-model.md)） |
| `style-src` / `script-src` | `'self'` `'unsafe-inline'` | 允许内联的样式与脚本，也允许产物里以文件形式存在的 JS 与 CSS |
| `connect-src` | `'self'` | **脚本可以跑，但发不到别处**：同源请求可用，`fetch` / `XHR` / `WebSocket` 指向任何外部地址都被挡下 |
| `frame-src` / `object-src` | `'none'` | 发布物不能嵌套别的页面或插件 |
| `form-action` | `'none'` | 不能把访问者填的东西提交到任何地方 |
| `base-uri` | `'none'` | 不能用 `<base>` 改写内容里所有相对地址的解析基准 |

由浏览器执行这条策略，意味着**扫描漏掉的写法仍然取不到东西**。两层机制的分工必须说清楚：**扫描负责"告诉用户哪里错了"，响应头负责"让错的无论如何也做不到"。** 只有前者会让一个漏检变成一个真实的越界；只有后者会让用户只看到一张裂图而不知道原因。

**`'self'` 是发布域整体，不是本工程。** 一个产物因此可以加载另一个工程的公开脚本或图——但那本来就是公开内容，不构成越权；私有对象一个都取不到（靠对象权限，见下）。这一条要写清楚，免得把 `'self'` 当成"本工程"来论证。

**同桶之后，这条保证的落点变了。** 允许的来源是**桶主机**，而私有对象也在同一个主机上——因此"取不到东西"不再来自"来源不同"，而是来自**对象权限**：私有对象匿名取被拒。这是同桶换来的代价（见 [asset-library.md](asset-library.md) 的"公开区与私有区在同一个桶里"），也是那条"临时凭证不得能声明权限"成为硬性约束的原因。

**允许的桶主机只有一个来源：桶地址这一个配置值。** 上架时写入的公开地址与响应头里允许的来源都从它派生——两处各写一份的表现是"地址指向 A、策略允许 B"，而它的表现是"发布成功了但什么都显示不出来"。`'self'` 不构成第二处：它就是发布域自己，不由任何配置项给出。

**响应头不改内容。** 这是交付层的事。内容本身：`site` 槽的文本逐字来自用户，`docs` 槽的产物是渲染出来的——那是本模块**唯一**一处允许服务端生成标记的地方，它的代价由"渲染规则按版本钉住"承担（见 [site-model.md](site-model.md)）。

### 解析

发布时把源侧的记号解析成产物里的形态，**逐字替换，不解析 HTML**（理由见 [authoring.md](authoring.md)）。因此记号出现在元素属性、内联 CSS、`srcset` 里都成立。

| 记号 | 解析成 |
|------|-------|
| `asset://<资产标识>` | 该资产在文件组里的**路径**（站点内绝对地址）；取字节时再由服务端按路径重定向到公开区 |
| 文档间相对 `.md` 链接（`docs` 槽） | 站点内的绝对地址 |

**产物里不出现公开区地址。** 公开区地址按内容摘要寻址、只在重定向的那一刻给出；产物里写的是站点内的路径。因此构建产物一个字节都不用改，工程标识也不必出现在产物里（见 [site-model.md](site-model.md)）。

**解析产生的文本是新的内容对象。** 记号被替换、文档被渲染，产物的字节因此与版本的字节**可能不同**——那些不同的文件按内容摘要写成新对象，相同的文件直接复用版本已经在用的对象（不产生第二份）。重复发布同一个版本，解析结果逐字相同，因此也不会产生新对象。

**`docs` 槽还多一步渲染**，且它是一次**确定性**变换：同一版本重复渲染产物逐字相同；渲染规则**按版本钉住**，重新发布用版本记录里的那一版规则，而不是当前最新的（见 [site-model.md](site-model.md)）。**渲染只作用于 markdown；文件组里的站点文件按原路径原样进产物**，与 `site` 槽一样逐字相同。

### 媒体上架

**只上架该版本引用到的资产，不搬整个资产库。** 一个工程可能有几百个素材而某个页面只用了三个，整体搬运会让一次发布的时间与成本取决于一个与它无关的数字。

**上架按（工程标识，内容摘要，媒体类型）寻址，因此是幂等的**：目标对象已存在即跳过，不重写。由此得到两条结果：

- 重复发布同一个版本不产生新字节。
- **代价：跨工程不再共享同一份字节。** 两个工程用到同一张底图是两份对象、两份存储；换来的是"这些发布物属于哪个工程"在键上一眼可见（见 [asset-library.md](asset-library.md) 的"对象键"）。

**上架后不做回收**：撤回发布或被后续发布取代时，先前上架的公开副本留在原处（见"待定决策"的回收）。

### 发布记录与对外地址

每次发布产生一条**发布记录**，保存本次解析好的产物清单：

| 内容 | 说明 |
|------|------|
| 发布标识 | 由 aladdin 分配 |
| 所属工程 / 所属内容槽 / 目标版本 | 这次发布的是哪个工程的哪个槽的哪个版本 |
| 产物清单 | 路径 → 内容摘要（产物文本的对象键）。**字节不在库里** |
| 发布人主体标识 / 发布时间 | 留痕 |

**产物清单落库，而不是每次请求现算。** 理由与"库内对象键是头像有没有的权威"同构（见 [../profile/avatar-storage.md](../profile/avatar-storage.md)）：库里存着"当前发布的是什么"这一事实，取用者只读它，不需要在请求路径上重新跑一遍解析与渲染（那会要求取用时重新读文件组、重新查资产，把一个已经完成并校验过的结论变成每次请求都要重算的东西）。**而清单只有路径与摘要，没有内容本身**——库因此不随内容增长。

**产物清单放在独立的发布表上，不放在工程行上。** 工程行会被列表接口读取，往它上面挂一组记录，正是头像那一课要避免的事（见 [../profile/avatar-storage.md](../profile/avatar-storage.md)）。**发布指针住在内容槽行上，每个槽一个、可空**——两个槽因此各指各的，互不影响。

**对外地址是该槽的根接上路径。** `site` 槽是 `<发布域>/g/<工程标识>/<路径>`，入口 `<发布域>/g/<工程标识>`（与 `.../index.html` 同一页）；`docs` 槽是 `<发布域>/g/<工程标识>/docs/<路径>`，入口 `<发布域>/g/<工程标识>/docs`（与 `.../docs/index.html` 同一页）。服务端按**该槽当前发布的那一份**清单分派：

- 该路径是一条**文本条目**：服务端返回产物文本，`ETag` 是它的内容摘要，带 `Cache-Control: no-cache`；
- 该路径是一条**资产条目**：返回一个**重定向**到公开区地址。

**槽根是唯一一处"地址不带结尾斜杠"的地方，因此它要先补一个斜杠。** 页内相对地址按文档所在的目录解析，而站点根是 `<发布域>/g/<工程标识>/`——浏览器停在不带斜杠的入口上时，`style.css` 会被解析成 `/g/style.css`，而那一条不在集合里。表现是"发布成功了，但样式全丢、图片全裂"，而内容与上架其实都是好的。因此交付入口对**不带结尾斜杠的槽根**先 301 到带斜杠的形式（`site` 槽与 `docs` 槽各一处）。**这条重定向不查工程存不存在**：否则"重定向还是 404"本身就成了"这个标识是真的"这条信号，与下面那张表冲突。**子目录不在此列**——它不做 `<路径>/index.html` 回落，集合成员测试仍然只查清单。

两种取字节方式的取舍与理由见 [site-model.md](site-model.md) 的"取字节"。文本条目的内容类型由扩展名白名单给出；资产条目的内容类型是上传时声明的那个。

它是一条**浏览器直连的非 RPC 入口**，因此要在既有的直连入口判定处登记（见 [../../../docs/ssot-registry.md](../../../docs/ssot-registry.md) 的 `isBrowserEntry`）——发布态的读取不走鉴权拦截器（见 [README.md](README.md) 的"发布即公开"）。

| 情形 | 返回 |
|------|------|
| **不带结尾斜杠的槽根** | **301** 到带斜杠的形式（唯一一条不查工程存不存在的回答，理由见上） |
| 该槽已发布，路径在集合里 | 该路径的产物（资产条目是重定向） |
| 路径不在集合里 | **"不存在"** |
| 该槽未发布 / 已撤回 | 同上，"不存在"（该槽所有路径都不存在，不只是入口） |
| **该槽没有启用** | 同上，"不存在" |
| 工程已删除 | 同上，"不存在" |
| 工程标识不可猜中 | 同上，"不存在" |

**这几种情形返回同一个否定结果。** 区分它们等于告诉一个猜地址的人"这个标识是真的"或"这一页是真的，只是还没发布"——那是一个比"猜不到"更有用的信号。

### 发布域上还有一条预览通道

同一个源上还有一条**需凭证的草稿通道**：`<发布域>/g/p/<凭证>/<工程标识>/<路径>`，供工作台看草稿渲染成什么样（见 [authoring.md](authoring.md) 与 [site-model.md](site-model.md) 的"预览"）。**它按槽给出**：`site` 槽就是上一条形状，`docs` 槽在工程标识之后多一个 `docs` 段。凭证绑在（工程，槽）上。

它复用**同一段取字节的实现**，差别只有数据源与地址来源：

| | 发布态 | 预览态 |
|--|-------|-------|
| 取哪一份清单 | 当前发布的那条记录 | 当前草稿 |
| 凭证 | 无（地址即凭据） | 短时凭证，随地址走 |
| 资产地址 | 公开区（匿名可读） | 私有区的短时地址 |

**它不改发布这条路的任何判定。** 判据仍然只有一条：这一条路径在不在**当前发布**的产物清单里。草稿通道存在与否，不改变任何一次发布态的结论。

**"发布域只服务发布物"里的"发布物"要读成"用户内容"。** 草稿是用户内容的一种形态，因此它与发布物同源是自洽的：这一条硬约束要的是"与主应用不同源"（见下），而不是"这个源上只许有已发布的那些字节"。隔离因此没有变化——发布域上跑的仍然只有用户自己的代码。

### 撤回发布

撤回把**该槽**的发布指针置空。

- 该槽所有路径**立刻**不可达（不依赖缓存过期），不只是入口那一页。文本响应是校验式的（`no-cache`），因此下一次请求就打到源上；媒体那一跳由公开区对象承担，撤回后服务端不再给出它的地址。
- **另一个槽不受任何影响**：它的指针、版本与地址都不动。
- 该槽对外状态回到"有版本未发布"（见 [README.md](README.md) 的"状态流转"），因此可以重新发布同一个版本，也可以把指针切回它。
- **公开区的副本不因撤回而删除。** 它是一份独立对象，召回它需要一次对账（见"待定决策"）。

### 不同源：一条硬约束

**发布域必须与主应用源不同源**，且这一点在**启动时校验**：发布域与 `public_base_url` 同源时拒绝启动。

理由不是整洁，是隔离：发布物里跑着用户写的脚本。同源意味着那段脚本与应用共享 origin，于是它能读写应用的 cookie 与本地存储、能代表访问者向应用发起请求——**每一次"我发布了一个页面"都会变成一次注入**。

这与头像的预签名地址天然不同源（在 COS 域上）是同一个道理，但发布物更危险，因为它承载的是任意脚本而不是一张图片。

### 可见性与前提

**发布态不显示任何主体信息**：不显示拥有者的昵称、头像或主体标识。发布物是公开匿名的，把展示信息带上去会凭空引入一条身份暴露面（见"待定决策"）。

**发布物内不得承载任何秘密。** 公开匿名，且地址可能被转发——这与头像那条约束同源但更强（头像是发给本人，发布物是发给所有人的）。

### 未配置时

发布需要两项配置：对象存储桶与发布域（见 [../config/server-config.md](../config/server-config.md)）。公开区的素材与私有资产在**同一个桶**里，因此发布复用的是资产那一项配置，只多了发布域。

| 情形 | 行为 |
|------|------|
| 桶与发布域都为空 | 资产、**内容**与发布都不可用（字节没有地方放）。只有工程元数据可写，前端**不渲染**发布入口 |
| 桶给了、发布域为空 | **发布未启用**（这是常态）：资产与内容可用，发布入口不渲染 |
| 两者都给 | 发布可用 |
| 只给发布域、桶为空 | **拒绝启动**，信息里指出缺的是桶 |

最后一条与头像、GitHub 登录、引导是同一条取向：半套配置的失败方式既不是"没启用"（界面会渲染一个点了报错的入口），也不是"配错了"（启动时能看见），而是"看起来配好了"，直到第一次发布才失败。**"只缺发布域"不是半套**——那是"没启用发布"，与"没启用头像"同类，是配置的常态而不是错误。

## 边界与约束

- **发布物是一组文本产物，字节只来自两处**：用户写入的文本（`docs` 槽下经一次确定性渲染）与本工程的公开资产。这是本模块的顶层约束（见 [README.md](README.md) 与 [site-model.md](site-model.md)）。
- **发布物不含任何服务端渲染的内容。** 服务端只做校验、改写与上架，不生成用户没写的标记。
- **不代理发布态的资源字节。** 媒体从公开区直连，服务端只承担 HTML 本身（几 KB 量级）。
- **不做自定义域名、不做 SEO 相关产物（`sitemap`、`robots`）、不做访问统计。**
- **发布态不参与 RBAC 判定**，因此它也无法按主体裁剪内容——一个发布物对所有人是同一份。需要"只给某些人看"的内容，不该走发布（见"待定决策"）。
- **不给发布物配置独立的跨域策略**：发布物不需要被别的页面以脚本方式读取，公开区对象按直连取用即可。

## 可验证性与长程执行

**本子模块属于长程任务。** 一次发布要把一批资产搬到公开区——其中可能有几十 MB 的视频，可能慢、可能因外部依赖中断。中断必须可判断、可续跑，而不是从头再来。

### 阶段划分与完成判据

| 阶段 | 完成的可观测判据（产出了什么可检验的信号/记录） |
|------|------------------------------------------------|
| 受理与校验 | 校验结论已留痕，含发布标识、工程、版本与发起主体；被拒时给出具体位置，且**不产生任何持久化影响**（指针未动、公开区无新对象） |
| 媒体上架 | 该版本引用的**每一个**资产在公开区都存在且内容摘要一致；文本不上架；留痕含被引用数、新上架数与跳过数 |
| 产物落库 | 发布记录可按发布标识读回，**每个路径**的摘要与本次解析的结果一致；本次新增的内容对象都已落盘 |
| 切换与生效 | 无鉴权请求发布地址（含子路径）取到的正是本次产物；生效时间已留痕 |

### 进度记录（让进展可见）

- 每个阶段开始/结束须产出**可被外部读取的记录**，使得无需重跑即可回答"现在到第几步、上一步结果如何"。
- 记录的具体字段与格式遵循 [../../observability.md](../../observability.md)，本节只声明**哪些阶段必须留痕、留痕需包含哪些信息维度**：

| 阶段 | 必须留痕的信息维度 |
|------|------------------|
| 受理与校验 | 发布标识、工程标识、版本标识、发起主体、校验结论、被拒的引用标识（若有） |
| 媒体上架 | 被引用资产数、新上架数、跳过数、上架字节总量、耗时 |
| 产物落库 | 发布记录标识、路径数、新增内容对象数与字节数 |
| 切换与生效 | 生效时间、参与确认的请求标识 |

**留痕不含文本全文**（见 [../../observability.md](../../observability.md) 与 [authoring.md](authoring.md) 的同源约束）。

### 检查点与恢复（让失败可续跑）

- **检查点边界：设在"产物落库"完成之后。**
  - 落库**之前**的中断（校验中、上架中）：对外**不留任何影响**——指针没动，所有路径返回的还是上一次的产物。重试即从受理开始，且因为上架与内容对象都按内容摘要幂等，重试不需要任何清理。
  - 落库**之后**、切换之前的中断：从**切换**继续即可，不需要重新上架、不需要重新落库。库里的发布记录已经是完整的。**整套一次性生效就落在这里**：切换是一个单点，因此不存在"入口是新的、某一页还是旧的"。
- **幂等/去重要求**：
  - 媒体上架按内容摘要（含类型）寻址，重复上架不产生新对象、不改动已有对象。
  - 内容对象按内容摘要寻址、仅当不存在时写入：同一份产物重复落库不产生新对象。
  - 产物清单按（发布标识，路径）去重：同一次发布重复落库不产生第二条记录。
  - 指针切换幂等：把指针指向同一条发布记录不改变任何对外可见的结果。
- **检查点状态的可读性**：发布标识可作为查询键，读取这次发布当前所处阶段与各阶段的留痕。**不允许存在"只写日志、无法按键查询"的进度记录。**

### 跨子模块的约束

| 核查项 | 判据（验证手段） |
|--------|----------------|
| `site` 槽的产物与文件组逐字相同 | 逐字比较，差异集合恰好是记号被解析（`internal/galaxy` 测试） |
| 同一版本重复发布产物相同 | 撤回后重新发布同一版本，**整组**产物逐字相同（`internal/galaxy` 测试） |
| 重复发布不产生新对象 | 连续两次发布同一版本，私有区新增对象数为零（`internal/galaxy` 测试） |
| 文本响应是校验式的 | 文本条目的响应带 `ETag = 内容摘要` 与 `no-cache`（端到端测试） |
| 文本不进公开区 | 上架阶段只为资产条目写公开区对象（`internal/galaxy` 测试 + 部署后冒烟） |
| 外部引用被拒 | 内容里出现 `http(s)`、协议相对地址或 `data:` 形式的资源引用时发布失败，错误信息指出那一处（`internal/galaxy` 测试 + 端到端测试） |
| 外部链接不被拒 | `<a href="https://example.com">` 在内容里时发布成功（`internal/galaxy` 测试） |
| 指向他工程 / 已删除资产被拒 | 发布失败且错误信息含该资产标识（`internal/galaxy` 测试） |
| 草稿不可发布 | 无版本的工程发布被拒（`internal/galaxy` 测试） |
| 只上架被引用的资产 | 资产库有 5 个资产、文件组引用 2 个时，公开区只新增 2 个（`internal/galaxy` 测试） |
| 上架按工程切分 | 公开区的键落在 `galaxy/<工程标识>/release/` 下（`internal/galaxy` 测试 + 端到端测试） |
| 上架幂等 | 连续两次发布同一版本，公开区对象数与摘要均不变（`internal/galaxy` 测试） |
| 槽根带结尾斜杠 | 不带斜杠的槽根 301 到带斜杠的形式（未发布的标识与不存在的标识得到同一个 301），带斜杠的槽根与 `.../index.html` 是同一页（端到端测试） |
| 文档槽的槽根即首页 | `/g/<标识>/docs` 与 `/g/<标识>/docs/index.html` 是同一页，返回渲染出来的那一页（端到端测试） |
| 公开区对象为公开读 | 匿名取一个已上架的公开区对象成功（部署后冒烟） |
| 公开区不可枚举 | 桶未开启列举权限（部署后冒烟） |
| 响应头即边界 | 用一份刻意绕过扫描的外部引用（例如扫描清单未覆盖的写法）发布，浏览器仍取不到该资源（端到端测试 + 部署后冒烟） |
| 脚本跑得动但发不到别处 | 产物里的脚本能执行、同源请求可用，而指向外部地址的 `fetch` 与 `XMLHttpRequest` 被策略拒绝（端到端测试） |
| 允许的来源只有一处 | 上架生成的公开地址与响应头里允许的桶主机都等于同一个配置值派生出来的取值；`'self'` 不由任何配置给出（`internal/galaxy` 测试） |
| 不同源强制 | 发布域与 `public_base_url` 同源时启动失败，信息里指出两项（`internal/config` 测试） |
| 发布入口不鉴权 | 不带任何凭证请求发布地址（含子路径）能取到当前产物（端到端测试） |
| 资产条目不从服务端出字节 | 请求资产条目对应的路径得到重定向，响应体不含字节（端到端测试） |
| 否定结论六合一 | 路径不在集合、未发布、已撤回、**槽未启用**、已删除、标识不存在六者返回同一个否定结果（端到端测试） |
| 两槽的发布互不影响 | 发布 / 撤回一个槽之后，另一个槽的每一条路径读到的产物逐字不变（`internal/galaxy` 测试 + 端到端测试） |
| 撤回立刻生效 | 撤回后下一次请求即不可达，且**每一条**路径都是（端到端测试） |
| 发布物不含主体信息 | 产物与响应头里不出现拥有者的昵称、头像地址与主体标识（`internal/galaxy` 测试） |
| 中途失败无外部影响 | 在校验后、切换前注入失败，所有路径仍返回上一次的产物，且指针未动（`internal/galaxy` 测试） |
| 从检查点续跑 | 构造"已落库未切换"的状态，重启后发布完成且未重复上架（`internal/galaxy` 测试） |
| 撤回后仍可重发 | 撤回后重新发布同一版本成功，整组产物与首次逐字相同（端到端测试） |
| 半套配置拒绝启动 | 给了发布域但桶为空时启动失败，信息里指出缺的是桶（`internal/config` 测试） |
| 未配置时降级正确 | 两项都为空时工程照常，发布入口不渲染；只缺发布域时资产照常可用（`internal/config` 测试 + 前端测试） |

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 公开区孤儿对象的回收 | 暂不做。需要一次对账（列举公开区、与发布记录里引用到的摘要比对），是新的一类运维职责（**未定**） | 撤回与重发不回收字节；总量随时间增长 |
| 发布记录的清理 | 暂不做，保留每次发布的清单（**未定**） | 清单只有路径与摘要，库增长不再是压力；压力转移到私有区对象（内容寻址、可共享），它的回收见 [asset-library.md](asset-library.md) 的待定决策 |
| 发布物直接由桶托管 | 暂不做，保持服务端返回（**未定**） | 省掉发布域与一条服务端入口，且天然不同源；代价是地址落在存储域上，换桶即换地址 |
| 站点落在发布域根（每工程一个子域） | 暂不做，站点落在 `/g/<工程标识>/` 下（**未定**） | 地址更干净、构建产物不必注入发布根；代价是泛域名 DNS 与证书，且"发布域与主应用不同源"要在子域上重新论证 cookie 作用域 |
| 允许发布物向**外部**地址发请求 | 暂不做，`connect-src` 只含 `'self'`（**已定**，见"扫描不是边界，响应头才是"里的策略表） | 放开等于允许一个公开页面向任意地址发数据；至少要先把允许的目标收成一个白名单 |
| 允许 `data:` 形式的图片 | 暂不做（**未定**） | 与"只引用资产库"直接冲突：它让内容绕开资产的类型与大小约束 |
| 发布物按访问者裁剪（登录可见等） | 暂不做（**未定**） | 与"发布态不经过 RBAC"这条前提冲突，需要重新设计一整套可见性模型 |
| 发布物上显示拥有者信息 | 暂不做（**未定**） | 引入身份暴露面；要重新论证"公开匿名的发布物可以显示谁做的" |
| 发布体积上限的取值 | 定为校验规则的一部分，具体数值实现时确定（**未定**） | 只影响写入与发布校验 |
