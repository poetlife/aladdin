# galaxy — 编写与预览

> 内容是什么形状、有哪两种内容槽、地址怎么给见 [site-model.md](site-model.md)。本文件只管两件事：**内容怎么写**，以及**这一页看到什么**。

## 背景与目标

创作路径在命令行，不在浏览器。命令行覆盖全部原子能力（把目录送上送下、存版本、传素材、发布，见 [cli.md](cli.md)），内容由本地工具或生成器产出来再送上去；在网页里逐行敲一份完整站点是低效的那一端。因此网页这一页**不是编辑器优先**的界面，它的职责是另外三件：**看草稿渲染成了什么样**（发布地址只反映已发布的那一版，草稿的渲染结果只有这里能看到）、**看清现在处于哪一步**、**把它推出去**。**网页端不改内容**——内容的写入只有命令行一条路，因此源码视图退化为**只读**的逐份查看：它回答的是"这一页对应哪一份文件、它写了什么"，不是"我要改哪一句"。

成功的衡量标准：

1. 打开这一页，一眼看到三件事：草稿渲染出来是什么样、这份草稿能不能发布、下一步该做什么。
2. 预览始终是草稿的当前内容：命令行改完草稿，打开这一页看到的就是刚改的那一份；**这一页已经开着时，别处的改动会推过来并立刻更新**（订阅见 [../events/README.md](../events/README.md)），不需要再整页刷新。
3. 素材通过一个**可粘贴、可读、可替换**的记号被引用，用户不需要记任何地址。
4. 预览渲染的内容里有脚本时，**它读不到这一页的任何数据**。
5. 这一页不自己判断内容对不对——它问服务端，与服务端发布时**同一句回答**，且这个回答不需要用户主动索取。

## 功能行为

### 这一页的形态：预览与状态是主体

页面由一个固定的分区骨架构成，而不是一串自上而下阅读的卡片。骨架回答的问题各自固定在一个位置：

| 分区 | 回答什么 |
|------|---------|
| 顶栏 | 去哪里（返回、工程信息），有哪些集合可以打开（资产、版本），以及推进流程的两个动作（存版本、发布） |
| 状态条 | 这份草稿能不能发布、发布出去的是什么（尚未发布 / 已发布 + 分享地址 + 撤回） |
| 主区 | 草稿现在渲染成什么样；需要看某一页的源文件或某一份素材时切到只读的源码视图。两者共用同一块面积 |

五条约束：

- **主区铺满，集合进弹层。** 资产与版本是"一批东西"，不是"此刻正在看的东西"——与主区并排，代价是主区**长期**窄掉一截，换来的却是一个多数时候不看的列表。改成从顶栏打开、以弹层承载。代价是看集合时看不到渲染结果，而复制引用是把记号复制到剪贴板、不需要同时看着主区。弹层的内容区**自己滚动**，不把父页面撑长。
- **状态条上只放驱动决定的信息。** 常驻的那一行回答两件事：这份草稿能不能发布，以及发布出去的是什么。草稿与版本的**保存时间不在那里**——它不改变任何一次决定。命令行改过草稿之后，这一页收到事件就会重新问服务端（见 [../events/README.md](../events/README.md)）；版本的时间在版本面板里点一下就有。因此它是一行无框的两段，而不是几个带时间戳的方块。网页端不改内容，因此没有「本地改过、结论过期」这一档。
- **预览与源码是两种模式，在同一块面积上切换。** 并排会让两者争夺同一块面积——"看渲染结果"是这一页的主体动作，而"查一份文件写了什么"是偶尔的；把源码收成一块常驻的折叠面板则是另一种失手：它每次都要多滚一段，还永久占着一行。
- **预览可以单独打开成一个页面。** 它是"要同时看渲染结果与别处"时的出口——改与看不必挤在同一个屏幕里。它读的是同一份草稿；地址过期后刷新即得到新地址（与"重新读取即得到新地址"同源）。
- **主操作随流程位置变化，但任何时刻只有一个。** 缺版本时主操作是存版本，有版本未发布时是发布；其余动作降为次要按钮。这与"一页只有一个主操作"是同一条，只是"哪一个"由状态决定。
- **推进流程的动作只有一个入口，而"撤回"紧挨着它撤销的那个状态。** 发布与更新发布在顶栏一处（决定哪一版发出去）；撤回放在状态条上、它要作废的那个地址旁边——它不是第二个发布入口，而是那一处状态的逆操作。撤回要把地址一并带出来，因为"撤回哪一个地址"是做起这个决定唯一需要知道的事。
- **撤回不做成文字链接。** 同一排里"发布"是实心按钮、撤回是一行小字，人得先认出那行字能点才会去点——这正是"能力已经有、却像没有"的来源。它是**按钮级**的次要动作（描边、危险色），体量与位置仍服从上一条：在地址旁边，不搬到顶栏。
- **列表里也能撤。** 工程列表的"状态"列按槽给出已发布的地址，那一条上就带着撤回——与工作台同一处权限、同一套二次确认。列表侧不缺的是入口：能看到地址的地方，就该能在那里把它作废，而不是先打开工作台、再去找状态条。

**窄屏下这套骨架不重排，只折叠 chrome**：低频入口收进顶栏的「更多」、状态条压成一行、预览工具条只留主要动作，主体仍是预览/源码。折叠不改变上面几条不变量——主操作任何时刻仍只有一个（窄屏下它常驻，次要的那个流程动作入「更多」）、撤回仍在地址旁、集合仍进弹层。窄屏的具体形态见 [../web/responsive.md](../web/responsive.md)。

状态条呈现的就是 [README.md](README.md) 的"状态流转"里那个机器当前所处的位置（① 无版本 / ② 有版本未发布 / ③ 已发布），再加上"这份草稿能不能发布"这个与草稿绑定的结论。**两者都不是这张表新增的状态**：草稿的结论不改变槽的状态，槽的状态也不告诉你草稿改过没有——这是它们必须分成两段显示的原因。

**这一页一次看一个内容槽。** 状态条与状态机器**都属于当前选中的那个槽**：两个槽各有各的草稿、版本与发布状态，混在一张状态条上就没有哪一句是真的。工程有两个槽时，顶栏给一个切换器（"站点 / 文档"两个标签），切换即换这一页看的草稿、版本、状态与预览；只有一个槽时它不出现。**给工程加一个槽也在这里**——从切换器旁边的入口加，加完这一页就多一个标签，已有那个槽的一切不动。

工程元数据（名称、简介）与启用的内容槽、工程标识都不占常驻版面：它们不参与创作循环，收进点工程名打开的那个入口。工程标识、启用哪些槽、以及每槽的入口路径作为只读信息也出现在那里。

### 源码视图：文件列表 + 选中的那一份（只读）

它不是"一份正文"，而是**文件列表 + 选中的那一份**（见 [site-model.md](site-model.md)）。内容本来就是一组具名文件，把它伪装成一份文本会立刻引出"我改的到底是哪一份"这个无法回答的问题。

**文件列表按路径段折成树**：目录是节点、文件是叶子，目录可折叠、默认展开。路径本来就是树形的，平铺列表把 `img/` 这样的前缀在每一条上重写一遍，而这个前缀一次折叠就能省掉——树没有多出信息，只是把路径本来的形状露出来。

**选中的那一份按它是什么呈现，而不是一律当文本读。** 文本条目显示原文；资产条目**就地渲染**——图片按原字节显示、视频与音频用各自的控件播放。这一条不是顺手添的功能："能渲染"正是网页端相对命令行多出来的那一样，把一份资产退化成一句类型说明加一个外链，等于在这一页唯一的强项上缺席。**这也是源码视图不必是纯文本视图的原因**：它回答"这一份是什么"，而对一张图片，答案就是那张图片。类型未知或地址取不到时如实说明，不装作有。

**它是只读的，网页端不改内容。** 理由不是保守，是形状：写入要么是"整组表达期望状态"、要么是"单条替换"，而两者并存会引出"网页上刚改的一句被一次命令行 push 静默盖掉"这类**只在两个入口之间发生**的冲突。收成一条写入路径，这份冲突连同它需要的基线校验一起消失。

**读一份文件的原文与读一份资产是同一种下发**：服务端给一个短时地址，客户端直连取，服务端不代理字节（见 [asset-library.md](asset-library.md)）。查看也一样——它不经过服务端转发，因此就地渲染也不需要第二套通路。读正文是浏览器对这条短时地址的跨域读取，因此桶的跨域规则必须允许主应用源发起 `GET` 并让脚本读到响应体；只放行上传用的 `PUT` 时，源码视图拿不到正文（见 [../../deploy.md](../../deploy.md)）。**资产的就地渲染不受这条限制**：显示一张图片不需要脚本读到响应体，因此跨域规则只配了上传时它照常成立——两者形态不同，别把它们合并成一条前提。

**整组文件的读写只有命令行一条路**（见 [cli.md](cli.md)）。

### 源侧的记号

两条记号都是**源侧写法**——服务端只认文件组（见 [site-model.md](site-model.md)）：`asset://` 在进入文件组时被**登记**成一条资产条目、发布时被**替换**成该条目在站点内的路径；文档间链接在发布时被解析成站点内的绝对地址。

**一、素材：`asset://<资产标识>`**

例如 `<img src="asset://a1b2c3">`，或 `<style>body{background:url(asset://a1b2c3)}</style>`。

三条理由，缺一条这个设计就不成立：

1. **记号是一个可被逐字替换的文本。** 因此替换不需要解析 HTML——出现在元素属性里、在 `<style>` 里的 CSS `url()` 里、在 `srcset` 里，都只是把这段文本换掉。**依赖"枚举哪些属性算引用"的做法必然会漏**（`srcset`、内联 CSS、未来新增的属性），而逐字替换不会漏。
2. **编辑态与发布态的地址本来就不同**（一个短时预签名、一个稳定公开地址，见 [asset-library.md](asset-library.md) 与 [publication.md](publication.md)）。把真实地址写进源，等于让源里存着一个**会过期**或**与发布态不一致**的字符串。记号让源与两套地址都解耦，也让源里不必出现工程标识。
3. **"这个引用是不是本工程的资产"成了一个可判定的问题。** 写成真实地址时，判断它属不属于本工程要靠比对地址前缀——一个可以被相似域名、被重定向、被大小写绕过的问题。记号把问题变成"这个标识在不在本工程的资产里"，没有歧义。

**用 `asset://` 这个协议形状**，而不是某种模板标记：它不是一个浏览器能解析的协议，所以**任何一次漏掉解析的场合都是显式失败**（图片裂开、链接点不动），而不是静默指向某个看起来合法的地方。静默失败的内容发布是最糟的失败方式——它不会被人发现，直到有人看懂了页面上的错。

**替换落在哪些位置，由"这段文本会不会被浏览器拿去取字节或跳转"回答，按槽给出：**

| 槽 | 替换发生在哪 | 什么样的记号**不**被替换 |
|----|------------|----------------------|
| `site` | 整份文本逐字替换：元素属性、`<style>` 里的 `url()`、`srcset`、脚本里拼出来的路径，一视同仁 | 无——这里没有"哪些位置算引用"的枚举，因此也不存在枚举漏掉的那一类 |
| `docs` | **渲染这一趟**：markdown 图片与链接的目的地，以及正文里的 raw HTML（行内与块级，含其中的内联 CSS） | **代码块、行内代码与正文散文里出现的记号原样保留**——那是给人看的文本，不是一处引用 |

**"不替换"不等于"静默放过"。** 记号写成既不是引用位置、又不能当普通文本读的形状时，校验会拒绝并指出那一处：例如整段写成 `<asset://a1b2c3>` 时，markdown 把它当成一条自动链接，而自动链接不是一处可替换的位置——要链到一份素材就写成 markdown 链接或图片语法。

**漏解是一处失败，不是一处坏页面。** 校验与发布的判据落在**产物**上：产物里出现没解开的记号即拒绝（见 [publication.md](publication.md) 的"解析"）。因此"记号的替换被漏掉"这件事不会留到读者的浏览器控制台里。

**素材库提供"复制引用"**，用户拿到的是这段文本，不需要打开存储或拼地址。

**二、文档间链接：相对 `.md` 路径**（仅 `docs` 槽）

```
[标题](guide/intro.md)
![图](images/x.png)
```

发布时解析成站点内的绝对地址；指向文件组里不存在的位置即拒绝，并指出是哪一份文件的哪一处。

**外部导航链接不受限制**：`<a href="https://example.com">` 可以是任意地址——用户链到外部网站是他的意图，不是资源引用。

**构建产物里的路径引用不需要任何记号。** 产物里写的 `/assets/index-abc.js` 原样保留，由命令行的发布根注入让它成立（见 [cli.md](cli.md)）。

### 预览

预览在浏览器里的一个**沙箱 iframe** 中渲染。

**沙箱的关键是它落在不透明源上（即不给它 `allow-same-origin`）。** 这样即使内容里有脚本，它也读不到这一页的 DOM、会话与本地存储。**"同源 + 沙箱"不是一个可接受的替代**：同源意味着脚本与这一页共享 origin，浏览器给的隔离就只剩一层属性开关，任何一次属性调整都会变成一次真实的数据泄露。

**预览加载的是草稿整站的地址，不是一份塞进来的文档。** 服务端把**当前这个槽**的草稿整组按发布的路径形状从一条属于预览自己的、带短时凭证的地址上提供（形如 `<发布域>/g/p/<凭证>/<工程标识>/<路径>`；`docs` 槽在工程标识之后多一个 `docs` 段，与发布态同形），iframe 的 `src` 就是那条地址。**页面因此有自己的源与目录**：页内的相对地址、站点绝对地址、样式里的 `url()`、脚本里拼出来的路径，全都由浏览器在同一个地址空间里解析——与发布态同一套道理（见 [site-model.md](site-model.md) 的"预览：草稿整组从一条自己的地址上给出"）。`docs` 槽的页面在预览时由服务端渲染（同一段渲染、按请求算），因此文档站的预览里站点文件生效、页间导航是真的链接。

这条通道落在**发布域**上，因此：

- **内容的脚本仍然进不了这一页**：iframe 不给 `allow-same-origin`，而发布域与主应用不同源（见 [publication.md](publication.md)）。隔离由这两条一起保证。
- **预览里的资产是私有区的短时预签名地址**（见 [asset-library.md](asset-library.md)）：那一页长时间开着时，图片可能在地址过期后显示不出来。刷新预览即得到新地址——与头像"重新读取档案即得到新地址"同源。
- **凭证是短时的、随地址走**：预览态接受"地址是凭证"这一取舍，因此**未发布的草稿与资产里不得承载秘密**，草稿地址也不得被当作分享链接长期使用。这两条要出现在界面上，而不是留给用户猜。
- **预览与壳共用同一条加载态**：这一块在内容到达之前有加载提示，超过时限仍未加载完时提示改成不遮挡正文的可重试状态条（见 [publication.md](publication.md) 的"主站壳"）。它随交付内容的那一帧一起定义，因此两处不可能"一个有一个没有"。

**预览不做审查、不做裁剪**：内容写什么就渲染什么。引用坏了就显示坏的——这一页的即时提示（见下）是另一个渠道，预览不因为"知道这处有问题"就替用户藏起来。**"预览看起来对"与"发布能成功"是两件事**，把它们混起来会让用户以为预览通过就等于发布通过。

### 能不能发布是一个自动产生的状态，不是一个按钮

**页面打开时、以及订阅收到事件后，自动调用服务端的校验入口**（见 [publication.md](publication.md)）一次，把结论作为状态呈现出来：可以发布，或者有哪几处问题、分别在哪一份文件的哪一行。**不在前端复写引用解析。**

网页端不改内容，因此不存在「正文改了还没保存、上一次结论作废」这一档。命令行可以在这一页开着的时候把新草稿 push 上来：**这一页订阅了它正在看的那个工程**（见 [../events/README.md](../events/README.md)），收到事件就重拉草稿、版本与工程状态，并重新问一次校验、重新渲染预览——状态条不会继续显示 push 之前的「可以发布」。

**页面在后台不另外照顾。** 这里**没有**"回到前台再重读一次"这条兜底：隐藏期间不退订，事件照常交付；连接真的死了（浏览器冻结标签页只是其中一种成因）由客户端按心跳判活、重连，而重连本身就会带来重拉（见 [../events/README.md](../events/README.md) 的"页面隐藏时"）。

兜底看着像"多一层保险"，实际换不来覆盖上的好处，却一定会猜错：它的触发信号是"用户是不是又看向这一页"，而它与"这条连接是不是还活着"之间的相关性很弱——**页内换一次焦点就会凑成一次**。那正是"在预览里点过一下之后，点外壳上任何一个按钮预览都整个重载"这个缺陷的来源（记录见 [../../debugging/records/2026-10-07-preview-reloads-on-page-internal-focus.md](../../debugging/records/2026-10-07-preview-reloads-on-page-internal-focus.md)）。**判连接的死活，就去看连接。**

理由有两层。

第一层是"结论只有一处"：**"这份内容能不能发布"是一个判断，按 SSOT 原则只有一个实现入口。** 两端各写一份的表现有两种，都很难排查：

- 提示说没问题、发布说不行 → 用户被卡住，且没有任何提示告诉他哪一句是真的。
- 提示说不行、发布其实可以 → 用户放弃一个能用的功能。

服务端这一处的校验同时是发布的前置阶段，因此"页面提示过"与"发布时校验"用的是同一段代码、同一份规则集合，不会漂移。

第二层是"结论要主动出现"：`validate` 在命令行上是一个可以被 shell 看见的结论（见 [cli.md](cli.md)），因为脚本要能写 `validate && publish`。网页上没有这条组合，若结论要等用户点一下才产生，那么"这份草稿现在能不能发"就变成了一个需要用户先想起来去问的问题——而他打开这一页本来就是来问这件事的。因此**不设"校验"按钮**：状态放在那里，人一到就看得见。

**校验请求本身失败**（网络中断、权限不足）与"内容有问题"是两件事，不得混为一谈：前者显示为"校验未完成、可重试"，页面其余部分（预览、版本、资产）照常可用。把一次取不到结论渲染成一片失败，会让用户以为自己的工程坏了。

界面呈现校验结论的位置是**状态条**（结论就在 ① 段上，问题的逐条清单从那里展开），预览不做裁剪——内容有坏引用时预览仍照常渲染其余部分，坏的地方就显示为坏的。

**校验结论是「有问题」时，顶栏不提供对「与当前草稿清单相同的版本」的发布。** 发布读的是版本而不是草稿，但同一份清单会得到同一份拒绝；再点一次只是多一次失败的往返。清单与当前草稿不同的历史版本仍可发布——那份结论说的是草稿，不是每一个历史版本。原因就在状态条上，按钮旁不再写第二句。

## 边界与约束

- **网页端不改内容，也没有结构化编辑。** 写入只有命令行一条路（见 [cli.md](cli.md)）；"点选插入图片"那类所见即所得的问题（两套内容表示如何同步）因此根本不存在——它只在"网页端能改源码"的前提下才成立。
- **网页端不做构建，也不整组送取。** 打包与目录的上送下载都属于本地工具链与命令行（见 [cli.md](cli.md)）。
- **预览里不在用户页面上叠加任何 aladdin 编写的脚本或样式**（`site` 槽跑的只有用户自己的内容与资产）。`docs` 槽的页不在此列：那些页本来就是渲染出来的，外壳与排版属于渲染规则本身（见 [site-model.md](site-model.md)）。
- **预览不承诺与发布态逐像素一致。** 两者的资产地址来源不同（预览是私有区的短时预签名、发布是公开地址），访问前提也不同（凭证 vs 匿名）；**页的形状是同一套**——一页一个地址，这是上面那条「整站在一条自己的地址上」买来的（见 [site-model.md](site-model.md)）。**内容一致是由资产不可变保证的**（见 [asset-library.md](asset-library.md)），不是由地址一致保证的。
- 语法高亮属于只读源码视图的呈现细节，不在本 spec 内。

## 可验证性与长程执行

**非长程任务。** 编辑与预览都是即时的同步操作。发布才是长程的，见 [publication.md](publication.md)。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 记号可逐字替换 | 在元素属性、内联 CSS 的 `url()`、`srcset` 三处写 `asset://`，发布后三处都被替换（`internal/galaxy` 测试） |
| `docs` 槽的记号在 raw HTML 里也解开 | markdown 里的 `<img src="asset://…">` 与内联 CSS 的 `url(asset://…)` 在产物里都变成站点内路径（`internal/galaxy` 测试） |
| 代码块里的记号原样保留 | 围栏代码块与行内代码里的 `asset://…` 逐字留在产物里，不算一处引用（`internal/galaxy` 测试） |
| 记号写成自动链接即拒绝 | 正文里整段写成 `<asset://…>` 时校验被拒，信息里指出那一处（`internal/galaxy` 测试） |
| 漏解即失败 | 产物里出现没解开的记号时被报成问题，发布因此被拒（`internal/galaxy` 测试） |
| 记号不被浏览器解析 | 未解析的 `asset://` 在浏览器里取不到任何东西（部署后冒烟 / 端到端测试） |
| 指向不存在资产即失败 | 内容引用一个不存在的资产，发布被拒且错误信息含该标识（`internal/galaxy` 测试） |
| 指向他工程资产即失败 | 引用另一个工程的资产标识，发布被拒（`internal/galaxy` 测试） |
| 文档间坏链接即失败 | `docs` 槽下引用一个不存在的 `.md` 位置，发布被拒且指出是哪一份文件的哪一处（`internal/galaxy` 测试） |
| 指不到的锚点即失败 | `[小节](#不存在)` 与 `[小节](guide/intro.md#不存在)` 都在校验期被拒，信息里指出文件与那个锚点（`internal/galaxy` 测试） |
| 预览落在不透明源 | 预览 iframe 的沙箱属性里没有 `allow-same-origin`，且内容中的脚本读不到父页面（前端测试） |
| 预览不用长效地址 | 预览的草稿凭证带失效时刻、资产地址带签名与有效区间，两者的量级都是分钟（`internal/galaxy` 测试） |
| 预览加载的是整站地址 | iframe 用 `src` 指向当前槽的草稿整站地址；页内引用在预览里可解析（含 `docs` 槽的站点文件与 `site` 槽的站内导航）（前端测试 + 端到端测试） |
| 一次只呈现一个槽 | 两个槽时顶栏有切换器；切换后状态条、版本、预览与校验结论都换成该槽的，且不与另一个槽混显（前端测试） |
| 窄屏下预览是主体 | 窄屏常驻行只有 返回 + 工程标题 + 一颗主操作 +「更多」，除标题外都只剩图标（名字在 `aria-label` 上）；长标题以省略号截断，不压住右边的按钮；资产、版本、槽切换、加槽经「更多」或既有弹层可达；状态条不常驻长发布地址、撤回仍在；预览工具条不出现「单独打开」字样（前端测试） |
| 预览不裁剪却报错 | 内容有一处坏引用时，预览仍渲染其余部分，同时服务端校验入口返回该处问题（前端测试 + `internal/galaxy` 测试） |
| 提示与发布同一入口 | 这一页的校验调用与发布的前置校验指向同一个服务端方法（代码审查 + `internal/server` 测试） |
| 校验结论自动产生 | 打开页面即调用校验入口，不需要用户先做任何操作；订阅收到事件后再次调用（前端测试） |
| 别处改动自动跟上 | 这一页订阅了它正在看的那个工程；收到事件即重拉草稿并重新渲染预览，不需要刷新页面（前端测试 + `test/e2e`） |
| 后台回来不靠"猜" | 页面停留期间连接死了（超时收不到任何东西，含心跳）时客户端主动重连并重拉；没有任何"回到前台/重新获得焦点"触发的重读，页内换一次焦点不产生任何调用（前端测试） |
| 有问题的同一份清单不从顶栏发布 | 草稿校验为有问题时，与草稿清单相同的版本在顶栏不可发布；清单不同的版本仍可发布（前端测试） |
| 校验失败不冒充"内容有问题" | 校验请求失败时呈现为"校验未完成"，且预览与版本、资产照常可用（前端测试） |
| 预览文档不由应用源服务 | 用户内容只经沙箱 iframe 从**发布域**上的预览通道进入；应用源上不存在一个返回用户内容的地址（前端测试 + 代码审查） |
| 预览可单独打开 | 预览有一条独立路由，单独打开时渲染的是同一份草稿，且沙箱属性与内嵌时一致（前端测试） |
| 预览也有灯箱 | 工作台里的预览与单独打开的预览页都消费同一条通道消息并开灯箱，两处的隔离与沙箱属性一致（前端测试） |
| 预览首屏不留空白 | 内容未到达时这一块有加载提示；超过时限仍未加载完时撤掉遮罩、只留可重试的状态条，正文不再被盖住（前端测试） |
| 网页端不改内容 | 源码视图是只读的；接口面上不存在从网页端写内容的调用（前端测试 + `internal/server` 测试） |
| 撤回在工作台找得到 | 已发布且持有发布权限时，状态条上地址旁有一个**按钮级**的撤回，二次确认后才调用；不持有发布权限时不渲染（前端测试） |
| 撤回在列表找得到 | 工程列表"状态"列里，每一条已发布的槽都在地址旁带撤回；权限与二次确认与工作台一致，取消不产生调用（前端测试） |
| 文件列表按路径折成树 | 同一目录下的多份文件归在一个可折叠的目录节点下，折叠后不再逐条列出（前端测试） |
| 资产条目就地渲染 | 选中一份资产条目时渲染出图片（或视频、音频）本身，而不是只给一句类型说明（前端测试） |
