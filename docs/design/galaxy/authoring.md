# galaxy — 编写与预览

## 背景与目标

用户写的是**一份完整的 HTML 文档**，不是模板片段、不是结构化表单。这个选择决定了本子模块的全部内容：既然正文是源码，那么"怎么引用素材"和"写的时候看到什么"就是仅有的两件需要定义的事。

成功的衡量标准：

1. 用户在编辑器里改正文，能立刻在预览里看到效果。
2. 素材通过一个**可粘贴、可读、可替换**的记号被引用，用户不需要记任何地址。
3. 预览渲染的正文里有脚本时，**它读不到编辑器的任何数据**。
4. 编辑器不自己判断正文对不对——它问服务端，与服务端发布时**同一句回答**。

## 功能行为

### 正文是一个完整的 HTML 文档

正文就是用户写的全部内容：`<!doctype html>` 到 `</html>`。

- **不包裹。** 不替用户加 `<html>`、`<head>`、`<body>`，也不注入任何标签、属性或脚本。
- **不补全。** 用户漏了闭合标签就漏着，浏览器怎么容错是浏览器的事。
- **不注入。** 发布时除了替换资产占位符（见下）与在**交付层**附加安全响应头（见 [publication.md](publication.md)）之外，正文的每一个字节都来自用户。

这条的理由很直接：**用户以为发布的是自己写的东西，那就必须是。** 任何一层看不见的包裹都会让"我写的这行为什么没生效"变成一个需要读 aladdin 源码才能回答的问题。安全头走的是 HTTP 响应头而不是正文，因此不违反这一条。

### 资产占位符

正文里引用素材，写的是**占位符**：

```
asset://<资产标识>
```

例如 `<img src="asset://a1b2c3">`，或 `<style>body{background:url(asset://a1b2c3)}</style>`。

三条理由，缺一条这个设计就不成立：

1. **占位符是一个可被逐字替换的记号。** 因此"改写"不需要解析 HTML——出现在元素属性里、在 `<style>` 里的 CSS `url()` 里、在 `srcset` 里，都只是把这段文本换掉。**依赖"枚举哪些属性算引用"的做法必然会漏**（`srcset`、内联 CSS、未来新增的属性），而逐字替换不会漏。
2. **编辑态与发布态的地址本来就不同**（一个短时预签名、一个稳定公开地址，见 [asset-library.md](asset-library.md) 与 [publication.md](publication.md)）。把真实地址写进正文，等于让正文里存着一个**会过期**或**与发布态不一致**的字符串。占位符让正文与两套地址都解耦。
3. **"这个引用是不是本工程的资产"成了一个可判定的问题。** 写成真实地址时，判断它属不属于本工程要靠比对地址前缀——一个可以被相似域名、被重定向、被大小写绕过的问题。占位符把问题变成"这个标识在不在本工程的资产里"，没有歧义。

**用 `asset://` 这个协议形状**，而不是某种模板标记：它不是一个浏览器能解析的协议，所以**任何一次漏掉改写的场合都是显式失败**（图片裂开、链接点不动），而不是静默指向某个看起来合法的地方。静默失败的内容发布是最糟的失败方式——它不会被人发现，直到有人看懂了页面上的错。

**正文里出现的每个占位符都必须指向本工程的资产。** 指向不存在的、别的工程的、或已删除的资产，一律是发布期的拒绝理由（见 [publication.md](publication.md)）。编辑态下它表现为取不到图，这正是应有的反馈。

**素材库提供"复制引用"**，用户拿到的是这段文本，不需要打开存储或拼地址。

### 预览

预览在浏览器里的一个**沙箱 iframe** 中渲染。

**沙箱的关键是它落在不透明源上（即不给它 `allow-same-origin`）。** 这样即使正文里有脚本，它也读不到编辑器的 DOM、会话与本地存储——它连自己的源都没有。**"同源 + 沙箱"不是一个可接受的替代**：同源意味着脚本与编辑器共享 origin，浏览器给的隔离就只剩一层属性开关，任何一次属性调整都会变成一次真实的数据泄露。

**预览里的资产地址是短时预签名地址**（见 [asset-library.md](asset-library.md)）。因此：

- 一个长时间开着的编辑页里，预览的图片可能在地址过期后显示不出来。刷新预览即得到新地址——与头像"重新读取档案即得到新地址"同源。
- 预览态接受"地址是凭证"这一取舍，因此**未发布的资产里不得承载秘密**。这条要出现在界面上，而不是留给用户猜。

**预览不做审查、不做裁剪**：正文写什么就渲染什么。引用坏了就显示坏的——编辑器的即时提示（见下）是另一个渠道，预览不因为"知道这处有问题"就替用户藏起来。**"预览看起来对"与"发布能成功"是两件事**，把它们混起来会让用户以为预览通过就等于发布通过。

### 即时提示走服务端同一个入口

编辑器需要告诉用户"这处引用有问题"时，**调用服务端的校验入口**（见 [publication.md](publication.md)），不在前端复写引用解析。

理由与"前端不缓存判定结果"同源：**"这段正文能不能发布"是一个判断，按 SSOT 原则只有一个实现入口。** 两端各写一份的表现有两种，都很难排查：

- 编辑器说没问题、发布说不行 → 用户被卡住，且没有任何提示告诉他哪一句是真的。
- 编辑器说不行、发布其实可以 → 用户放弃一个能用的功能。

服务端这一处的校验同时是发布的前置阶段，因此"编辑器提示过"与"发布时校验"用的是同一段代码、同一份规则集合，不会漂移。

## 边界与约束

- **没有结构化编辑。** 不提供"点选插入图片"生成 DOM 的所见即所得模式；正文就是源码。理由不是保守——结构化编辑会立刻引出"用户也能直接改源码吗"，于是有了两套内容表示，而它们的同步是一整类新问题。
- **没有多文件。** 一个工程一份正文；CSS 与脚本内联其中（这正是"发布物只能是一个 HTML"的含义，见 [README.md](README.md)）。
- **编辑器不注入任何脚本或样式到预览里**（预览里跑的只有用户的正文与资产）。
- **预览不承诺与发布态逐像素一致。** 两者的资产地址来源不同（预签名 vs 公开地址）。**内容一致是由资产不可变保证的**（见 [asset-library.md](asset-library.md)），不是由地址一致保证的。
- 语法高亮、自动补全、格式化属于编辑器实现细节，不在本 spec 内。

## 可验证性与长程执行

**非长程任务。** 编辑与预览都是即时的同步操作。发布才是长程的，见 [publication.md](publication.md)。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 正文不被包裹或注入 | 发布产物与用户正文逐字比较，差异只有资产占位符被替换（`internal/galaxy` 测试） |
| 占位符可逐字替换 | 在元素属性、内联 CSS 的 `url()`、`srcset` 三处写占位符，发布后三处都被替换（`internal/galaxy` 测试） |
| 占位符不被浏览器解析 | 未改写的 `asset://` 在浏览器里取不到任何东西（部署后冒烟 / 端到端测试） |
| 指向不存在资产即失败 | 正文引用一个不存在的资产，发布被拒且错误信息含该标识（`internal/galaxy` 测试） |
| 指向他工程资产即失败 | 引用另一个工程的资产标识，发布被拒（`internal/galaxy` 测试） |
| 预览落在不透明源 | 预览 iframe 的沙箱属性里没有 `allow-same-origin`，且正文中的脚本读不到父页面（前端测试） |
| 预览不用长效地址 | 预览的资产地址带签名与有效区间，且区间的量级是分钟（`internal/galaxy` 测试） |
| 预览不裁剪却报错 | 正文有一处坏引用时，预览仍渲染其余内容，同时服务端校验入口返回该处问题（前端测试 + `internal/galaxy` 测试） |
| 提示与发布同一入口 | 编辑器的校验调用与发布的前置校验指向同一个服务端方法（代码审查 + `internal/server` 测试） |

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 所见即所得编辑 | 暂不做，只编辑源码（**未定**） | 引入第二套内容表示，与源码的同步是一整类新问题 |
| 预览的运行时错误回传（`postMessage` 通道） | 暂不做（**未定**） | 需要一条受控的预览↔编辑器通道，且它本身是一个需要论证边界的攻击面 |
| 语法高亮与自动补全 | 暂不做（**未定**） | 纯编辑器实现，不影响任何行为约定 |
| 多文件正文（拆出 CSS/JS） | 暂不做（**未定**） | 与"发布物只能是一个 HTML"直接冲突：要么发布时内联，要么就产生多个文件 |
| 正文体积上限的取值 | 定为发布校验的一部分，具体数值实现时确定（**未定**） | 只影响写入与发布校验 |
