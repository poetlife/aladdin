# galaxy — 工程附件

## 背景与目标

创作过程中除了网页要引用的媒体（资产），还会产生**发布物**：二进制、zip 包、导出文件。它们与资产是两件事：

- **资产**会被网页引用、由浏览器渲染，因此类型必须严格白名单（不收任何可执行类型）、发布后进公开区；
- **附件**是给工程成员**下载**的，类型不限，**永远不进公开区**。

把 zip 与二进制塞进资产那条路会同时破坏两边：白名单收紧的原因（公开区上的对象必须以一个无害类型下发）会被"什么都能传"取消掉；而二进制放进文件组也不行——文件组只收文本条目（见 [site-model.md](site-model.md)）。

本子模块定义第三类对象：**工程私有附件**。

成功的衡量标准：

1. 成员能上传任意类型的文件（zip、二进制、导出物），看到文件名、大小、摘要、说明与上传时间。
2. 下载拿到的**永远是强制下载**：响应头由签发策略固定，即使文件是 `.html` 或 `.svg`，浏览器也不会内联渲染或执行它。
3. 附件**不进公开区、不进发布产物**，也无法成为文件组的条目——发布态里查不到任何附件对象。
4. 只有一个工程成员（拥有者）读得到、传得了、删得了；匿名者即使拿到对象键也取不到字节。
5. 字节仍走**公共直传链路**：服务端不接触字节（见 [../objectstore/README.md](../objectstore/README.md)）。

## 功能行为

### 附件属于工程，与资产并列而不混用

| | 资产 | 附件 |
|---|---|---|
| 用途 | 被网页引用、由浏览器渲染 | 给工程成员**下载** |
| 类型 | 严格白名单（见 [asset-library.md](asset-library.md)） | **不限**，按文件名记录 |
| 下发 | 以声明的类型、可进公开区 | **一律强制下载**，永不进公开区 |
| 可见 | 发布后公开 | **仅工程成员**（本期不做公开下载） |
| 配额 | 按类别分档（单文件） | 按**工程总量**（见下） |

**两者不互相转换。** 一个文件要成为资产就得过一个类型白名单，要成为附件就得走附件那条路；把附件"提升"成资产（或反过来）不是本模块的动作——那会绕过白名单，而白名单正是资产那条路唯一的安全依据。

### 附件的字段

| 内容 | 说明 |
|------|------|
| 附件标识 | 由 aladdin 分配，不可猜、不复用 |
| 所属工程 | 一个附件属于唯一一个工程。**不可转移**（与工程同一条） |
| 标注的版本 | **可选**，默认不标。它是一个**标注**，不是引用：说明"这一份是那一版的构建产物" |
| 文件名 | 原始文件名。**仅供展示与排障**：它不进对象键，也不参与任何判断 |
| 字节数 | 取自提交时对对象的核对，不是声明值 |
| 内容摘要 | 字节的 SHA-256。**不是寻址键**（附件按标识寻址），只用于核对与展示 |
| 说明 | 可选的短文本，给人看的。**可改** |
| 上传人 | 留痕用 |
| 上传时间 | 展示与排障用 |

**字节不可变。** 没有"替换这一份附件的字节"这个动作——要换就重新上传一个（与资产同一条）。可变的是**说明**那一层，它不进对象键、不参与任何判定。

### 标注版本，而不是引用版本

标注与引用是两件事，差别落在**删除**上：

- 文件组里的资产条目是**引用**：被引用的资产不可删（见 [project-versioning.md](project-versioning.md)）。
- 附件上的版本标注是**标注**：它不拦阻版本删除，**删除一个版本时把指向它的附件标注清空**。

不拦阻的理由：标注回答的是"这一份大概是哪一版产出的"，它不参与发布、不影响任何版本的可用性；让一个标注去锁住一个版本，会让"想删一版"变成一件要先翻遍附件列表才能做的事。清空的理由与"引用完整性"同源：标注指向的东西已经不存在，留着它就是一条悬空引用。

### 上传：与资产同一条直传链路，类型不声明

上传走**公共直传链路**（签发 → 直传 → 提交，见 [../objectstore/README.md](../objectstore/README.md)）：服务端分配附件标识并签发一份**短时、只允许写、只对这一个键有效**的凭证；客户端拿它把字节直传进私有区；随后提交，由服务端对那个键做一次 Head，核对存在性与真实字节数。

**上传声明的内容类型是中性类型**（`application/octet-stream`），不是"用户声明的类型"：

- 附件的**下发类型是固定的**（永远 `application/octet-stream` + `attachment`），因此上传时那一次声明不产生任何对外可见的后果，让它可填只是多一处能被误信的东西；
- 存储侧的策略仍然需要一条类型规则来**绑定大小上限**（一条规则 = 一种类型 + 它那一档的上限，见 [asset-library.md](asset-library.md) 的取舍），中性类型正好是那一条。

**内容摘要由上传方声明，并在提交时核对**，与资产逐字同一条路：让存储侧算（字节不过境），存储侧给不出时读回自己算（见 [asset-library.md](asset-library.md) 的"内容摘要同样由上传方声明"）。不一致即拒绝提交并删掉那个对象。

**摘要在附件上不是寻址键**，因此核对它的意义与资产不同：它不是"地址会不会指到别处"，而是"这一行记录说的那份字节是不是真的那份"。核对仍然做，理由是展示与排障全靠它，而一个不核对的值没有任何理由被相信。

### 上限与配额

| 项 | 取值 | 由谁执行 |
|----|------|---------|
| 单文件上限 | 500 MiB | 签发策略（存储侧执行），提交时再按真实字节数核一遍 |
| 每工程总量 | 10 GiB | **服务端**：签发前按当前占用 + 声明大小早退，提交时按真实字节数再核一遍 |

两者都不含"文件数"这一档：附件是构建产物，一个工程几十份就到头了，而软件包的大小差得很远——**卡字节、不卡个数**。

**配额按工程算，算的是库里的行。** 库内的元数据行是"存在哪些附件"的权威（与资产同一条），因此占用是这些行的字节数之和，不去问对象存储——对象存储上可能有无从被引用的孤儿对象，那是清理的事，不是配额的事。

**签发前的早退不是安全边界**：声明的大小是不可信输入。真正的判定在**提交**那一步，用核对出来的真实字节数做——一次超过配额的提交因此不会留下元数据行，对象也被删掉。签发前那一次的作用只是别让用户白传一遍。

### 下发：固定响应头的短时地址

读一个附件时，服务端签发一条**短时有效**的预签名地址。响应头由**签发策略固定**，不取上传时声明的任何值：

| 响应头 | 取值 |
|--------|------|
| `Content-Type` | `application/octet-stream`（**恒定**） |
| `Content-Disposition` | `attachment`，带上文件名（RFC 6266 的 `filename*`，非 ASCII 用百分号编码） |

因此同样一份字节，无论它的文件名以什么结尾，浏览器都只会把它**存下来**，不会渲染、不会执行。这一条是附件这条路能收任意类型的前提：白名单对资产是必需的，而它对附件不成立——附件根本不给浏览器渲染的机会。

**文件名只影响展示，因此下发前要滤一遍**：它是客户端给的自由文本，可能含引号、反斜杠、控制字符与换行。拼进响应头之前统一替换掉这些字符并限长——响应头注入的入口只有这一处，滤也只在这一处做（见 [../objectstore/README.md](../objectstore/README.md)）。

**地址短时有效（5 分钟）。** 它在有效期内是一份谁拿到都能用的凭证，因此下发给的是一个已经通过归属校验的调用者（见下），而部署侧必须保证桶本身是私有的（见 [asset-library.md](asset-library.md) 的"私有区不可匿名读"）。

### 归属：只有工程拥有者

附件的每一个动作都要求**调用者是该工程的拥有者**，与工程的所有其它动作同一条（见 [project-versioning.md](project-versioning.md) 的"归属"）：

- 他人工程的附件与"不存在的附件"返回**同一个结论**；
- 签发下载地址这一步**要判权**（与编辑态资产地址相同），而发布态那条不判权的读取路径不适用于附件——附件没有发布态。

### 删除

删除一份附件做两件事：删私有区的对象，删元数据行。删除要求工程写权限，且是一次危险动作（界面上要二次确认）。

删掉一个工程时附件**随它一起清掉**（元数据行在删工程那个事务里，对象由清理那一趟尽力删除）——工程都不存在了，它的构建产物也没有留下的理由。

### 未配置对象存储时

桶没有配置时附件**整体缺席**（与资产、内容同一条）：字节没有地方放，因此读取、上传、删除一律不可用，前端不渲染这个入口。它与工程元数据无关，因此工程照常可读写。

## 边界与约束

- **附件不进公开区，也不进发布产物。** 对象键的前缀与资产、内容都分开（见下），因此"误公开"在结构上不可能：上架那条路径只认它自己那些键。
- **附件不是文件组的条目。** 文件组的两类条目是内容对象与资产（见 [site-model.md](site-model.md)），附件不在其中——一个 `.zip` 因此不会随整站文件被推上去。
- **不做公开下载。** 做公开下载要单独设计下载域名、限流与统计，见"待定决策"。
- **不扫描、不解压、不预览。** 附件的字节永远不经过服务端，也不由服务端解释。
- **不做跨工程共享。** 与资产同一条：一个附件属于唯一一个工程。
- **不提供"列出桶里有什么"的能力。** 库内的元数据行是权威（与资产同一条）。
- **说明不进日志原文**，与文件名同级（见 [../../observability.md](../../observability.md)）。

## 对象键

| 区 | 用途 | 键 |
|----|------|-----|
| 私有区 | 附件 | `galaxy/<工程标识>/attachments/<附件标识>` |

它在 `galaxy/<工程标识>/` 之下与 `assets/`、`text/` 并排：**先按工程分组**，于是"这些构建产物属于哪个工程"在控制台里一眼可见，按工程清理也留着一条路。**不含版本段**：标注的版本是可改的（也可能随版本删除被清空），把它拼进键会让"换一个标注"变成一次搬字节。

前缀是**常量，不是配置项**（与 `assets/`、`text/`、`release/` 同一条理由）。

## 可验证性与长程执行

**非长程任务。** 上传、下载地址与删除都是即时的同步操作。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 类型不限 | 上传 `.zip`、无扩展名与二进制文件都能提交成功，元数据里记的是文件名（`internal/galaxy` 测试） |
| 下发恒为强制下载 | 签发的地址里带着 `response-content-type=application/octet-stream` 与 `attachment` 的 disposition；`.html` / `.svg` 文件名不改变这一结论（`internal/objectstore/cosupload` 测试） |
| 文件名滤过 | 带引号、反斜杠、换行与控制字符的文件名不会把额外的头拼出来，也不会产生非法头（`internal/objectstore` 测试） |
| 单文件超限即拒 | 声明超过 500 MiB 的拒于签发；真实字节数超限的拒于提交且对象被删（`internal/galaxy` 测试） |
| 配额按工程算 | 占用接近上限时，再传一份会超出的被拒于签发；声明一个小值但真实字节数超出的在提交时被拒（`internal/galaxy` 测试） |
| 摘要被核对 | 声明一个与实际字节不符的摘要：提交失败，对象被删，不留元数据行（`internal/galaxy` 测试） |
| 字节不可变 | 接口面上不存在"替换附件字节"的方法；同一附件重复读回的摘要不变（`internal/server` 测试 + `internal/galaxy` 测试） |
| 附件不进公开区 | 发布阶段不为附件写任何公开区对象；发布产物清单里没有附件路径（`internal/galaxy` 测试 + 端到端测试） |
| 附件不是文件组条目 | 一个附件标识无法作为文件组的条目参与推送（`internal/galaxy` 测试） |
| 非成员取不到地址 | 用另一个主体的凭证读附件清单、取下载地址一律被拒，且结论与"不存在"相同（端到端测试） |
| 删版本清空标注 | 删除一个被附件标注的版本后，该附件的标注为空，附件本身与字节不受影响（`internal/galaxy` 测试 + 存储契约测试） |
| 删工程清附件 | 删除工程后附件行与对象都不在（`internal/galaxy` 测试 + 存储契约测试） |
| 未配置时降级正确 | 桶未配置时附件的四个动作都返回同一个"未启用"结论，而工程元数据可用（`internal/galaxy` 测试） |
| 不联网即可测 | 对象存储藏在接口后面，测试注入假实现；签发下载地址本身不发起请求（`internal/galaxy` 与 `internal/objectstore` 测试） |
| 桶真的照做了策略 | 部署后冒烟：不带签名的地址取不到私有区对象；下载响应头确实是强制下载（部署后冒烟） |

## 依赖关系

| 依赖对象 | 交互方式 |
|---------|---------|
| galaxy 总览 | 复用 [README.md](README.md) 的概念模型、归属与权限约定 |
| 工程与版本 | 提供所属工程与归属校验；**版本标注**的清空由 [project-versioning.md](project-versioning.md) 的删除语义触发 |
| 资产库 | 本模块与它**并列而不复用**：白名单、公开区、配额模型都不同，只有直传链路与桶是共用的 |
| 对象存储直传 | 上传、提交核对与下载地址都走公共链路；**强制下载的响应头**由那里的签发入口产生（见 [../objectstore/README.md](../objectstore/README.md)） |
| 身份认证 | 只消费已确认的主体标识作为上传人（见 [../identity/README.md](../identity/README.md)） |
| RBAC | 消费 `galaxy.attachment.*` 的判定结论；归属校验在本模块（见 [../rbac/README.md](../rbac/README.md)） |
| 持久化 | 附件表见 [../persistence/schema.md](../persistence/schema.md)；字节在对象存储 |
| 可观测性 | 上传与删除的留痕**不含字节、文件名与说明**（见 [../../observability.md](../../observability.md)） |

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 公开下载链接 | 暂不做。要做需先设计下载域名、限流与统计（**未定**） | 增加一条匿名读取路径，必须与发布态的判权模型对齐 |
| 病毒与恶意文件扫描 | 暂不做，先留扩展点（**未定**） | 引入异步流水线（本模块第一个后台任务），发布与删除的语义要跟着改 |
| 在线解压与预览 zip | 暂不做（**未定**） | 服务端要解释字节，与"字节不经过服务端"直接冲突 |
| 附件转成资产 | 暂不做（**未定**） | 要过类型白名单，且要定义"同一份字节在两个键上"的取舍 |
| 附件的历史版本（同名多份） | 暂不做，重传就是新的一份（**未定**） | 需要"取代"关系，与"字节不可变"的取舍要重新论证 |
| 私有区孤儿对象回收 | 暂不做，与资产、内容合并处理（**未定**） | 需要一个对账动作；附件按标识寻址，回收要按行对账 |
