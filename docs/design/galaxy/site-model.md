# galaxy — 内容槽与文件组

> 本文件定义 galaxy 里**一份内容的形状**，以及产物是"一组文件"之后多出来的那些事：地址怎么给、每个条目的字节放在哪又由谁给出、什么算一处引用。源侧的写法见 [authoring.md](authoring.md)，发布的阶段划分见 [publication.md](publication.md)。

## 背景与目标

原先的定义是"正文是一份完整的 HTML 文档"。它只覆盖一种作品：一个页面。而用户实际要发布的是两类东西：

- **构建产物**：vite 或任何工具产出的整站——一个 HTML、若干 JS 与 CSS、若干素材。它们之间按路径互相引用，字节由工具生成，用户不会（也不该）去改。
- **多文件文档**：一组 markdown 文档，一章一个文件，互相链接。

两者的共同形状不是"一段文本"，而是**一组具名文件**。本文件定义这个形状。

成功的衡量标准：

1. 一个工程的内容是一组具名文件，路径在工程内唯一，且路径是**公开地址的一部分**。
2. 构建产物可以**一个字节都不改地**发布：产物里的 JS、CSS 与素材引用照原样生效。
3. 文档按文件分章写，发布后每一章有自己的地址，深链可以直接分享。
4. 文件组里每一处取字节的引用，都能判定它落在本文件组里——**不需要解析文本**。
5. 产物既然是"一组"，那么**整套一次性生效**：不存在入口是新的、而某一页还是旧的。
6. 站点落在发布域的 `/g/<工程标识>/` 下，这件事对用户透明：构建产物里不必知道工程标识。
7. **库不随内容增长**：保存版本与发布都不往库里写内容本身，字节按内容摘要共享，改一个文件只产生一个新对象。

## 功能行为

### 文件组：清单在库里，字节在对象存储

一个工程的内容是一组**具名文件**。

路径是相对路径、以 `/` 分隔、受限于 URL 安全字符集、不含 `..`、不以 `/` 开头或结尾、不含空段。**路径会成为公开地址的一部分，因此它的字符集不是风格偏好，是地址的约束。**

每个条目是两类之一：

| 条目 | 是什么 | 字节在哪 |
|------|--------|---------|
| 文本条目 | 写入的内容本身：HTML、CSS、JS、JSON、markdown、纯文本 | 对象存储的**私有区**，**按内容摘要寻址** |
| 资产条目 | 指向资产库里的一个资产（图片、视频、音频、字体） | 私有区按资产标识寻址；发布时上架到公开区 |

**库里保存的是清单，不是字节。** 文件组落到库里是一组 `（路径，内容摘要）`；工程行、草稿行与版本行都不带内容本身（见 [project-versioning.md](project-versioning.md)）。这与头像那一课是同一条取向，只是现在**连文本也一视同仁**：库只回答"有哪些、是什么"，字节一律交给对象存储。

**按内容摘要寻址 = 同一份内容只存一份。** 一份未改动的 JS 在多个版本、多次发布之间共享同一个对象；改一个字只有那一个文件产生新对象。这是"保存版本 = 一份完整快照"在存储上的化解方式——快照的是清单，不是字节。

**文件组只收文本；一切二进制都是资产。** 理由是**约束不同**，不是性能：媒体要有声明的类型、白名单与按类别的字节上限，并且要被单独管理（列出、引用、删除拦阻）；文本没有这些，它的类型由扩展名派生、体积由整组上限约束。把二进制放进文件组等于让它绕过那套约束。

**"哪些路径是资产"由文件组的资产条目决定。** 它是发布态分派的唯一依据，也是"这个版本引用了哪些资产"这件事的直接答案，不必解析任何文本。

源侧有两种写法落到同一件事上：构建产物的路径由命令行与上传结果绑定成条目；手写内容的 `asset://` 记号在进入文件组时被解析成条目（见 [authoring.md](authoring.md)）。**两者的一致性由写入校验固定**：文本里每一处取字节的引用都必须落在一条资产条目上，落不上就拒绝。因此条目不是文本的第二份副本，而是**引用关系本身所在的地方**（见 [publication.md](publication.md) 的引用完整性）。

### 内容槽：两种语义

工程在**创建时**至少选一个内容槽，此后**只增不删**。让历史版本无法复现的从来不是"多了一个槽"，而是"同一个槽换了语义"——而槽的语义不再可变，因此加一个槽不会动到任何已保存的版本。

| 槽 | 文件组是什么 | 发布做什么 | 入口 |
|----|------------|-----------|------|
| `site` | 整站文件：HTML、CSS、JS、JSON、纯文本 | **原样服务** | `index.html` |
| `docs` | 一组 markdown + 少量**站点文件**（CSS、JS、JSON） | 渲染 markdown 成多页，并把站点文件按原路径一并带上 | `index.md` |

**一个工程可以两个槽都有，也可以只有一个，两槽互不影响。** 站点槽发它的整站，文档槽发它的多页文档，各有一套草稿、版本与发布指针，谁也不用管另一个（见 [project-versioning.md](project-versioning.md)）。**这就是"文档是站点的补充"落成的形状**：一个已经发布了的站点，可以再长出文档来，而不必变成另一个工程、也不会被重推一次站点覆盖掉。

**入口文件必须存在。** 缺失时是**写入期**的拒绝（保存草稿即失败），而不是等到发布才发现。这条**按槽各判各的**：`site` 槽要 `index.html`，`docs` 槽要 `index.md`。

两种槽的差别落在四处，**没有一处在对象存储的键上**：

| | `site` 槽 | `docs` 槽 |
|--|---------|---------|
| 入口 | `index.html` | `index.md` |
| 文件组里是什么 | 整站文件 | markdown（**渲染输入**）+ 站点文件（**原样服务**） |
| 发布时对文件做什么 | 原样服务 | markdown 渲染成页；站点文件原样 |
| 扩展名白名单 | HTML、CSS、JS、JSON、纯文本 | markdown、CSS、JS、JSON（**不收 HTML**） |

**键上不体现槽，因为这不是键该回答的问题。** 内容寻址的键只回答"这份字节是什么"——同一个摘要既可能是某个工程的 markdown，也可能是另一个工程的 JS 或 CSS，因此**同一个 `text/<内容摘要>` 在两个槽下长得完全一样**。槽只住在一个地方：**内容槽行**；而"这个条目是渲染输入还是原样服务的内容"由**清单里的路径与扩展名**给出。要判断一个对象属于谁、拿来做什么，读库，不要读键。

`site` 槽同时覆盖构建产物与手写页面：**手写单页就是"文件组里恰好一个 `index.html`"的特例**，因此不存在第三种槽。

### 地址：一个文件一个地址

每个槽有自己的根，槽内的某一份文件是 `<槽根><路径>`：

| 槽 | 根 | 入口 |
|----|-----|------|
| `site` | `<发布域>/g/<工程标识>/` | `<发布域>/g/<工程标识>` |
| `docs` | `<发布域>/g/<工程标识>/docs/` | `<发布域>/g/<工程标识>/docs` |

**地址按槽固定，与另一个槽是否存在无关。** 这是"槽可增"的前提：若文档的地址会随站点槽的有无而移动，后加一个槽就会挪走一条已经发出去的地址。

**上表里的入口地址都不带结尾斜杠，而槽根是带斜杠的那一个**：交付入口对不带斜杠的槽根先 301 到带斜杠的形式——页内相对地址按文档所在的目录解析，理由见下面"取字节"。

**`docs` 因此是一个保留段：`site` 槽的路径不得以 `docs/` 开头**，写入期拒绝。这与预览通道占住 `p` 段是同一种做法——用一个固定分段占住位置，而不是靠猜来消歧。代价诚实记下：一个 `site` 工程因此用不了顶层 `docs/` 目录。换来的是一条**稳定**的文档地址，以及"加槽不动旧地址"这条性质。

- 入口与入口文件是**同一页**（`/g/<标识>` 与 `/g/<标识>/index.html`；`/g/<标识>/docs` 与 `/g/<标识>/docs/index.html`——`docs` 槽那一份是渲染出来的，产物里没有 `index.md`）。
- **读取侧只做集合成员测试**：这个路径在"该槽当前发布的那一版"的文件集合里吗。不拼接路径、不规范化、不碰文件系统。`..`、重复斜杠、大小写与编码差异因此无从生效——路径在写入时就已被形状约束限定死。
- **否定结论只有一个**：未发布、已撤回、已删除、工程标识不存在、路径不在集合里，五者返回同一个"不存在"。**槽没有启用也算在这一条里**——向一个没有 `docs` 槽的工程请求 `/g/<标识>/docs/...`，与请求一个不存在的路径没有区别。区分它们等于告诉猜地址的人"这个标识是真的"或"这一页是真的，只是还没发布"（见 [publication.md](publication.md)）。

### 取字节：文本由服务端在自然路径上给出，媒体走重定向

| 请求的路径 | 返回 |
|-----------|------|
| 一条**文本条目** | 服务端返回内容。`ETag` 是该条目的**内容摘要**，并带 `Cache-Control: no-cache` |
| 一条**资产条目** | 一个**重定向**到该资产的公开区地址；字节由浏览器直连对象存储，服务端不代理 |

**为什么文本必须是服务端给，而不能也重定向到公开区。** 因为**内容寻址会抹掉路径**：文档一旦落在 `<桶域>/galaxy/<工程标识>/release/<摘要>` 上，它的 base URL 就是那个摘要地址（`base-uri` 为 `'none'`，没有 `<base>` 能救），于是文档里的每一处 `/assets/index.js` 与每一处相对链接都会解析到桶域上一个不存在的位置——构建产物的 base 是 `/g/<标识>/`、文档站的页间链接是相对的，两者都指望"路径还在"。**能重定向的只有自身不含引用的东西**：图片、视频、音频、字体。它们恰好是字节量的大头，因此 CDN 的收益仍然拿到。

**同理，入口那一跳要把目录补全。** 交付入口对**不带结尾斜杠的槽根**先 301 到带斜杠的形式（见 [publication.md](publication.md) 的"发布记录与对外地址"）：文档停在不带斜杠的入口上时，页内相对地址会解析到**上一层目录**，与上一段是同一个失效——而那正是上面那条"构建产物一个字节都不改地发布"的判据所依赖的东西。用 `project base` 写站点绝对地址的产物不受影响，**手写相对地址的页面**靠这一跳才成立。

**`no-cache` 不是"不缓存"。** 它让 CDN 存下文档、但每次向服务端校验。于是撤回（改指针）在**下一次请求**就生效，不必失效任何缓存；而校验命中时服务端只读库里的清单，不碰对象存储。

**文本字节不进公开区。** 服务端从私有区读它，因此**文本不需要上架**——上架只为媒体而做（匿名可读）。公开区因此仍然只装媒体，与头像共用同一个桶的理由不变。

两条必须写死的约束：

- **允许的来源要同时含 `'self'` 与桶主机。** 媒体重定向的起点是发布域、终点是桶；只允许桶的表现是浏览器在跳转前那一次请求就被策略拦下。这与 [publication.md](publication.md) 里"地址指向 A、策略允许 B"是同一类失败，只是方向相反。
- **媒体条目在上架阶段按（内容摘要，类型）上架**，与其它被引用的资产走同一条路（幂等、不产生重复字节）。

**为什么媒体是重定向，而不是把公开地址写进产物。** 因为构建产物一个字节都不能改：产物里写的是 `/assets/logo-abc.png`，解析成站点内的绝对地址即可，公开区的地址既不进产物也不进源。这正是原先把真实地址写进源所避免的那两条代价（会过期的字符串、与发布态不一致的字符串）。

### 引用完整性

规则从"正文里的占位符"推广成一句：

> **每一处取字节的引用，其目标路径都必须落在本文件组里。**

落在一条**文本条目**上由服务端给出，落在一条**资产条目**上重定向到公开区；落不上——外部地址、别的工程的路径、文件组里不存在的位置——一律拒绝。

原先那条区分仍然成立，且要在实现里守住（见 [publication.md](publication.md)）：

| 写法 | 例子 | 规则 |
|------|------|------|
| **取资源的引用** | `<img src>`、`<video src>`、`<link href>`、CSS `url()`、`srcset`、脚本里的取资源路径 | 只能是文件组里的一条条目（文本或资产）。**发布物不得从本工程之外取任何一个字节** |
| **导航链接** | `<a href="https://example.com">` | 可以是任意地址 |
| **页内导航** | `<a href="#小节">`、`<a href="?q=1">` | 指向**本页自己**，不落在任何条目上，原样保留。**只有后缀、没有位置**的写法只有这一档 |

**引用可以带一个跟在位置后面的后缀**——锚点（`#小节`）或查询串（`?q=1`）。后缀说的是
"这个位置里的哪一部分"，而文件组记的是位置，所以**后缀先摘掉再查，位置解析出来之后
再把后缀原样接回去**：`guide/intro.md#小节` 得到的是那一页的产物地址加 `#小节`。把两者
当成一个整体去查，表现就是每一处带锚点的引用都变成一次"引用了文件组里不存在的位置"。

**锚点指不指得到，不校验。** 判断 `#小节` 里的名字对不对，要么再走一遍本页的语法树、
要么回读渲染出来的 HTML——两者都不做，理由与"改写发生在语法树上、不在 HTML 上"同源。
指不到就是浏览器停在原地，不会给出一个坏页面；GitHub 也不查这一条。

引用写成什么形状，取决于谁在写：

- **构建产物写的就是路径**（`/assets/index-abc.js`），**一个字都不改**。
- **手写 HTML 与 markdown 写 `asset://<资产标识>`**，它是**源侧记号**：在"进入文件组"那一步被解析成一条资产条目（路径默认取 `assets/<资产标识>`），发布时把该记号逐字替换成它在文件组里的路径。因此"逐字替换、不解析 HTML"这条性质保住（见 [authoring.md](authoring.md)），而"引用了哪些资产"从此不必解析。

**站点根不是发布域根。** 内部引用必须以发布根为基准，因此：

- 命令行能注入发布根的（构建产物），由它在构建时解决（见 [cli.md](cli.md)）；
- 发布时逐处校验内部引用是否落在文件组里，不落在则拒绝并指出**是哪一份文件的哪一处**。

**外部地址一律拒绝**（导航链接除外）。构建产物若引了 CDN，发布会失败并指出那一处——这是"只引用本工程资产"的固定代价：依赖要打进产物。这条必须让用户看得见，而不是留给访问者发现一张加载不出来的图。

### 文本的类型

文本条目的下发类型由**扩展名与一张白名单**决定，白名单之外的扩展名在**写入期**拒绝。下发时带 `nosniff`。

**白名单按槽给出**：`site` 收整站文件那一套（HTML、CSS、JS、JSON、纯文本），`docs` 收 markdown 与站点文件（CSS、JS、JSON）——**`docs` 不收 HTML**，因为它的页面是渲染出来的，不是写出来的；放开 HTML 等于让两套页面来源并存，而它们的优先级无从回答。白名单的具体取值实现时定。

**不做嗅探。** 这与资产那边"声明不等于验证"是同一条真实代价（见 [asset-library.md](asset-library.md)），只是这里没有危害：文本是服务的对象，这个源本来就允许跑用户自己的脚本。

### `docs` 槽的渲染

- **渲染发生在服务端、在发布时**，是一次**确定性**的变换。因此产物不再等于用户原文——这与 `site` 槽的"逐字相同"不同，是本模块第一条允许服务端生成标记的路径。
- **渲染规则按版本钉住**：版本记录它保存时所用的渲染规则版本，重新发布用它而不是用当前最新的。否则"撤回后重新发布同一版本，产物逐字相同"（见 [publication.md](publication.md)）会在渲染器升级的那天悄悄失效。
- **渲染取的是 GitHub 风格的 markdown**（表格、删除线、任务列表、裸地址成链）。这不是可选项：裸的 CommonMark 里没有表格，而"一张 pipe 表被静默当成一段带管道符的正文"是一种不报错的坏——用户写 markdown 时的预期本来就来自 GitHub。
- **外壳与排版是渲染规则的一部分。** 每一页的 `<!doctype>`、顶栏、侧栏、本页目录与一份内联样式都由 aladdin 生成，与正文一起构成产物、一起按版本钉住。**这与 `site` 槽"逐字相同"正相对**：那里 aladdin 一个字节都不加；这里整页都是它渲染的，因此"页面长什么样"是我们说了算的事，而不是往用户内容上叠的东西。
- **版式照搬 VitePress 默认主题的取值**（配色 token、字号阶梯、正文 688px、二级标题带上边线、表格斑马纹、代码块外壳与语言标签、标题悬停锚点）。借的是取值而不是它的样式文件：这里手写，只留这份版式真正要用的部分。**明暗两套取值都在同一处，暗色只跟随系统**（`prefers-color-scheme`）——不做手动开关是"产物里不出现 aladdin 编写的脚本"的直接后果：没有脚本就没有地方记住选择，一个翻页就回到原样的开关不如没有。
- **标题锚点与目录同源。** 二级、三级标题在渲染时拿到页面内的锚点标识，目录那一行指的就是正文里那个 `id`——两处同源就不会出现"目录指向一个正文里不存在的锚点"这种只在点下去时才发现的问题。标识自己算，保留表意文字：用 goldmark 的自动标识会让一份中文文档得到 `heading-1`、`heading-2` 这样一串与内容无关的名字。
- **窄屏下侧栏折成一行可横滑的链接，目录整块收起。** 没有汉堡菜单——那也是脚本。折叠的判据是视口宽度（[../web/responsive.md](../web/responsive.md) 那一套）。
- **文档间引用**写相对 `.md` 路径，发布时解析成站点内的绝对地址；指向文件组里不存在的位置即拒绝，并指出是哪一份文件的哪一处。
- **侧栏只由 markdown 文件的树派生**，不引入清单文件，**站点文件不进侧栏**。文件组是"有哪些文档"的唯一信源：排序取路径序，标题取每份的首个一级标题；要固定顺序就用带序号的文件名。当前这一页在侧栏里高亮。
- **顶栏上那个站名取自入口文档（`index.md`）的一级标题。** 产物里没有别处记着"这个站叫什么"，而入口本来就是这份文档集的首页。
- **站点文件不是渲染结果，按原路径一并进产物**（`theme.css` 还是 `theme.css`）。因此文档站的产物是"渲染出的每一页 + 原样带上的站点文件"，两者都在产物清单里、都按路径分派。
- **渲染器产出的地址一律是站点绝对路径。** 页面落在嵌套路径下，相对地址会解析到错误的层级——这一点与构建产物那一侧同源（见上）。
- **产物里不出现 aladdin 编写的脚本。** 页面切换靠锚点与原生机制，不靠一段注入的路由脚本——发布域上跑的只有用户自己的代码。

### 预览：草稿整组从一条自己的地址上给出

预览把**整组草稿**按发布的路径形状，从一条**预览自己的地址**上提供，再把那条地址交给沙箱 iframe（`src`，不是 `srcdoc`）。文档因此有了自己的源与目录，页内的相对地址与站点绝对地址都由浏览器自己解析——与上面"文本必须由服务端在自然路径上给出"是同一条道理。

地址形如 `<发布域>/g/p/<凭证>/<工程标识>/<路径>`——预览根就是发布域下 `p/<凭证>/` 接上**该槽的发布根**（`site` 槽是 `<工程标识>/`，`docs` 槽是 `<工程标识>/docs/`）。它落在发布域既有的 `<发布域>/g/` 之下，因此**不新增域名、证书或服务端入口**；`p` 不是合法的工程标识形状，因此它永远撞不上某个工程自己的路径。

**两个槽都走这条通道，一次预览落在一条槽上。** 预览的是"这个槽的草稿整组"，凭证也绑在（工程，槽）这一对上——拿站点槽的凭证去取文档槽的路径，与"这一页不存在"没有区别。`docs` 槽的页面不是现成的文件，因此在预览时**由服务端渲染**（与发布同一段渲染，只是按请求算、且宽容——见下），导航链接指向预览根下的真实地址；站点文件按原路径给出。于是"预览里能不能用"这件事不再按槽分叉：**预览看到的是一份完整的、页面之间真的能跳转的站点**。

**文本条目由服务端给出，资产条目重定向到编辑态的短时地址。** 与发布态的差别只有三处：

| | 发布态 | 预览态 |
|--|-------|-------|
| 取哪一份清单 | 当前发布的**版本** | 当前**草稿** |
| 凭证 | 无（公开匿名，地址即凭据） | 短时**凭证**，随地址走 |
| 资产地址 | 公开区（匿名可读） | 私有区的短时预签名地址 |

**"文本由服务端给出"在预览上比在发布上更硬。** 内容对象在桶上是**中性类型**（对象本身不承担类型语义，下发类型由扩展名派生）——直接取回来是一段 `application/octet-stream`，浏览器不会拿它当样式或脚本用。因此页面的 CSS 与 JS 只有"服务端按自然路径给出"这一条路：把引用换成任何一个桶上的地址都不成立。

**引用改写只有一处：发布根换成预览根。** 构建产物写的是站点绝对地址（`/g/<工程标识>/assets/index-abc.js`，见 [cli.md](cli.md)），它在预览里必须落在同一个工程、同一个槽的**草稿**上。因此经这条通道给出的每一份文本，**该槽的发布根**被逐字换成**该槽的预览根**（`/g/<标识>/` → `/g/p/<凭证>/<标识>/`；`docs` 槽则是 `/g/<标识>/docs/` → `/g/p/<凭证>/<标识>/docs/`）。这是一次**已知字符串**的替换：不解析、不枚举引用位置，因此也不会漏。

**凭证短时、随地址走、"地址即凭证"。** 预览是给看过这一页的人用的，因此凭证由 `galaxy.project.read` 换出来，过期即失效，重新渲染预览得到新地址（与"重新读取即得到新地址"同源）。有效期取**分钟**量级，具体值是一个常量、不由配置给出：这类"凭据的窗口"在本仓库一律留在代码里（会话、资产短时地址、事件通道的寿命同此），配置只回答"这个部署长什么样"。

**过期的表现要说清楚：页内跳转会失效**——票过了，而已经打开的那一页里用的还是地址里那张旧票；这时**刷新**一次即换新票（工作台那一侧每次重新渲染本来就会换）。已经加载出来的媒体不受影响：它的短时地址比票长。**草稿地址不得被当作分享链接长期使用**——这与未发布资产那条约束同源，属于预览接受的那条取舍。

**隔离不变，且由两条一起保证。** 预览文档仍然落在**不透明源的沙箱 iframe** 上（`allow-scripts`，不给 `allow-same-origin`，见 [authoring.md](authoring.md)），因此内容里的脚本读不到主应用的 DOM、会话与本地存储；而这条通道落在发布域上，发布域必须与主应用**不同源**（见 [publication.md](publication.md)）。**不能靠"把草稿从应用源上服务出去"来省掉这条通道**：那份 HTML 一旦被直接打开就是一次应用源上的脚本执行。

**没有发布域的部署没有预览。** 这条通道落在发布域上，未配置发布域时预览整体缺席，如实缺席——而不是退回一份解析不了自己引用的文档假装能用。

## 边界与约束

- **不做构建。** 命令行不内含打包器、不解析构建配置、不改写产物里的引用——它只注入发布根并把产物搬上去。
- **库内不存字节。** 文件组与产物都以清单落库，字节一律在对象存储（理由见上）。
- **文件组只收文本**（理由见上）。
- **不做通用 CMS 的建模能力**：导航从文件树派生，没有分类、字段、模板（见 [README.md](README.md)）。
- **不提供"列出某工程的全部页面"的独立入口。** 站内导航是产物的一部分；跨工程的枚举入口一个都不存在。
- **槽只增不删**（理由见上）。
- **`docs` 是保留段**：`site` 槽的路径不得以 `docs/` 开头（理由见上）。

## 可验证性与长程执行

**非长程任务。** 文件组的读写都是即时的同步操作；发布才是长程的，见 [publication.md](publication.md)。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 构建产物零改写 | 把一份含外部 JS/CSS 与素材路径的产物原样送入并发布，产物里的每一处路径与送入时逐字相同（`internal/galaxy` 测试） |
| 文本由服务端在自然路径上给出 | 请求一条文本条目的路径得到 200 与内容，且 `ETag` 等于该条目的内容摘要（`internal/galaxy` 测试 + 端到端测试） |
| 媒体条目的字节不从服务端出 | 请求一个资产条目的路径得到重定向，响应体不含字节（`internal/galaxy` 测试 + 端到端测试） |
| 文本不进公开区 | 上架阶段只写媒体对象；文本内容在公开区不存在（`internal/galaxy` 测试 + 部署后冒烟） |
| 字节不入库 | 工程行、草稿行与版本行都不含内容本身（`internal/galaxy` 测试 + 代码审查） |
| 同一份内容只存一份 | 同一份字节出现在两个路径或两个版本下时，指向同一个对象键（`internal/galaxy` 测试） |
| 允许的来源含起点与终点 | 内容安全策略里 `img-src` / `media-src` / `font-src` 同时含 `'self'` 与桶主机（`internal/galaxy` 测试） |
| 路径约束 | 含 `..`、前导 `/`、空段、白名单外字符的路径在写入时被拒（`internal/galaxy` 测试） |
| 集合成员测试 | 请求一个不在当前发布集合里的路径，得到与"未发布"相同的否定结论（端到端测试） |
| 入口等价 | `/g/<标识>` 与 `/g/<标识>/index.html` 返回同一页（端到端测试） |
| 内部引用必须落在文件组里 | 产物引用一个不在文件组里的路径时发布失败，错误信息指出文件与位置（`internal/galaxy` 测试） |
| 外部引用被拒 | 产物引用 CDN 时发布失败并指出那一处（`internal/galaxy` 测试 + 端到端测试） |
| 引用集合由清单决定 | 同一清单里的资产条目集合在草稿与各版本上一致；发布态只按条目分派（`internal/galaxy` 测试） |
| 文本不收二进制 | 送入一个二进制内容的条目被拒（`internal/galaxy` 测试） |
| 类型按扩展名白名单 | 白名单外的扩展名在写入时被拒；下发带 `nosniff`（`internal/galaxy` 测试 + 部署后冒烟） |
| 渲染确定性 | 同一版本重复渲染，产物逐字相同（`internal/galaxy` 测试） |
| 渲染规则按版本钉住 | 构造"以旧规则保存的版本"，重新发布得到旧规则下的产物（`internal/galaxy` 测试） |
| 表格真的渲染成表 | 一段 pipe 表在产物里是 `<table>` 而不是含管道符的段落；删除线、任务列表同此（`internal/galaxy` 测试） |
| 目录锚点与正文同源 | 目录每一项的 `href` 指向的 `id` 在正文里存在；同一页重名标题各得一个不同的标识（`internal/galaxy` 测试） |
| 明暗两态都在同一处 | 产物自带的样式里同时含浅色与 `prefers-color-scheme:dark` 两套取值（`internal/galaxy` 测试） |
| 当前页在侧栏里可辨 | 侧栏里只有当前这一页带 `aria-current`（`internal/galaxy` 测试） |
| 文档引用解析 | 文档间链接在产物里指向同一站点下的目标地址；指向不存在的位置即拒绝（`internal/galaxy` 测试） |
| 锚点只跟着位置走 | `guide/intro.md#小节` 的地址是那一页的产物地址加 `#小节`；`#小节` 与 `?q=1` 原样保留、发布与预览都不拒绝；`![图](#小节)` 仍被拒（`internal/galaxy` 测试） |
| 站点文件按原路径进产物 | `docs` 槽下站点文件在产物里的路径与文件组一致，且不是渲染结果（`internal/galaxy` 测试） |
| 站点文件不进侧栏 | 侧栏条目只对应 markdown 文件（`internal/galaxy` 测试） |
| `docs` 不收 HTML | 往 `docs` 槽写入 `.html` 被拒（`internal/galaxy` 测试） |
| 保留段被拒 | 往 `site` 槽写入以 `docs` 为首段的路径被拒，错误说明它是保留段（`internal/galaxy` 测试 + 命令行测试） |
| 槽的地址固定 | `site` 槽的根是工程根、`docs` 槽的根是它下面的 `docs/`，与另一个槽是否存在无关（`internal/galaxy` 测试） |
| 两槽各有一套 | 同一工程两个槽各自的草稿、版本、发布指针与地址互不影响；发布一个槽不改变另一个（`internal/galaxy` 测试 + 端到端测试） |
| 导航派生 | 导航条目与文件组一一对应，不读第二处清单（`internal/galaxy` 测试） |
| 产物无 aladdin 脚本 | 文档产物里不出现服务端注入的 `<script>`（`internal/galaxy` 测试） |
| 整套一次性生效 | 发布中途失败时，所有路径读到的都仍是上一次的产物（`internal/galaxy` 测试） |
| 槽只增不删 | 接口面上不存在"删除内容槽"的方法（`internal/server` 测试） |
| 加槽不动旧地址 | 加一个槽之后，另一个槽的入口地址与产物逐字不变（`internal/galaxy` 测试） |
| 草稿整组按路径可取 | 经预览通道请求草稿里的每一条路径都取到字节，文本的类型由扩展名派生（`internal/galaxy` 测试 + 端到端测试） |
| 预览不把字节塞进文档 | 预览交付的是一条地址（iframe 用 `src`），不把整份文件组的内容拼进 `srcdoc`（前端测试 + 端到端测试） |
| 预览凭证短时且过期失效 | 凭证带失效时刻；过期或伪造的凭证得到与"这一页不存在"相同的否定结论（`internal/galaxy` 测试 + 端到端测试） |
| 预览凭证绑在槽上 | 拿一个槽的凭证请求另一个槽的路径，得到与"这一页不存在"相同的否定结论（`internal/galaxy` 测试） |
| 预览的资产走私有短时地址 | 预览通道里一条资产条目重定向到私有区的短时地址，不是公开区地址（`internal/galaxy` 测试 + 端到端测试） |
| 发布根换成预览根 | 经预览通道给出的文本里，站点绝对地址落在预览根下，且指向的是草稿（`internal/galaxy` 测试） |
| 预览域与主应用不同源 | 预览通道与发布物落在同一个源上，该源与主应用不同源，由启动校验强制（`internal/config` 测试） |
