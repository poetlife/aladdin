# galaxy 模块总览

> 本目录是 aladdin **"用户创作一个网页并把它发布出去"** 这一能力的唯一信源。

## 背景与目标

aladdin 目前有三块能力：认人（[../identity/](../identity/README.md)）、判权（[../rbac/](../rbac/README.md)）、记这个人长什么样（[../profile/](../profile/README.md)）。它们全都服务于"管理 aladdin 自己"。没有任何一块回答"用户能用 aladdin 做出什么东西"。

galaxy 补上这一块：用户在 aladdin 里写 HTML、放素材，然后发布成一个别人能打开的页面。

它要回答三个问题：

| 问题 | 归属 |
|------|------|
| 作品怎么组织、改坏了能不能退回去 | **工程与版本**（[project-versioning.md](project-versioning.md)） |
| 图片、视频、音频放哪 | **资产库**（[asset-library.md](asset-library.md)） |
| 写下的东西怎么变成别人能看的页面 | **编写与预览**（[authoring.md](authoring.md)）、**发布**（[publication.md](publication.md)） |

成功的衡量标准：

1. 用户能创建工程、写 HTML、上传素材、发布，并在发布后用一个地址看到自己的页面。
2. **发布物永远恰好是一个 HTML 文档**：CSS 与脚本内联其中，不产生第二个文件。HTML 之外唯一的引用是媒体资产。
3. **发布物只引用本工程资产库里的资产**。正文里出现任何别处的引用，发布被拒绝并指出那一处，而不是发布出去一张裂图。
4. 一个版本一旦保存就**不可变**：它当时引用什么，此后永远引用什么。因此"发布过的页面内容变了"这件事不会发生。
5. 已发布页面对**未登录的人**可打开；草稿与未发布的版本对除拥有者外的所有人不可见。
6. 未配置发布所需的存储时，工程与资产照常可用，只有发布不可用；前端据此不渲染发布入口。

## 概念模型

| 概念 | 含义 | 关键性质 |
|------|------|---------|
| 工程（Project） | 创作单元：元数据 + 一份草稿 + 若干版本 + 一个资产库 | 有一个拥有者主体；标识由 aladdin 分配且不可猜 |
| 草稿（Draft） | 工程当前正在编辑的正文，随时可改 | 不是版本，不参与发布，不保证可退回 |
| 版本（Version） | 正文的一次**不可变快照** | 保存即冻结；发布只能发布版本，不发布草稿 |
| 资产（Asset） | 工程资产库里的一个媒体文件 | 字节在对象存储；不可变；属于唯一一个工程 |
| 发布（Publication） | 把一个版本冻结成对外可达的产物 | 产物是一个 HTML；对外地址稳定；可撤回 |

四者的关系是**单向包含**：工程拥有版本与资产，发布指向版本。**资产不属于版本**——一个版本引用了哪些资产，由该版本的正文里的占位符决定，正文是这件事的唯一信源（理由见 [project-versioning.md](project-versioning.md)）。

## 模块边界

本模块**明确不做**：

| 不做的事 | 理由 |
|---------|------|
| 服务端执行用户代码 | 发布物是静态文档。"用户能在 aladdin 上运行代码"是完全不同的一件事，且它带来的隔离要求比静态渲染高一个量级 |
| 通用 CMS 的建模能力 | 没有分类、字段、关系、模板。用户要结构化数据，自己写在 HTML 里 |
| 多人实时协作 | 首版一个工程一个拥有者。协作需要显式的成员与并发模型，见 [project-versioning.md](project-versioning.md) 的待定决策 |
| 分支与合并 | 版本的演进是线性的。见同上 |
| 自定义域名、模板市场、SEO 收录 | 都不属于"让用户把一个 HTML 发出去"这件事的最小闭环 |
| 转码与缩略图 | 上传什么就分发什么。转码是一整条独立的处理流水线，见 [asset-library.md](asset-library.md) 的待定决策 |

## 归属与权限

### 两把闸门，各管一件事

| 闸门 | 管什么 | 唯一入口 |
|------|--------|---------|
| RBAC 权限码 | 这个主体**有没有资格**创作 | [../../../api/permissions/catalog.yaml](../../../api/permissions/catalog.yaml) |
| 归属 | 这个工程**是不是他的** | 工程记录上的拥有者主体 |

**归属不由 RBAC 表达。** 这一条沿用 [../rbac/role-model.md](../rbac/role-model.md) 已经划走的边界（"只能看到自己创建的订单"属于资源归属）。权限码决定"能不能创作"，归属决定"能创作哪些"。两把闸门都必须过。

**没有以他人工程为目标的接口。** 所有 galaxy 方法的目标工程都必须是**调用者自己的**，不存在"指定别人的工程标识"这个形状。这与档案模块"每个方法只作用于调用者自己"是同一取向（见 [../profile/README.md](../profile/README.md)）。

### 权限码

| 权限码 | 含义 |
|--------|------|
| `galaxy.project.read` | 读取自己的工程、草稿与版本 |
| `galaxy.project.write` | 创建、修改、删除工程，保存版本 |
| `galaxy.project.publish` | 发布与撤回发布 |
| `galaxy.asset.read` | 读取自己的资产列表与地址 |
| `galaxy.asset.write` | 上传与删除资产 |

**`galaxy.project.publish` 单独一码**，因为它是本模块里唯一一个让内容**离开私有边界**的动作。撤回发布也用它——撤回是发布的反向操作，不给它单独一码不会带来任何安全收益，只会让"发布得出去、收不回来"变成一个可以只授一半的组合。

权限码落在新建的内置角色 **`galaxy.author`（创作者）** 上，作用域限于其被授予的作用域。它不是 `viewer` 的扩展：`viewer` 是只读用户，而 galaxy 的"读"受归属约束——给一个没有工程的人 `galaxy.project.read` 不产生任何可见效果。

## 发布即公开（本模块最重要的一条取舍）

**发布态的读取不走 RBAC，也不走鉴权拦截器。** 它是仓库里第一条让未认证的一方读到业务内容的路径。

因此：

- **工程标识必须不可猜。** 它是发布地址的一部分，而"公开匿名"的具体含义是**地址即凭据**：拿到地址的人能看，猜不出地址的人看不到。
- **不存在"列出所有已发布工程"的入口。** 一旦有，不可猜标识就失去意义——那等于把"地址即凭据"降级成"打开首页就能逛"。这条要作为一项可验证的约束守着。
- **发布物内不得承载任何秘密。** 因为公开匿名，且地址可能被转发。这与头像那条"头像不得承载秘密"同源（见 [../profile/avatar-storage.md](../profile/avatar-storage.md)），但更强：头像是发给本人，发布物是发给所有人的。

## 引用完整性的唯一入口

"**这段正文能不能发布**"是一个**判断**，按 [../../../docs/ssot-registry.md](../../ssot-registry.md) 的 SSOT 原则只有一个实现入口，且在**服务端**。规则全集见 [publication.md](publication.md)。

编辑器需要即时提示时，**调用同一个服务端入口**，而不是在前端复写一套引用解析。两端各写一份的表现是"编辑器说没问题、发布说不行"（或更糟的反过来），而用户无法从任何一个提示里知道哪个是对的。这与"前端不缓存判定结果"是同一条原则的应用。

## 依赖关系

| 依赖对象 | 交互方式 |
|---------|---------|
| 身份认证 | 只消费"已确认的主体标识"，把它作为工程的拥有者（见 [../identity/](../identity/README.md)） |
| RBAC | 消费权限码判定结论；归属校验在本模块，不复制进 RBAC（见 [../rbac/](../rbac/README.md)） |
| 个人档案 | **无交互**。工程不显示拥有者的昵称与头像——发布态是公开匿名的，把展示信息带上去会引入一条新的身份暴露面，见 [publication.md](publication.md) 的待定决策 |
| 持久化 | 四张表由持久化模块统一管（见 [../persistence/schema.md](../persistence/schema.md)） |
| 对象存储直传 | 资产的字节走公共直传链路（签发凭证、直传、提交核对），见 [../objectstore/README.md](../objectstore/README.md) |
| 对象存储 | 私有区与公开区在**同一个桶**里（不同前缀），公开区靠逐对象的公开读区分，见 [asset-library.md](asset-library.md) 与 [publication.md](publication.md) |
| 服务端配置 | 桶地址（沿用 `cos_bucket_url`）与发布域由配置给出（**各项上限是常量，不是配置项**，见 [../config/server-config.md](../config/server-config.md)） |
| proto | 方法与权限码在 `api/proto/aladdin/galaxy/v1/` 中声明，经 `buf generate` 派生两端代码 |
| 前端权限 | galaxy 页面的入口按 `galaxy.*` 权限码裁剪（见 [../rbac/frontend-permissions.md](../rbac/frontend-permissions.md)） |
| Web 界面 | 呈现机制见 [../web/README.md](../web/README.md)；取舍见 [../uiux/README.md](../uiux/README.md) |
| 可观测性 | 发布各阶段留痕，见 [publication.md](publication.md) 与 [../../observability.md](../../observability.md) |

## 可验证性与长程执行

**部分属于长程任务。** 工程与资产的读写是即时的同步操作；**发布不是**——它要把一批资产搬到公开区，可能很慢、可能中断。发布的阶段划分、进度判据与检查点见 [publication.md](publication.md)。

跨子模块的约束：

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 发布物恒为一个文档 | 一次发布产出恰好一个 HTML 产物；产物内不含指向第二个文档的引用（`internal/galaxy` 测试） |
| 只引用本工程资产 | 引用他工程资产、外部地址或 `data:` 的正文一律发布失败，错误信息指出那一处（`internal/galaxy` 测试 + 端到端测试） |
| 版本不可变 | 保存版本后改动草稿，已保存版本读回的内容逐字不变（`internal/galaxy` 测试） |
| 草稿不可发布 | 对没有版本的工程发起发布被拒；改草稿后重新读到的是发布时的产物而不是改后的正文（端到端测试） |
| 归属不可绕过 | 用一个主体创建的工程标识，在另一个主体的凭证下读取、修改与发布一律被拒（端到端测试） |
| 没有以他人工程为目标的形状 | 接口面上不存在"指定拥有者"的方法（`internal/server` 测试：遍历 method descriptor） |
| 发布入口公开 | 未携带任何凭证请求发布地址能取到当前发布产物（端到端测试） |
| 未发布不可达 | 未发布的工程、已撤回的工程，其发布地址返回"不存在"而不是空页（端到端测试） |
| 不可枚举 | 接口面上不存在列出已发布工程的入口（`internal/server` 测试：遍历 method descriptor） |
| 权限码不外泄 | 无 `galaxy.*` 权限时，工程与资产入口不渲染；直接调用被拒（前端测试 + 端到端测试） |
| 未配置时降级正确 | 发布域未配置时工程与资产的读写照常，发布入口不可用（`internal/config` 与 `internal/galaxy` 测试） |

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 工程的对外名字（可读 slug） | 暂不做，只用不可猜标识（**未定**） | 需引入唯一性与保留字校验；与"不可枚举"这条约束的关系要重新论证 |
| 管理员 / 审计员查看他人工程 | 暂不做。真出现时单独设计并带权限码（**未定**） | 以他人为目标，与档案模块同类问题（见 [../profile/README.md](../profile/README.md) 的待定决策） |
| 发布物上显示拥有者信息 | 暂不做，发布态不带任何主体标识（**未定**） | 引入一条身份暴露面；要重新论证"公开匿名的发布物可以显示谁做的" |
| 资产跨工程复用 | 暂不做，一个资产属于一个工程（**未定**） | 对象键与删除语义都要改；公开区已按内容寻址，复用成本主要在归属与回收 |
| 发布域是否必填 | 未配置则发布不可用（**已定**，见 [publication.md](publication.md)） | 影响配置校验与前端裁剪，不影响工程与资产 |
