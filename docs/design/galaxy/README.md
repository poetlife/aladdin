# galaxy 模块总览

> 本目录是 aladdin **"用户创作一个网页并把它发布出去"** 这一能力的唯一信源。

## 背景与目标

aladdin 目前有三块能力：认人（[../identity/](../identity/README.md)）、判权（[../rbac/](../rbac/README.md)）、记这个人长什么样（[../profile/](../profile/README.md)）。它们全都服务于"管理 aladdin 自己"。没有任何一块回答"用户能用 aladdin 做出什么东西"。

galaxy 补上这一块：用户在 aladdin 里放下一份**内容**——手写一个页面、送上一份构建产物、或写一组文档——再放素材，然后发布成一个别人能打开的站点。

它要回答三个问题：

| 问题 | 归属 |
|------|------|
| 作品怎么组织、改坏了能不能退回去 | **工程与版本**（[project-versioning.md](project-versioning.md)） |
| 图片、视频、音频放哪 | **资产库**（[asset-library.md](asset-library.md)） |
| 写下的东西怎么变成别人能看的站点 | **站点形态与文件组**（[site-model.md](site-model.md)）、**编写与预览**（[authoring.md](authoring.md)）、**发布**（[publication.md](publication.md)） |

成功的衡量标准：

1. 用户能创建工程、放下内容与素材、发布，并在发布后用一个地址看到自己的站点。
2. **发布物是一组文件，全部由该版本的文件组产出**：文本由服务端原样服务或渲染，素材一律取自本工程的公开资产。产物里不存在指向别处的取字节引用。
3. **发布物只从本工程取字节**。每一处取字节的引用都必须落在本文件组的某一条条目上；出现别处的引用，发布被拒绝并指出那一处，而不是发布出去一张裂图。
4. 一个版本一旦保存就**不可变**：它当时引用什么，此后永远引用什么。因此"发布过的页面内容变了"这件事不会发生。
5. 已发布的站点对**未登录的人**可打开；草稿与未发布的版本对除拥有者外的所有人不可见。
6. 未配置发布域时工程、内容与资产照常可用，只有发布不可用；连桶也没配置时，只有工程元数据可写（字节没有地方放）。前端据此不渲染对应入口。

## 概念模型

| 概念 | 含义 | 关键性质 |
|------|------|---------|
| 工程（Project） | 创作单元：元数据 + 一个形态 + 一份草稿 + 若干版本 + 一个资产库 | 有一个拥有者主体；标识由 aladdin 分配且不可猜；形态创建时定下、此后不可改 |
| 文件组（File set） | 工程的内容：一组具名文件，每个条目是一条**文本条目**（字节按内容摘要存放在对象存储）或一条**资产条目** | 路径在工程内唯一，且是公开地址的一部分；**库里只存清单，不存字节** |
| 草稿（Draft） | 工程当前正在编辑的文件组，随时可改 | 不是版本，不参与发布，不保证可退回 |
| 版本（Version） | 文件组的一次**不可变快照** | 保存即冻结；发布只能发布版本，不发布草稿 |
| 资产（Asset） | 工程资产库里的一个媒体文件 | 字节在对象存储；不可变；属于唯一一个工程 |
| 发布（Publication） | 把一个版本冻结成对外可达的产物 | 产物是**一份清单**（路径 → 内容摘要），字节在对象存储；一文件一地址；对外地址稳定；可撤回 |

它们的关系是**单向包含**：工程拥有版本与资产，发布指向版本。**资产不属于版本**——一个版本引用了哪些资产，由该版本文件组里的**资产条目**直接读出，而条目是发布态分派的唯一依据（理由见 [site-model.md](site-model.md)）。

工程有两种形态，创建时定下：`static`（整站文件原样服务，覆盖手写页面与**构建产物**）与 `docs`（一组 markdown 加少量站点文件，发布时渲染成多页）。见 [site-model.md](site-model.md)。

## 状态流转

一个工程对外只有三个状态，而**唯一决定可见性的是工程上那一个发布指针**：它指向哪一份产物清单，地址就返回哪一份；它为空，所有地址都是"不存在"。

```
                       存版本                    发布
  ① 无版本  ────────────────────▶  ② 有版本未发布  ─────▶  ③ 已发布
      ▲                                  ▲                  │
      │ 删掉最后一个版本                    └──── 撤回 ────────┘
      │                                     （指针置空）
      └──────────────────────────────────────┘

  ③ ── 删除工程 ─▶ 终态：工程、版本、资产与地址一起消失
```

**草稿不在这个机器上。** 草稿随时可改，改它不改变任何一个状态，也不改变任何一条地址——它是"当前在编辑什么"，不是"对外是什么"。因此**保存版本与发布是两个各自独立的动作**：存版本不改对外可见的内容，发布不改草稿。

每个动作碰了哪一层，是判定时最要紧的一张表：

| 动作 | 库里的清单 | 桶里的对象 | 对外地址 |
|------|-----------|-----------|---------|
| 改草稿 | 草稿清单换掉 | 新增内容对象；旧的**不删**（可能正被某个版本引用） | 不变 |
| 存版本 | 冻结草稿清单为一个新版本 | **不搬运任何字节** | 不变 |
| 发布 | 写入本次的产物清单 | 媒体上架到公开区；解析产生的文本写成新对象 | 开始可达（**整套一次性生效**） |
| 撤回 | 产物清单留着 | 全部留着（公开区副本不回收） | 立刻不可达，**每一条路径都是** |
| 删版本 | 删掉该版本 | 对象不删（共享，可能仍被别处引用） | **被发布指向的版本不许删** |
| 删资产 | 删掉元数据与私有区对象 | 公开区副本留着 | **被任一版本引用时不许删** |
| 删工程 | 全部删掉 | 私有区可能留下孤儿对象；公开区副本留着 | 不可达 |

两句话读法：**判断"现在对外是什么"，只看指针；判断"改它安不安全"，看有没有版本引用它。**

## 存储分层

**库只回答"有哪些、是什么"，字节一律在对象存储。**

```
关系库（不含任何字节）
  ├─ 工程：名称 · 简介 · 形态 · 【发布指针】   ← 唯一决定对外可见性的东西
  ├─ 草稿清单 / 版本清单 / 产物清单：路径 → 内容摘要 或 资产标识
  └─ 资产元数据：声明类型 · 字节数 · 摘要 · 文件名
        │
        │ 发布：上架，只搬媒体（文本不上架）
        ▼
桶 · 私有区                                    桶 · 公开区
  ├─ galaxy/<工程标识>/text/<内容摘要>            ├─ galaxy/release/<内容摘要>/<类型标识>
  └─ galaxy/<工程标识>/assets/<类别>/<资产标识>    └─ 逐对象公开读，匿名可取
     预览与发布态的服务端从这里读                   浏览器直连，CDN 可以永久缓存
```

三层各管一件事：

| 层 | 存什么 | 键 / 位置 |
|----|-------|----------|
| 关系库 | 工程元数据（名称、简介、形态、发布指针） | 工程行。**没有内容** |
| 关系库 | 草稿的**文件清单**（路径 → 内容摘要或资产标识） | 草稿行，可随时换 |
| 关系库 | 版本的**文件清单** | 版本行，冻结后不可改 |
| 关系库 | 发布的**产物清单** | 发布记录 |
| 关系库 | 资产元数据（声明类型、字节数、摘要、文件名） | 资产行 |
| 桶 · 私有区 | 文本条目的字节 | `galaxy/<工程标识>/text/<内容摘要>` |
| 桶 · 私有区 | 资产的字节 | `galaxy/<工程标识>/assets/<类别>/<资产标识>`，类别取自声明类型那一档 |
| 桶 · 公开区 | 已被发布引用的**媒体** | `galaxy/release/<内容摘要>/<类型标识>`，逐对象公开读 |

**两种前缀形状不同，因为它们是两种边界**：私有区按**归属**切分（`galaxy/<工程标识>/` 之下是这个工程的一切，删工程在存储侧就是一次前缀清理），公开区按**内容**寻址（跨工程共享同一份字节，因此不带任何工程的标识）。

**键上不体现工程形态**：`static` 与 `docs` 的文件在同一个 `text/` 下、形状完全一样——内容寻址的键只回答"这份字节是什么"，不回答"它拿来做什么"。形态住在工程行里，条目是渲染输入还是原样服务的内容住在清单里（见 [site-model.md](site-model.md)）。键的完整规则见 [asset-library.md](asset-library.md)。

**同一份字节在同一个工程内只有一个对象。** 清单里的摘要是这条事实的全部依据：内容没改的文件，在这个工程的草稿、版本与产物之间共享同一个对象；改一个字，只有那一个文件产生新对象。另一个工程里的同一份字节是另一个对象——私有区按工程前缀切开（见上，以及「待定决策」里的跨工程去重）。

**文本不进公开区，媒体才进。** 公开区要能匿名直连，而**内容寻址会抹掉路径**——文档一旦落在 `<桶域>/galaxy/release/<摘要>` 上，它内部那些 `/assets/index.js` 与相对链接就都指不到地方了（见 [site-model.md](site-model.md) 的"取字节"）。所以文本留在私有区，由服务端在它自己的路径上给出。

### 字节怎么进、怎么出

```
写入   改草稿 / 传素材     客户端 ──直传（仅当不存在时写入）──▶ 私有区
       存版本 / 发布       服务端 ──只写清单、切指针──▶ 关系库

读取   编辑 · 预览         服务端 ──读──▶ 私有区 ──▶ 渲染成 HTML 返回
       编辑 · 源码与素材   客户端 ──短时地址直连──▶ 私有区
       发布 · 文本条目     服务端 ──读──▶ 私有区 ──▶ 返回，带 ETag = 内容摘要 · no-cache
       发布 · 资产条目     服务端 ──302──▶ 公开区 ──▶ 浏览器直连，CDN 永久缓存
```

发布态的一次请求就是上面第三条或第四条：先查**发布指针**得到产物清单，再取这个路径的条目；清单里没有它，返回与"未发布"同一个否定结论。**撤回就是让下一次校验得到"不存在"，所以立刻生效。**

**字节不经服务端转发，只有一处例外**：发布态的文本文档由服务端从私有区读出并返回——那一步无法交给客户端直连，理由见上。服务端另外读回字节只有两处，且都是核对而不是转发：写入内容对象时核对摘要、上架到公开区时核对摘要。

## 模块边界

本模块**明确不做**：

| 不做的事 | 理由 |
|---------|------|
| 服务端执行用户代码 | 发布物是静态文档。"用户能在 aladdin 上运行代码"是完全不同的一件事，且它带来的隔离要求比静态渲染高一个量级 |
| 通用 CMS 的建模能力 | 没有分类、字段、关系、模板。用户要结构化数据，自己写在文件组里 |
| 内含构建与打包 | 打包器属于用户的工具链。本模块只接收构建产物，命令行只注入发布根（见 [site-model.md](site-model.md)） |
| 多人实时协作 | 首版一个工程一个拥有者。协作需要显式的成员与并发模型，见 [project-versioning.md](project-versioning.md) 的待定决策 |
| 分支与合并 | 版本的演进是线性的。见同上 |
| 自定义域名、模板市场、SEO 收录 | 都不属于"让用户把一份内容发出去"这件事的最小闭环 |
| 转码与缩略图 | 上传什么就分发什么。转码是一整条独立的处理流水线，见 [asset-library.md](asset-library.md) 的待定决策 |

## 归属与权限

### 两把闸门，各管一件事

| 闸门 | 管什么 | 唯一入口 |
|------|--------|---------|
| RBAC 权限码 | 这个主体**有没有资格**创作 | [../../../api/permissions/catalog.yaml](../../../api/permissions/catalog.yaml) |
| 归属 | 这个工程**是不是他的** | 工程记录上的拥有者主体 |

**归属不由 RBAC 表达。** 这一条沿用 [../rbac/role-model.md](../rbac/role-model.md) 已经划走的边界（"只能看到自己创建的订单"属于资源归属）。权限码决定"能不能创作"，归属决定"能创作哪些"。两把闸门都必须过。

**没有以他人工程为目标的接口。** 所有 galaxy 方法的目标工程都必须是**调用者自己的**，不存在"指定别人的工程标识"这个形状。这与档案模块"每个方法只作用于调用者自己"是同一取向（见 [../profile/README.md](../profile/README.md)）。

### 权限码

| 权限码 | 含义 |
|--------|------|
| `galaxy.project.read` | 读取自己的工程、草稿与版本 |
| `galaxy.project.write` | 创建、修改、删除工程，保存版本 |
| `galaxy.project.publish` | 发布与撤回发布 |
| `galaxy.asset.read` | 读取自己的资产列表与地址 |
| `galaxy.asset.write` | 上传与删除资产 |

**`galaxy.project.publish` 单独一码**，因为它是本模块里唯一一个让内容**离开私有边界**的动作。撤回发布也用它——撤回是发布的反向操作，不给它单独一码不会带来任何安全收益，只会让"发布得出去、收不回来"变成一个可以只授一半的组合。

权限码落在新建的内置角色 **`galaxy.author`（创作者）** 上，作用域限于其被授予的作用域。它不是 `viewer` 的扩展：`viewer` 是只读用户，而 galaxy 的"读"受归属约束——给一个没有工程的人 `galaxy.project.read` 不产生任何可见效果。

## 发布即公开（本模块最重要的一条取舍）

**发布态的读取不走 RBAC，也不走鉴权拦截器。** 它是仓库里第一条让未认证的一方读到业务内容的路径。

因此：

- **工程标识必须不可猜。** 它是发布地址的一部分，而"公开匿名"的具体含义是**地址即凭据**：拿到地址的人能看，猜不出地址的人看不到。
- **不存在"列出所有已发布工程"的入口。** 一旦有，不可猜标识就失去意义——那等于把"地址即凭据"降级成"打开首页就能逛"。这条要作为一项可验证的约束守着。
- **发布物内不得承载任何秘密。** 因为公开匿名，且地址可能被转发。这与头像那条"头像不得承载秘密"同源（见 [../profile/avatar-storage.md](../profile/avatar-storage.md)），但更强：头像是发给本人，发布物是发给所有人的。

## 引用完整性的唯一入口

"**这份内容能不能发布**"是一个**判断**，按 [../../../docs/ssot-registry.md](../../ssot-registry.md) 的 SSOT 原则只有一个实现入口，且在**服务端**。规则全集见 [publication.md](publication.md) 与 [site-model.md](site-model.md)。

网页端需要即时提示时，**调用同一个服务端入口**，而不是在前端复写一套引用解析。两端各写一份的表现是"提示说没问题、发布说不行"（或更糟的反过来），而用户无法从任何一个提示里知道哪个是对的。这与"前端不缓存判定结果"是同一条原则的应用。

## 可验证性与长程执行

**部分属于长程任务。** 工程与资产的读写是即时的同步操作；**发布不是**——它要把一批资产搬到公开区，可能很慢、可能中断。发布的阶段划分、进度判据与检查点见 [publication.md](publication.md)。

跨子模块的约束：

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 发布物自洽 | 产物里每一处取字节的引用都落在本文件组的某一条条目上（文本或资产）；不存在指向别处的这类引用（`internal/galaxy` 测试 + 端到端测试） |
| 整套一次性生效 | 发布中途失败时，所有路径（含子路径）读到的仍是上一次的产物（`internal/galaxy` 测试） |
| 只引用本工程资产 | 引用他工程资产、外部地址或 `data:` 的内容一律发布失败，错误信息指出那一处（`internal/galaxy` 测试 + 端到端测试） |
| 版本不可变 | 保存版本后改动草稿，已保存版本读回的内容逐字不变（`internal/galaxy` 测试） |
| 草稿不可发布 | 对没有版本的工程发起发布被拒；改草稿后重新读到的是发布时的产物而不是改后的内容（端到端测试） |
| 归属不可绕过 | 用一个主体创建的工程标识，在另一个主体的凭证下读取、修改与发布一律被拒（端到端测试） |
| 没有以他人工程为目标的形状 | 接口面上不存在"指定拥有者"的方法（`internal/server` 测试：遍历 method descriptor） |
| 发布入口公开 | 未携带任何凭证请求发布地址能取到当前发布产物（端到端测试） |
| 未发布不可达 | 未发布的工程、已撤回的工程，其发布地址返回"不存在"而不是空页（端到端测试） |
| 不可枚举 | 接口面上不存在列出已发布工程的入口（`internal/server` 测试：遍历 method descriptor） |
| 权限码不外泄 | 无 `galaxy.*` 权限时，工程与资产入口不渲染；直接调用被拒（前端测试 + 端到端测试） |
| 未配置时降级正确 | 发布域未配置时工程、内容与资产的读写照常，发布入口不可用；桶未配置时只有工程元数据可写（`internal/config` 与 `internal/galaxy` 测试） |

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 工程的对外名字（可读 slug） | 暂不做，只用不可猜标识（**未定**） | 需引入唯一性与保留字校验；与"不可枚举"这条约束的关系要重新论证 |
| 管理员 / 审计员查看他人工程 | 暂不做。真出现时单独设计并带权限码（**未定**） | 以他人为目标，与档案模块同类问题（见 [../profile/README.md](../profile/README.md) 的待定决策） |
| 发布物上显示拥有者信息 | 暂不做，发布态不带任何主体标识（**未定**） | 引入一条身份暴露面；要重新论证"公开匿名的发布物可以显示谁做的" |
| 资产跨工程复用 | 暂不做，一个资产属于一个工程（**未定**） | 对象键与删除语义都要改；公开区已按内容寻址，复用成本主要在归属与回收 |
| 发布域是否必填 | 未配置则发布不可用（**已定**，见 [publication.md](publication.md)） | 影响配置校验与前端裁剪，不影响工程与资产 |

> spec 是功能行为的唯一信源，代码是实现的唯一信源。

> 功能行为变更 → 先改 spec；实现细节变更 → 只改代码。

> 当单个子模块文件超过 1000 行或出现明显独立的子职责时，继续拆分为独立 spec 文件。
