# galaxy — 创作与发布 SDK

> 用户在**自己的构建与自己的页面里**怎么用平台能力见本篇；用户在**终端里**怎么用见 [cli.md](cli.md)。源侧记号的写法见 [authoring.md](authoring.md)，文件组与站点内地址见 [site-model.md](site-model.md)。

## 背景与目标

今天创作者接入平台只有一条形状：**命令行 + 源侧记号**。

- 引用素材要在源里写 `asset://<资产标识>`（见 [authoring.md](authoring.md)）——**这是 aladdin 自己的方言**，不属于任何一种标准写法；
- 发布链路把原子命令串起来，靠用户自己的 shell（命令行有意不提供组合命令，见 [cli.md](cli.md)）。

两条都要求用户**为了平台而改变自己的内容与工具链**。本子模块补上另一种接入形状：一个**创作与发布 SDK**——用户在自己的构建里、在自己的页面里调用它获得平台能力，**源保持标准**，构建与生产仍在本地完成。

成功的衡量标准：

1. 一个标准工程（源里没有一处 aladdin 写法）能构建、能发布，产物的每一处引用都落在文件组里。
2. 引用了不存在的文件时，**构建**失败并指出是哪一份文件——报出它的是标准工具链自己的解析，不是插件另写的一份扫描器（见下）。
3. **发布阶段平台一个字节都不改写**：产物清单里的文本条目字节与用户构建产出逐字相同。
4. 构建期不联网：构建这一步不发起任何请求，产物与联网时逐字相同。
5. 用户不引入运行期包时，页面里没有一个 aladdin 字节。
6. 引入运行期包时，页面里的 aladdin 代码就是用户构建产出的那份字节，而不是平台注入的。
7. 页面里的脚本只能把字节发到发布域；不透明源下没有任何可用的本地存储。

## 功能行为

### 接入面的分界

仓库里已经有几处说着"SDK"或"接入"的地方，实现前先把它们分清楚，否则一定会混：

| | 是什么 | 不是什么 |
|--|-------|---------|
| [命令行](cli.md) | 人在终端里逐步操作 | **不是可编程的接入面**（有意如此） |
| `asset://` 记号 | 源侧写法，替换在平台侧发生 | 不是接入点 |
| [api-docs](../api-docs/README.md) 的待定决策「是否生成客户端 SDK → 暂不做」 | 调 RPC 的**客户端封装** | 与本子模块无关 |
| **本子模块** | 用户**构建期与运行期**到平台的两条接入面 | 不改用户源、不引入方言、不接管他的构建、不往产物里注入字节 |

**与记号的关系不是替代，是分工。** `asset://` 退到**没有构建步骤可挂**的那条路上：手写 `.html` 直接推、`docs` 槽里的 markdown 与站点文件。记号不被删掉，见下"`docs` 槽保留记号"。

### 三条红线

这三条是本子模块能否成立的分界线，实现时一条都不许让。

**一、构建期不联网。**

插件是**纯本地的变换**：不取发布根、不上传素材、不问校验结论。网络只发生在**使用侧**——把素材送进资产库、推送草稿、存版本、发布，以及页面在访客浏览器里取内容。

理由是构建不该绑定目标环境：一次构建一旦要连服务端，构建环境里就得有凭证，"这份产物是给哪个部署的"变成一个由构建时的网络决定的隐式事实。今天命令行把发布根交给构建命令，那是**人在终端里做的一次决定**；构建脚本里的插件没有这个位置。

**二、平台一个字节都不改写用户的产物，全部改写发生在构建期。**

`site` 槽的产物与用户构建产出逐字相同，这条不变量原样成立（见 [publication.md](publication.md)）。SDK 替掉的是"平台不做构建"这个**前提**，不是绕过它：改写发生在用户的构建里、由他自己选的插件完成、产物是他自己产出的，**平台从头到尾没碰过他的字节**，只负责审与发。

推论：发布阶段**一条改写都不许有**。任何"到发布时再认领 / 再解析"的方案都撞在这条上，不采纳。

**三、判定只有一处入口，插件不是判定方。**

"这份内容能不能发布"的判定入口只有服务端一处（见 [README.md](README.md) 的"引用完整性的唯一入口"）。因此：

- **插件是产出方，不是判定方。** 它把一棵标准源变成"产物 + 文件组"，而它**不复制**服务端那套规则（资产归属、文档间链接、体积与文件数上限、有没有没解开的记号……）。
- **"构建期提前报出坏引用"靠的是标准工具链自己的解析。** 源写的是标准写法，因此构建器解析 `import`、HTML 的 `src`、CSS 的 `url()` 时，目标不存在本来就是一次构建失败。**插件不为此另写一份引用扫描器**——那份扫描器就是同一个判断的第二份实现，表现是"插件说没问题、发布说不行"，而用户无法从任何一句话里知道该信哪个。
- **插件报"没问题"不构成可以发布的结论。** 界面上的即时提示已经是同一个服务端入口的另一次调用（见 [authoring.md](authoring.md)），SDK 不新增第三条。

### 三个面

| 面 | 在哪跑 | 联网 | 职责 |
|----|-------|------|------|
| **构建期插件** | 用户的构建里 | 不 | 标准写法 → 文件组条目与站点内地址；把发布根交给构建器 |
| **调用面** | 用户的构建脚本里 | 是 | 原子操作的薄封装：素材入库、存草稿、存版本、发布 |
| **运行期包** | 页面在访客浏览器里 | 是 | 取凭证、取内容、与宿主通信；受保护内容留实现位 |

**三个面是一个包、三个入口**（见"待定决策"与下节"包的分发与版本"）；分开的是职责，不是分发单元。

#### 构建期插件

**源保持标准，用户不必学任何 aladdin 方言。** `import logo from './logo.png'`、`<img src="./logo.png">`、内联 CSS 里的 `url(./logo.png)` 原样写；插件在构建期把它们解析成**文件组里的某一条条目**与**该条目在站点内的地址**。

**发布根由调用方传入，插件不去取。** 发布根只有一处派生入口（见 [site-model.md](site-model.md)），命令行不自己拼这个地址（见 [cli.md](cli.md) 的 `project base`），插件同样不拼——它只收下一个**已经拿到**的值，再交给构建器。取那个值是一次独立于构建的动作（调用面可以做，流水线里的一步也可以做）；**插件不发起这个请求**，否则构建就绑定了目标环境。

**插件不注入任何平台的字节。** 它只把引用改写成站点内地址：不改用户内容的形状、不加脚本、不加样式、不写注释。

**产物归属：产物由用户的构建产出，全部改写发生在构建期。** 这是红线二的落点。

#### 调用面

把命令行那些**原子操作**包成可调用面：素材入库、存草稿、存版本、发布。

**它不替用户决定发的是哪一版。** 版本模型是用户可见的：一次发布发的是**某一版**，不是"文件现在的样子"。收成一条"一路走到底"的调用会让"我这次发的是哪一版"变成一个只有读那个封装的实现才能回答的问题——与 [cli.md](cli.md) 那条"只有原子命令"同一条理由，且它把这条理由从命令搬到了一个更难被看见的地方。

**这不与命令行那条边界冲突。** 那条约束的是 **aladdin 的命令**，不是用户在**自己的脚本**里组合它们（[cli.md](cli.md) 里这条边界的理由本身就把 shell 的 `&&` 当作正当出路）。调用面就是"用户自己的脚本"那一侧的语言版本。

#### 运行期包

它在页面里跑，因此能做的事恰好是**壳读不到的那一半**：壳在主站那个源上，跨源读不到 iframe 内的点击与页面细节；运行期包就在页面内。两者互补，**不合并成一个入口**。

**它不往页面里注入任何东西——它本身就是用户产出的字节之一。** 用户不引入它时，页面里没有一个 aladdin 字节；引入时，页面里的 aladdin 代码就是用户构建产出的那一份。这一条是本子模块成立与否的分界线（见 [authoring.md](authoring.md)："预览里不在用户页面上叠加任何 aladdin 编写的脚本或样式"）。

### 包的分发与版本

**一个包，发到公共 npm 源，包名 `@poetlife/aladdin-sdk`，三个面各是一个入口。**

**升级走 npm，SDK 自己不做自更新。** 命令行需要一条自更新路径，理由是它是**装在别人机器上的二进制**——没有人能替使用者把那个文件换掉（见 [cli.md](cli.md) 的升级一节）。SDK 是一份 JS：npm 自己的安装、升级与 lockfile 就是它的分发形态，包里再长一条自更新路径，等于给同一件事配第二套实现。

**版本只有一个来源：发布 tag。** 包内那份 proto 派生物与包来自同一个 tag，因此"SDK 的版本"与"它对话的服务端版本"是同一个数——不维护第二张兼容矩阵，也不允许包里的版本号与 tag 各说各的。发布这一步因此要求 **HEAD 就在 tag 上**：包里的字节与那个 tag 逐字一致，这个号才不是一句空话。仓库里那个值只是占位，发布不会改它（见 [release.md](../../release.md)）。

**包里只有两类字节**：构建产物与它的类型声明、以及源码（使用者从声明跳进实现时要有东西可跳）。**包里没有一处是为使用者页面准备的脚本或样式**——页面里出现的 aladdin 字节，只可能是他自己打进产物的运行期包。

**发布是本地的一步，不进流水线**：一条 `make sdk-publish`，凭证就是发版人本机已有的 npm 登录态——流水线那边为了少敲一条命令，要在仓库里放一份发布凭证。代价要写明：**本地发布没有 provenance**（它需要 CI 的 OIDC），包页面上唯一的来源线索是 `repository` 字段。要不要为它把发布搬回流水线，是一个可以单独再定的取舍。

### 素材：入库是显式动作，引用走 SDK

**把一份素材送进资产库是用户的显式动作**（走命令行、网页端或调用面，见 [asset-library.md](asset-library.md)）；**SDK 不在构建里替用户上传**。

理由是红线一的直接推论：构建一旦联网就绑定目标环境、构建环境里就要有凭证；而"我这一版引用了哪些素材"不该由一个隐式的副作用决定。

**在项目里引用素材走 SDK。** 插件把标准写法解析成**该素材在文件组里的资产条目**与**它在站点内的地址**；素材仍然是一条资产条目，取字节的方式与今天完全相同（发布态重定向到公开区、预览态用短时地址，见 [site-model.md](site-model.md)）——SDK 不新增一种条目、也不新增一条取字节的路。

**插件靠一份本地资产记录认出"这份字节是哪个资产"，因此这一步不联网。**

- **按内容摘要记，不按本地路径记。** 与平台的内容寻址同源：同一份字节在平台上就是同一个资产，而"这个文件叫什么"不是——移动或改名一份素材不会让记录失效，按路径记则必然失效。
- **由入库那次动作写下**（调用面在素材入库之后写，见"三个面"），**由构建期插件读出**。这是记录存在的全部理由：构建期不联网，就不能去问服务端"这一份是哪个资产"。
- **缺项时插件不下结论。** 记录里没有的那一份，插件认不出来，于是**原样交给构建器**——它会被照常打包进产物（或由构建器自己的解析失败），而"这一处引用不落在文件组上"由服务端在发布时如实拒绝并指出那一处（见红线三）。
- **记录是每个工程一份的**：资产属于唯一一个工程，因此一份记录只对它所属的那个工程有意义。**记录里的资产标识由某一个部署分配**，换一个部署就是另一批——因此"要不要把它提交进版本库"由用户的部署形态决定，SDK 不替他决定。
- **记录本身不是内容。** 它可能就落在被送上去的那个目录里（把工程的根目录整个送上去时就会这样），但它不随内容进文件组、也不进产物——它是 SDK 的账本，发布出去既没有用处，也把"这一版引用了哪些素材"摊在了公开地址上。

### 运行期：凭证从哪来，内容怎么取

运行期包要取到内容，就需要凭证。**凭证有两条来源，走的是同一条链：**

| 场景 | 凭证来源 |
|------|---------|
| 页面在访客浏览器里 | 向**宿主**（主站壳、工作台）索取，走接入桥的宿主 → 页面方向 |
| 本地调试 | 经**命令行**取一份 |

**它不是主站的会话凭证。** 这一页跑在不透明源的沙箱里、页面里是用户自己的脚本；把主站会话交进去，等于让用户的内容可以替这位访客调主站的接口——那正是沙箱属性要挡住的事。因此这条通道只下发一份**只够取这一份内容**的窄凭证，而它的签发是内容保密那一条（#87）的服务端一半。在那一半落地之前，宿主**如实回一条"拿不到"**：**回一条明确的否定，而不是不回**——不回的那一侧只表现为页面等一次超时，而与"网络慢"分不开。

**取不到凭证不是致命的。** 发布物里的普通素材本来就公开可取，凭证是给受保护那一类用的；因此"这次没拿到"是一个可以被调用方接住的结果，不是一次异常。

**取内容必须发到发布域。** 发布物的内容安全策略把脚本能发往的地方限在发布域上（策略那张表见 [publication.md](publication.md) 的"扫描不是边界，响应头才是"），因此接收端只能落在发布域上，好处是不必再开第二份来源白名单。向宿主索取凭证走的是浏览器消息通道，**不受这条约束**；拿到凭证之后取内容那一次请求才受它约束。

**页面里没有客户端身份。** 不透明源的沙箱 iframe 用不了 cookie、localStorage 与 indexedDB——那正是沙箱属性要的效果。因此运行期包做不了客户端会话拼接、做不了稳定访客标识：它手里除了凭证什么都没有。**不要为了统计去拆沙箱属性**；想按别的信号在服务端归并是另一件事，属隐私决策，要单独定。

### 壳通信：复用同一份信封

页面 ↔ 宿主那条通道**已经存在**：`docs` 槽渲染出的每一页都带一段平台自己的接入脚本，信封是 `channel` / `version` / `type` / `payload` 四项（见 [site-model.md](site-model.md) 的"平台接入桥"）。

运行期包用的就是这条通道，因此三条约束：

- **用同一份信封。** 宿主侧必须复用同一个信封与同一套校验，**不得出现第二套页面 ↔ 宿主协议**。两个方向、两种槽、平台渲染的页与用户自己的页，全都认这四项。
- **加的是消息类型，不是版本。** 信封本来就是对称的，v1 里宿主 → 页面那一半是空的；因此支持运行期包是**增一种类型**，不是开 v2。本子模块用到的两种（要凭证、答复）就是这么加上去的。
- **`site` 槽没有平台渲染的页**，因此那边的接入脚本来自用户自己打进产物的运行期包，而不是平台注入——这正是"不引入运行期包时页面里零 aladdin 字节"的由来。
- **宿主侧只有一处**：主站壳与工作台共用的那一帧，两个方向都在那里收与发。页面侧因此有两份实现（服务端渲染进 `docs` 页的常量脚本、用户打进 `site` 产物的运行期包），**形状只有一份**，取值由运行期包那边的测试读服务端与宿主两侧的源码钉住。

### 受保护内容：只留实现位

运行期包要取的"内容"分两类：发布物里的**普通素材**，与**受保护内容**。两者**同一套包、同一套凭证链**，只是受保护的那一类多经过一次按主体的判定。

那次判定的**服务端一半不在本子模块**（见 #87）。本子模块只做客户端这一半：取密钥信封、解密、水印；接口位置先留出来，不让它挡住其余部分落地。

**诚实的上界：浏览器里"防盗版"的天花板是"平台不把字节交出去"。** 只要字节与密钥都到了访问者手里，剩下的都是抬逆向成本。

**这也正是现在做 SDK 最强的理由**：SDK 把"平台能力"与"用户内容"的接触面收敛到**接口**上。今天这个接口只解析素材；哪天要加受保护素材，是**换一个实现**，而不是回头去改用户的源。等到那时才做，用户已经被迫在源里写过平台方言，再想抽干净就是一次迁移。

### 数据上报：本子模块只留位

壳体统计（见 #36）与页面内上报**互补而不重复**：壳读不到 iframe 内的点击与页面细节，运行期包就在页面内。上报若要成立，实现时按三条约束设计：只能发到发布域（见上）；天然无身份（见上）；接收端是**发布域上的一个新入口**，不是壳层上报那一个。

**上报入口单独立项**，本子模块只登记它在这里有一个位置。

### `docs` 槽保留记号

`asset://` 不是被删掉，是**退到没有构建步骤可挂**的那条路：手写 `.html` 直接推、`docs` 槽里的 markdown 与站点文件。

**`docs` 槽先保留记号，且这个结论不随本子模块一起改。** 那边渲染在服务端、按版本钉住（见 [site-model.md](site-model.md)）；要让那条路上的用户也不用记号，就得把渲染搬进他的构建——等于把渲染规则的**所有权**交出去，与"渲染规则按版本钉住"直接冲突。它是一个独立决策，见 [authoring.md](authoring.md) 的待定决策。

## 边界与约束

- **不删掉记号。** `asset://` 原样保留，退到没有构建步骤的那条路。
- **不往用户的产物里注入任何字节。** 不上报脚本、不加样式、不改内容形状。运行期包是**用户自愿打进产物的字节**。
- **不接管用户的构建。** 不解析构建配置、不替用户选打包器、不提供"一路走完"的调用。
- **不做判定。** 插件报"没问题"不是可以发布的结论；唯一入口在服务端。
- **不改写发布阶段的产物。** 一条都不许（红线二）。
- **不做全站产品分析。** #23 / #37 的边界照旧。
- **不解决运行期内容保护的服务端一半。** 见 #87。
- **不做客户端会话与访客指纹。** 见上"页面里没有客户端身份"。
- **不做自更新。** 升级走 npm 自己的机制（见"包的分发与版本"）。

## 可验证性与长程执行

**非长程任务。** 三个面都是即时动作；没有一个跨越"提交 — 等待 — 生效"。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 源里零方言 | 一个标准工程的源里没有一处 aladdin 写法，仍能构建出产物、每一处引用都落在文件组里、发布成功（示例工程 + 端到端测试） |
| 构建期报出坏引用 | 引用一份不存在的文件时构建失败，并指出是哪一份文件（示例工程测试） |
| 构建期不联网 | 发布根与素材记录都已在手时，**构建这一步**不发起任何请求；断网构建出的产物与联网时逐字相同（示例工程测试） |
| 发布阶段零改写 | 产物清单里的文本条目字节与用户构建产出逐字相同（端到端测试） |
| 不引入运行期包时零注入 | 产物里没有一处 aladdin 写入的字节（端到端测试 + 前端测试） |
| 引入时字节来自用户 | 页面里的 aladdin 代码就是用户构建产出的那一份，不是平台注入的（示例工程 + 端到端测试） |
| 信封只有一份 | 宿主侧只接受 `channel` / `version` / `type` / `payload` 四项，忽略认不出的版本与类型，且只处理来自自己那一帧的消息（前端测试） |
| 取内容只能发到发布域 | 页面里指向别处的 fetch / XHR / WebSocket 被内容安全策略挡下（部署后冒烟） |
| 不透明源下无可用存储 | 页面里读不到 cookie、localStorage 与 indexedDB（示例工程 + 端到端测试） |
| 素材入库只经显式动作 | 构建过程不产生任何资产、不上传任何字节（示例工程测试） |
| 发出去的包能被外部消费者用 | 四个入口的产物与类型声明、许可证与说明都在包里，且入口按 `exports` 可解析（打包检查：`make sdk-check-package`） |
| 包里的版本与发布它的那次 tag 是同一个数 | 发布这一步要求 HEAD 就在 tag 上，号取自那个 tag（`make sdk-publish`）；包内容与 tag 因此逐字一致。本地发布没有 provenance，来源线索只有 `repository` 字段 |
| 直传的签名被真实桶接受 | 部署后一次真实直传冒烟：签发 → 直接传到桶 → 提交核对成功（部署后冒烟，见 [deploy.md](../../deploy.md)） |

## 待定决策

| 决策 | 结论 | 替换影响范围 |
|------|---------|-------------|
| 包的分发形态 | **公共 npm 源，包名 `@poetlife/aladdin-sdk`；版本取自发布 tag；发布在本地一步（`make sdk-publish`）；不做自更新**（**已定**，见上"包的分发与版本"） | 影响安装与升级路径 |
| 与 skill 目录共用同一条接入面 | **各走各的**（**已定**）：两边的凭证来源与形态不同（调用者已有的凭证 vs 宿主下发的窄凭证），而该共用的已经共用了——协议只有 Connect 一条，proto 由 `make gen` 派生 | 合并要重新论证：那等于让 agent 背一条浏览器通道，或让本包长出一个命令行形状的面 |
| 接入桥与直传的 SSOT 收敛 | **一份形状、按载体各一份，不得出现第四种**（**已定**，登记在 [ssot-registry.md](../../ssot-registry.md)）：重复的是常量与类型而不是逻辑，而形状还**跨语言**（另一头是服务端渲染进 `docs` 页的 Go 常量脚本），"字面上一份实现"不可达 | 改成 web 依赖本包会动 web 的构建顺序，并让主站自己的需求开始塑造这个对外包的公开面 |
| 手写 COS 签名的验证 | **补一次部署后的真桶直传冒烟**（**已定**）：与官方实现逐字对齐的那组测试只证明"与对照物一致"，不证明桶接受 | 冒烟需要真实凭证与网络，因此不进常规门禁（与"取内容只能发到发布域"同档） |
| 上报入口 | 单独立项，本子模块只留位（**未定**） | 发布域上多一个匿名入口，限频、字段白名单与无 PII 要一起定 |
| 受保护资产的实现位 | 以 #87 与"发布域要不要有一个主体"的结论为前提（**未定**） | 密钥签发要做一次按主体的判定，而发布域今天是匿名的 |
| `docs` 槽的记号是否随本子模块一起退场 | **保留**（见上，独立决策） | 要让那条路上的用户也不用记号，就得把渲染搬进用户的构建 |
| 三个面是一个包还是三个包 | **一个包，三个入口**（**已定**） | 只影响分发单元，不影响任何一条行为约定 |
| 构建期靠什么认出一份素材是哪个资产 | **一份本地资产记录，按内容摘要作键**（**已定**，见上"素材"） | 改成联网问服务端就要放弃红线一 |
