# galaxy — 站点水印（明水印与盲水印）

> 本文件只回答一件事：**发布出来的站点上，怎么标记「这一份是给谁看的」。** 发布链路、主站壳与隔离见 [publication.md](publication.md)，产物里为什么一个字节都不许加见 [site-model.md](site-model.md)。

## 背景与目标

#87 讨论过的是**保密**：让拿到地址、凭证、桶与日志的人都得不到明文，结论是不做——aladdin 交付的是站点而不是图片流，风险主要不在「传输被截」，在「看的人把它拍下来、存下来、发出去」，而加密对后者完全无效。

本文件做的是另一半：**溯源**。内容照旧公开可取，但**每一份副本上带着「这是谁的」这条信息**，于是「拿得到」不再等于「跑得掉」。它与保密互补而不替代：保密管「拿不到」，这里管「拿得到但跑不掉」。

成功的衡量标准：

1. 一个访客通过分享地址打开已发布的站点时，页面上带着**可见的**标识（明水印）与**不可见的**标识（盲水印），两者都指向**这一次访问**。
2. 一份从屏幕上截下来的图，能在命令行里**解出**那枚水印码，并据此查到是哪个主体（或哪一次匿名会话）、什么时候、来自哪里。
3. `site` 槽的产物**逐字不变**：水印不是注入到用户内容里的字节。
4. 水印不挡交互、不进无障碍树、不改变页面的任何一次判定——它只看得见。
5. 没有任何开关能让一个已发布的站点少掉水印：**发布启用即水印启用**。

## 功能行为

### 两个能力，不是同一个功能的两档

| | 明水印 | 盲水印 |
|-|-------|-------|
| 目的 | **威慑**：让看到的人（与截图的人）当场知道这一份带标识 | **取证**：拿到一份泄露的截图或另存图，能反查是哪一次访问 |
| 被裁剪、缩放后 | 失效——裁掉就没了 | 应当仍可提取，但强度有限（见"验收标准"） |
| 对阅读体验 | 有影响，因此必须克制 | 无感 |
| 实现位置 | 画在壳上的一层文字 | 叠在壳上的一层近乎不可见的平铺图案 |
| 能不能分开做 | 能 | 能 |

**它们被写进同一篇是因为铺在同一条链路上，而不是因为该合成一个能力。** 两者的验收标准完全不同：明水印判「看不看得见且不碍事」，盲水印判「截图里解不解得出、会不会误报」。

### 铺在哪：铺在壳上，不进内容

发布物跑在一个**跨源沙箱 iframe** 里（`allow-scripts`，不含 `allow-same-origin`，见 [publication.md](publication.md) 的"主站壳"），页面里是用户自己的脚本。因此水印有两个可能的落点，本文件选定**壳**：

| 落点 | 边界 | 代价 |
|------|------|------|
| **壳上（选定）** | 水印是平台自己页面上的一层，**一个字节都不进用户内容**；与"`site` 槽产物逐字相同"这条硬约束不冲突 | 水印只跟着主站这条路走：**直接打开发布域时没有水印**；按 iframe 节点截图（而不是截屏）也取不到壳上这一层 |
| 注入沙箱页内 | 贴得紧，随页面一起被截 | 等于往用户内容里插东西——`site` 槽的"逐字相同"当场作废；`docs` 槽那侧还要把渲染规则版本再加一次 |

**选壳还消掉了两个具体的绕开手法：**

- **页面自己的层叠绕不开它。** iframe 在宿主文档里只是一个元素，页面里的 `z-index` 再高也只在自己那个不透明源里生效，盖不到宿主上的另一层。
- **全屏也绕不开它。** 那一帧的沙箱属性里没有 `allowfullscreen`，内容因此请求不了全屏；页面无法把宿主的水印挤出视口。

**"直接打开发布域时没有水印"是如实接受的一档，不是遗漏。** 发布域的地址本来就只发给高级用户（见 [publication.md](publication.md)："不影响直接打开"），而水印要的是"给看的人看"，那条路上没有壳、也就没有"这一份是给谁的"这个问题——它是同一个地址发给所有人。要连那一路也标，等于回到"往用户内容里注入"，与上表的取舍冲突。

**明水印的画法必须克制。** 它盖在正文上，因此：

- 不接指针（`pointer-events: none` 一类），页面照常可点、可滚、可选中；
- 不进无障碍树（对读屏隐藏），它不是内容；
- 颜色与不透明度取在"看得见、但不压过正文"的那一档，斜向排布、疏排，避免形成一条实线；
- 它不参与加载态与失败态的呈现：水印在内容到达之前就已经在，**加载遮罩压在它上面**。两者同时可见时该被看见的是遮罩——水印是常驻的一层，而遮罩要回答"这儿为什么什么都没有"，让斜字穿过那颗居中的转圈只会让两边都读不清。

**明水印显示什么：平台标记 + 日期 + 水印码的前几位。** 它**不显示主体标识、昵称与来源地址**。理由两条：发布态本身是公开匿名的（见 [README.md](README.md) 的"发布即公开"），把访客身份印在一张会被转发的图上，等于把"谁看过这一页"交给任何拿到图的人；而这与溯源无关——码就够了。明水印要的是"这一份带我的一次标识"，不是"这一份带我的名字"。

### 标记什么身份：码是引用，不是身份明文

**水印里编进去的是一枚码，不是身份本身。** 码与"这是谁"的对应关系存在库里，由服务端在水印签发的那一刻登记。这一层间接是整套设计的关键：

- **像素里只有一枚随机码**，即使被人解出来也读不出隐私；而它必须能对回一条登记才构成溯源。
- **登记表能回答的问题比像素多**：主体、来源地址、浏览器标识摘要、时间、工程与槽。
- **身份优先取主体。** 访客带着会话访问分享地址时，登记的主体就是**这位已登录的访客**——这是"这一份是给谁的"最强的一种回答。
- **没有会话时退到匿名那一档**：登记来源地址与浏览器标识摘要。这份记录**仍然**是同一件事的一次留痕（"某个来源、某台浏览器、在某个时间打开了这一页"），只是它指向的是"这一次匿名访问"而不是一个人。

**"把 IP 与浏览器标识编码进去"落成的是登记表那一行，不是像素里的比特。** 直接把这些值铺进图案会同时坏掉三件事：位数不够（一帧装不下一个地址）、图案变成可公开读出的个人信息（任何拿到图的人都能解出自己的 IP）、以及无法回收（像素里写死的东西改不了、删不掉）。写成码之后，回收与保留期都是登记表的事。

**登记是可读的、有边界的：**

| 问题 | 答复 |
|------|------|
| 谁能读 | 只有持有 `galaxy.watermark.read` 的主体。它**不**给创作者：让作者能查出"谁看了我的页面"是一条独立的隐私决策，不随水印一起落地 |
| 保留多久 | 一个固定窗口（常量，不由配置给出），过期即回收；码本身在窗口之后仍可解出，但已对不回人 |
| 记什么 | 主体（匿名时为空）、来源地址（**去掉端口**）、浏览器标识的摘要、时间、工程与内容槽 |

**来源地址不进日志、不进明水印、不进给访客的响应。** 它只在登记表里，且只在一次提取之后被读到——这条与"发布物内不得承载任何秘密"是同一条取向的延伸。

### 一枚码的生命周期

**签发时机只有一个：壳解析分享地址的那一次调用。** 那是访客打开分享地址时唯一一次"平台知道有人来了"的时刻，也是主站与发布域之间唯一的一条公开通道（见 [publication.md](publication.md) 的"主站壳"），因此壳拿到的响应里同时带着水印要用的东西。

**同一访客在窗口内复用同一枚码。** 判据是（工程，槽，主体或来源地址，浏览器标识摘要）：命中一条仍在窗口内的登记就复用它，不新增行。

**来源地址在进判据之前要去掉端口。** 一次请求的远端地址是「主机:端口」，而端口是每条连接临时分配的——把它算进去，同一个人每打开一次页面就是一个新访客，复用当场失效，登记表又变回按页面浏览量增长。端口对「这一次是谁」没有任何信息量，因此它既不进判据、也不进登记。

两个理由：

- **登记表的增长由"访客数 × 工程数"决定，而不是由页面浏览量决定。** 每次打开都新签一枚，等于把一次普通浏览变成一行永久记录。
- **同一份内容在一段时间内带同一枚标识**，提取时不必先知道"是哪一次打开"，这恰恰是它能对抗裁剪与缩放的前提。

**撤回发布不删登记。** 登记回答的是"这一份图是谁看的"，与"现在还能不能打开"是两件事；撤回后那张已经流出去的截图仍然要能被查。删工程时才把它的登记一起删。

### 盲水印怎么进渲染结果

**图案由服务端生成，壳把它当作一层平铺背景叠上去。**

- **算法只有一处实现。** 图案的生成与提取都在服务端那一侧，壳拿到的是一张现成的图。前端不再算一遍——两份实现必然漂移，而漂移的表现是"页面上的图案提取出来是另一个码"，只有在拿到一张真截图时才会发现。
- **不新增一条取字节的地址，也不做变体。** 图案随解析响应一起下发，尺寸在几 KB 以内；**没有"每用户一份产物"**，也就没有缓存变体的爆炸——码是按（访客，工程）复用的，而产物本身一个字节都没变。
- **图案必须是双色的**：深色页面上浅色块可见、浅色页面上深色块可见。只加亮或只加深的那一种，在半数页面上等于不存在。这是"图案要能在任意底色上被解出"的直接要求，不是配色偏好。

**诚实记下这几条上界：**

1. **按 iframe 节点截图取不到它。** 那是浏览器只渲染那一帧的结果，壳上这一层不在其中——这是选"铺在壳上"换来的固定代价（见上）。
2. **直接打开发布域时没有它。** 同上。
3. **几何重采样是一道硬边界，不是渐变。** 提取要求截图仍在**原始像素网格**上：候选缩放档位之外的任何倍率都解不出（实测 1.95 倍与 2.05 倍都失败，只有 2 倍成功），因为错位让取样窗口混进邻格。候选档位因此取成浏览器真实会产生的那几档——系统与浏览器的整数倍缩放（1、2、3）、常见的小数档（0.5、0.75、1.25、1.5、1.75）与缩略图那一档。**不在这张表上的缩放比例解不出**，这一条要说在人前，而不是事后才发现。

   **能不能入表有一条硬判据：一格必须恰好占整数个像素。** 格子是 4 像素，因此候选倍率乘以 4 必须是整数——表里九档都满足（0.75→3、1.25→5、1.75→7、2.5→10），而 **1.1 倍不满足（4×1.1 = 4.4）**。格子周期 4.4 像素意味着格边界按 0→0.4→0.8→0.2 轮转，跑满一帧就漂移二十几个像素，"块内第几格"与它在像素上的位置脱钩，同一相位下的副本互相错位。实测它的相关值封顶在噪声之上一点点，永远过不了前导关；作为对照，表内每一档的相关值都是满的。

   **因此 Chrome 的 110% 页面缩放、4/3 缩放、1.2 / 1.4 / 1.6 / 1.8 这些"一格不落在整数像素上"的比例一律解不出。** 这是这套方案最现实的一条损失，要单独点名而不是笼统说"非标准缩放"：110% 恰恰是很多人日常使用的档位。它由几何决定，调参救不了；若要覆盖它，只能换成一套不依赖整数像素网格的编码，那是另一套方案。
4. **任何旋转都解不出**（1 度即失败）：那需要先知道角度才能配准，而截图不告诉任何人它的角度。
5. **裁到不足一帧多一点就解不出。** 最小可解面积量级是一帧再加一圈余量；一帧刚好的截图不可靠。
6. **重绘解不出。** 重新排版、重新绘制、把它压成一段文字再重排，图案就没了；这一档在业界也一样（见"待定决策"里对云厂商服务端盲水印的取舍）。重度模糊、把页面用半透明蒙层整体压暗也在这一档。
7. **对比度反而不是瓶颈。** 实测把不透明度压到目标值的四分之一、把有损压缩质量压到很低，仍然解得出——卡住的始终是几何配准。这也解释了为什么"把图案再调淡一点"不会让它突然失效，而"把窗口缩放改了 10%"会。

**这几条决定了它的定位：它是取证而不是防复制。** 一段从浏览器里直接截下来的图（保持原始像素网格、不旋转、面积够）解得出来；经过任何图像编辑、缩放、拼接、重绘的副本解不出来。把这一条写在前面，比事后解释"为什么这张图解不出"有用。

### 提取：命令行一处

**提取发生在命令行。** 一条命令读一张图，先解出码，再按码查登记并打印那一行。

**解不出就是解不出，不猜。** 与"这一页不存在"同一条取向：不是本平台的图、裁得太小、变换太强，三者得到**同一个否定结论**，不返回一个"最像的码"。这条不是洁癖：误报在溯源场景里比"查不到"更糟——它会把一次泄露指向一个没看过这份内容的人。

### 明水印与盲水印对页面的影响

- **它们都不改变任何一次判定。** 发布态仍然不经过 RBAC、仍然公开匿名、否定结论仍然是那一个（见 [publication.md](publication.md)）；水印只发生在"已经确定这一页能看"之后。
- **它们都不改变内容安全策略。** 图案是服务端随响应下发的数据，作为内联背景使用，不新增任何来源；明水印是宿主自己的文字。
- **预览不打水印。** 预览是作者看自己的草稿（见 [authoring.md](authoring.md)），那里没有"这一份是给谁看的"这个问题；给预览也盖一层只会让作者看不清自己的排版。

## 边界与约束

- **不改画布导出接口，也不做每用户一份渲染结果。** 前者实测一次合成器截图即可绕过，代价是无障碍、用户另存、调试与自动化测试；后者让缓存变体数等于用户数。
- **不把水印当成内容保密的替代。** 它挡不住"拿到原始字节"，只回答"这份副本是谁的"。
- **不往用户内容里加一个字节。** `site` 槽的产物逐字相同这条不变量原样成立；`docs` 槽的渲染规则版本也不因水印而变（见 [site-model.md](site-model.md)）。
- **不做服务端图片水印。** 那要改写字节、引入变体与一条图片处理链路，与"不代理字节、不做转码"的既定取舍冲突。
- **没有关掉水印的配置。** 配置不得成为判定或能力的来源（见 [AGENTS.md](../../../AGENTS.md) 的权限硬性约定第 7 条）；一个"跳过水印"的开关一旦存在就一定会被用在生产环境。
- **登记表不含内容本身**，只有码、身份维度、时间与工程归属。

## 可验证性与长程执行

**非长程任务。** 签发、生成与登记都是即时的同步动作。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 壳上有明水印与盲水印 | 打开分享地址后，壳的页面上同时存在那一层文字与那一层平铺图案；两者都在 iframe 之外（前端测试） |
| 水印不挡交互、不进无障碍树 | 水印层不接指针、对读屏隐藏；点、滚、选中照常落到内容上（前端测试） |
| 直接打开发布域没有水印 | 不经过主站壳取到的页面里没有任何水印字节（端到端测试 + 代码审查） |
| `site` 槽产物逐字不变 | 同一版本发布前后的产物逐字相同；产物里不出现水印码、图案与明水印文字（`internal/galaxy` 测试） |
| 渲染规则版本不变 | `docs` 槽的渲染规则版本不因水印而加一（`internal/galaxy` 测试） |
| 已登录访客登记到主体 | 带会话打开分享地址后，按码查到的那一行带主体标识（`internal/galaxy` 测试 + 端到端测试） |
| 匿名访客登记到来源与浏览器 | 不带会话时那一行的主体为空、来源地址与浏览器标识摘要有值（`internal/galaxy` 测试） |
| 窗口内复用同一枚码 | 同一（工程，槽，访客）在窗口内连续两次解析得到同一个码、且只新增一行（`internal/galaxy` 测试） |
| 端口不算身份 | 同一来源、换一个临时端口的两次访问复用同一枚码，且登记里存的是去掉端口的来源（`internal/galaxy` 测试） |
| 不同工程互不共用 | 同一访客打开两个工程，得到两枚不同的码（`internal/galaxy` 测试） |
| 图案是双色的 | 同一枚码的图案里同时有变亮的格与变暗的格（`internal/watermark` 测试） |
| 无水印图不误报 | 纯白、渐变、随机噪点三张没有水印的图分别提取，结论都是"查不到"（`internal/watermark` 测试） |
| 原尺寸截图可解 | 壳上同款页面的一次原尺寸截屏解出同一枚码（`internal/watermark` 测试） |
| 下发的那张图案解得回来 | 从服务端下发的那份图案铺出的截图里解出的码，与登记里的码是同一枚（端到端测试） |
| 带偏移的裁剪可解 | 从任意非零偏移裁出的、面积不小于下限的截图解出同一枚码（`internal/watermark` 测试） |
| 缩放后仍可解 | 候选档位里的每一个缩放比例（1、2、3 与 1.5 / 1.75 / 1.25 / 0.5 / 0.75）都解出同一枚码（`internal/watermark` 测试） |
| 档位之外即否定 | 候选表之外的比例（1.1 倍、1.33 倍、2.05 倍）与任何角度旋转都返回"查不到"，而不是一个相近的码（`internal/watermark` 测试） |
| 重编码后仍可解 | 以有损压缩重编码一次后解出同一枚码（`internal/watermark` 测试） |
| 裁剪不足即否定 | 裁到不足下限时返回"查不到"，而不是一个相近的码（`internal/watermark` 测试） |
| 对比度不是瓶颈 | 把图案的不透明度压到目标值的四分之一、并用最低一档的有损压缩重编码，仍解得出（`internal/watermark` 测试） |
| 查登记要权限码 | 无 `galaxy.watermark.read` 时查询被拒；创作者的权限集合里没有它（`internal/server` 测试 + `internal/rbac` 目录测试） |
| 过期即查不到 | 超出保留窗口的登记查不到（`internal/galaxy` 测试） |
| 撤回不删登记 | 撤回发布后同一枚码仍能查到那一行（`internal/galaxy` 测试） |
| 明水印不含身份明文 | 壳上那一层文字里不出现主体标识、昵称与来源地址（前端测试） |

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 由云厂商的图片处理做服务端盲水印（按桶或按段做变体） | 暂不做（**未定**） | 要引入一条图片处理链路与变体管理，与"不做转码、不代理字节"冲突；但它是唯一能对抗重绘的一档 |
| 创作者能看到自己作品的访问溯源 | 暂不做，只有 `galaxy.watermark.read` 能查（**未定**） | 那是一条按作品的访问统计 + 个人信息，要单独定字段与保留期 |
| 明水印显示主体昵称 | 暂不做，只显示平台标记、日期与码的前几位（**未定**） | 威慑更强，代价是把访客身份交给任何拿到图的人 |
| 直接把 IP / 浏览器标识铺进图案 | 不做（**已定**） | 位数不够、像素里变成可公开读出的个人信息、且无法回收；见"标记什么身份" |
| 水印开关（按工程关闭） | 不做（**已定**） | 开关一定会被用在生产环境；与"配置不得成为能力来源"冲突 |
| 发布域直连那条路也打水印 | 暂不做（**未定**） | 要往用户内容里注入，与 `site` 槽逐字相同直接冲突 |
