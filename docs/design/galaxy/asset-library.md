# galaxy — 资产库

## 背景与目标

一个网页要用的图片、视频、音频是几百 KB 到几十 MB 的**二进制**。把它放进关系库会重演头像那两条后果：读取相关行时带上大字段（而库被判定路径读），以及库快照被二进制支配导致恢复变慢（见 [../profile/avatar-storage.md](../profile/avatar-storage.md)）。

因此字节在对象存储，库内只留元数据。

但资产与头像有三处根本区别，本子模块的规则几乎都由它们推出：

| | 头像 | 资产 |
|--|------|------|
| 种类 | 只有图片 | 图片、视频、音频、字体，体积差两个数量级 |
| 生命周期 | 覆盖写，一个主体一个对象 | 不可变，一个工程多个对象 |
| 去向 | 只给本人看 | **会被发布到公开区给所有人看** |

成功的衡量标准：

1. 用户能上传素材、看到自己的素材清单、在文件组里引用它们。
2. 素材能被管理：加展示标题、标签与备注，按标签筛选，且随时可改；改它们**不影响已发布的页面**（见"可编辑元数据"）。
3. 上传的字节**直接进入对象存储**，服务端在签发与提交两步参与、不接触字节（见 [../objectstore/README.md](../objectstore/README.md)）。
4. 上传方声明的**媒体类型必须在白名单内**，且它决定此后下发时回给浏览器的内容类型；服务端对字节本身不做嗅探——这是直传的已知代价，白名单里因此不含任何可执行类型。
5. 每一次上传的键由服务端分配且不复用，因此**一个资产一旦上传，它的字节不再变化**——引用它的版本永远画得出同一张图。
6. 直传地址只对一个键、只允许写、短时有效。
7. 未配置对象存储时，工程与版本照常可用，只有资产与发布不可用。

## 功能行为

### 与工程附件的边界

工程里还有一类**附件**：二进制、zip 包、导出文件（见 [attachments.md](attachments.md)）。两者**并列而不互相转换**：

| | 资产 | 附件 |
|--|------|------|
| 用途 | 被网页引用、由浏览器渲染 | 给工程成员**下载** |
| 类型 | 严格白名单 | **不限**（按文件名记录） |
| 下发 | 以声明的类型、可进公开区 | **一律强制下载**，永不进公开区 |
| 可见 | 发布后公开 | **仅工程成员** |

因此**资产的白名单不因附件的存在而放松**。白名单成立的理由是"公开区上的对象永远以一个无害类型下发"，而附件不给浏览器渲染机会，它靠的是另一条性质（响应头由签发策略固定）。把 zip 当资产传会同时破坏两边：白名单收紧的依据会被"什么都能传"取消掉，而附件那条"强制下载"的保证对资产不成立——资产是给浏览器渲染的。

### 资产属于工程

一个资产属于**唯一一个**工程。它的可读范围与工程一致：只有拥有者能列出、能取得地址。

**不做跨工程复用**（见"待定决策"）。理由是归属与删除语义：一个资产若被多个工程引用，"哪个工程有资格删它"就没有答案，而本模块的另一条规则（被引用的资产不可删，见 [project-versioning.md](project-versioning.md)）会在跨工程时变成一个跨工程的锁。

### 资产在工程里的位置

一个资产出现在某个版本里，是因为**该版本的文件组里有一条指向它的条目**（见 [site-model.md](site-model.md)）。由此得到三条：

- **"这个版本用了哪些素材"读文件组即可**，不需要解析任何正文（见 [project-versioning.md](project-versioning.md)）。
- **上传了但没被任何文件组引用的资产照常存在**——它只是不出现在产物里。这类资产删除不受拦阻。
- 源侧的引用写成 `asset://<资产标识>`，那是**给用户用的记号**，不是存储形态：它进入文件组时被解析成一条资产条目，此后服务端只认文件组（见 [authoring.md](authoring.md)）。

### 元数据

| 内容 | 说明 |
|------|------|
| 资产标识 | 由 aladdin 分配 |
| 所属工程 | 一个资产属于唯一一个工程 |
| 内容摘要 | 字节的密码学摘要。**是"同一份字节"的标识**，公开区按它寻址。由上传方声明，服务端在**提交时**核对（让存储侧算，或读回自己算——见下） |
| 媒体类型 | **上传方声明的类型**，服务端只校验它在白名单内。它同时决定此后下发时回给浏览器的内容类型 |
| 字节数 | 展示与配额用 |
| 原始文件名 | 仅供展示与排障。**不作为对象键，不参与任何判断** |
| 展示标题 | 可选的展示名，与文件名分离（见"可编辑元数据"）。空时界面回退到文件名 |
| 标签 | 工程内的自由字符串，供检索与归类（见"可编辑元数据"） |
| 备注 | 自由文本说明（见"可编辑元数据"） |
| 上传时间 | 排障与展示用 |

**原始文件名只是一个标签。** 它可能含路径分隔符、控制字符、以及别人的名字，把它拼进对象键就是把一段不可信输入拼进存储路径。对象键用 aladdin 分配的标识与内容摘要，与文件名无关。

### 可编辑元数据：标题、标签、备注

资产的元数据分**两层**，两者的可变性不同。不分开谈，"资产不可变"就会变成一句含糊的话：

| 层 | 内容 | 可变性 |
|----|------|--------|
| 字节层 | 字节、内容摘要、媒体类型、类别、字节数 | **不可变**。没有替换字节的方法；要换图就重新上传一个（见"不可变"） |
| 说明层 | 展示标题、标签、备注 | **可变**。上传之后随时可改，与换图无关 |

说明层是"给人看、帮人找"的那一层，它有三个字段：

| 字段 | 约束 | 说明 |
|------|------|------|
| 展示标题 | 可选；≤ 128 字；空表示没有 | 与原始文件名分离。空时界面回退到文件名展示 |
| 标签 | 每个 ≤ 32 字，每资产 ≤ 16 个 | 工程内的自由字符串。**不是全局字典，也不做成权限资源** |
| 备注 | 可选；≤ 2048 字 | 给人看的说明。**纯文本，不是 Markdown** |

长度一律按**字符数**而不是字节数计，与工程名称、简介同一条理由：用户感知的长度是字数，按字节算会让"一段中文写到十几个字就被拒"成为一条需要解释的规则。

**标签的归一化只有一个入口**（skill 目录的标签走的是同一个：见 [../skill/catalog.md](../skill/catalog.md)）：去掉首尾空白；统一**小写**（存储与展示都用小写，中文不受影响）；空串、含控制字符、含 `/` 或 `\` 的取值被拒；长度或数量超限被拒；归一化之后相同的只留一个，并按**字典序**排好——顺序在三端一致，因此读回来的那一组标签是可以逐字比较的。

**说明层永远不进产物。** 发布只关心正文引用的字节：产物里没有标题、标签或备注，改它们不改变任何版本的正文，也不改变已发布页面的外观。它们也**不进日志原文**（见 [../../observability.md](../../observability.md)），与文件名同级。

**改元数据不改字节层任何一项。** 资产标识、内容摘要、媒体类型、类别、字节数与对象键在改动前后逐字不变——因此公开区的地址不变，已发布页面拿到的还是同一份字节。

**入口表达的是期望的完整状态**：一次调用给出标题、标签、备注三者的目标值，空值表示清空（与工程元数据的更新同取向，见 [project-versioning.md](project-versioning.md)）。上传提交时可以一次性带齐初始值，也可以上传之后再改，两者结果相同。

**按标签筛选是精确匹配、多值取交集**：给出多个标签时，只列出**同时**带这些标签的资产。筛选在服务端做，因此列表返回的标签候选是**整个工程**已有的标签，不随当前筛选收窄。

### 上传：直传，类型由上传方声明

上传走**公共的直传链路**（见 [../objectstore/README.md](../objectstore/README.md)）：服务端分配一个资产标识并签发一份**短时、只允许写、只对这一个键有效**的临时凭证；浏览器拿它把字节直传进私有区；随后调用提交接口，由服务端对那个键做一次 Head，核对存在性与真实字节数。**字节不经过服务端。**

**本次声明的类型与它那一档的上限写在签发出去的策略里**，由对象存储执行——因此不在白名单、或超过该类别上限的上传在存储侧就被拒绝，**不产生对象**（策略里只带声明的那一条，不把整份白名单摊进去：摊进去会让凭证比这次上传需要的宽，还会让策略文档随白名单线性变长，越过 STS 对 Policy 的长度上限）：

| 类别 | 类型 | 上限 |
|------|------|------|
| 图片 | PNG、JPEG、GIF、WebP | 10 MiB |
| 视频 | MP4、WebM | 100 MiB |
| 音频 | MP3、OGG、WAV | 20 MiB |
| 字体 | WOFF2、WOFF、TTF、OTF | 5 MiB |

**字体是随构建产物进来的那一类**：任何工具产出的整站几乎都会带一份 webfont，而在文件组里它必然是二进制，因此只能作为资产（见 [site-model.md](site-model.md)）。字体族名以 `font/` 开头，与图片一样不可执行；交付侧的 `font-src` 随之允许公开域与发布域（见 [publication.md](publication.md)）。

**"声明"不等于"验证"。** 服务端看不到字节，因此媒体类型是上传方说的，不是嗅探出来的。它仍然有意义的原因有两条：

- **类型决定下发时的内容类型**，而白名单里没有任何**可执行**的类型——因此公开区上的对象永远以一个无害类型下发，浏览器不会把字节当作脚本执行。
- **上限与类型绑在同一条策略允许项上**，因此"用视频的上限去卡图片"在存储侧就写不出来（上限取自声明的那一档）。

**SVG 不在白名单里。** 它是唯一一种"看起来是图片、实际是带脚本能力的 XML"的格式，而它会以声明出来的类型被下发。白名单里不收它，等于公开区上永远不会出现一个"能执行脚本的图片"（见"待定决策"）。

**内容摘要同样由上传方声明，且在被使用之前会被核对**：提交时核对它是不是那份字节的摘要——让存储侧算（字节不过境），存储侧给不出时读回自己算（见 [../objectstore/README.md](../objectstore/README.md)）——不一致即拒绝提交并删掉那个对象。因此一条假的摘要不会把公开区的地址指向别人的内容。

### 内容对象（文本条目）走同一条直传链路

文本条目的字节走**与资产完全相同的直传链路**（签发 → 直传 → 提交，见 [../objectstore/README.md](../objectstore/README.md)），差别只有三处：

| 项 | 资产 | 内容对象 |
|----|------|---------|
| 键 | 按资产标识 | 按**内容摘要** |
| 类型 | 上传方声明，服务端只校验白名单 | 由路径扩展名与服务端那一个白名单派生——不存在"声明"这一层 |
| 去向 | 发布时上架到公开区 | **不进公开区**；发布态由服务端从私有区读（见 [site-model.md](site-model.md)） |

**"按内容摘要寻址"对写入提了两条硬性约束**，缺一条"版本不可变"就不成立：

- **仅当对象不存在时才允许写入。** 否则一个错误或伪造的摘要会落到另一个版本已经在用的键上，把那个对象改写掉——而那是"版本不可变"的反面。凭证与条件必须一起保证这一点。
- **写入后服务端读回核对摘要。** 与资产那一步同一种核对、同一条理由：摘要是寻址键，而服务端没有字节可以自己算它。文本对象小，因此这一步直接读回自己算，不去问存储侧。

这两条合起来，使"一份内容只存一份、且此后永不改变"成为结构上的事实，而不是约定。

上限只约束字节数，不含像素尺寸或时长（见"待定决策"）。

### 不可变

**资产一旦上传，字节不再变化。** 没有"替换这个资产的字节"这个动作——要换就重新上传一个，然后改文件组里引用它的地方。

**"不可变"说的是字节层。** 展示标题、标签与备注是另一层，它们可改（见"可编辑元数据"），而它们不参与发布，因此不削弱下面任何一条。

不可变不是洁癖，它是发布语义的地基：

- 公开区按**（工程标识，内容摘要，媒体类型）**寻址。同一个工程里，同一份字节在任何版本、任何次发布里都落在同一个公开地址上——这让发布时"这份资产在这个工程里已上架"成为一个可以只看地址就回答的问题，重复发布不产生重复字节。**跨工程不共享**（键上带工程标识，见"对象键"）。
- 一个版本引用的资产不会在它背后被换掉，因此"发布过的页面内容变了"这件事不会发生。

**"改一个引用"要连着改内容。** 这是不可变带来的真实代价：用户想换一张图，得改引用它的地方——手写时是 `asset://` 记号，构建产物里是那个路径。这一点必须让用户看得见——它正是"版本可回退"的代价的另一面（见 [authoring.md](authoring.md)）。

### 对象键

| 区 | 用途 | 键 | 谁读 |
|----|------|-----|------|
| 私有区 | 资产 | `galaxy/<工程标识>/assets/<类别>/<资产标识>` | 只有工程拥有者，经短时预签名地址 |
| 私有区 | 文本条目 | `galaxy/<工程标识>/text/<内容摘要>` | 编辑态经短时预签名地址；发布态由服务端读（见 [site-model.md](site-model.md)） |
| 公开区 | 已被引用的资产 | `galaxy/<工程标识>/release/<内容摘要>/<类型标识>` | 所有人，经公开读地址 |

**资产的类别段取自声明类型那一档**（`image` / `video` / `audio` / `font`，与白名单的分档一一对应）。它换来的是：让**生命周期与配额策略能按类挂**（视频那一档的存储与清理策略与图片不同），也让"这一份是媒体"在键上就看得出来。代价是同一事实的第二种表达——声明类型已经是一条元数据；一致性由"键只按声明类型派生一次、不随后续更改"这一条固定，而声明错了只表现为位置错，不影响下发类型。

**文本不按扩展名分段，只按内容摘要。** 文本的下发类型由**路径**决定（扩展名 → 白名单），对象本身不承担类型语义。因此**同一个工程内**同一份字节以两种扩展名出现时是**同一个对象**，这正是想要的；文本对象也就可以用中性类型下发——顺带消掉"预签名地址被直接打开时按 HTML 渲染"这条隐患。跨工程不共享这个对象（键上有工程前缀）。

**公开区也按工程切分，段内才按内容寻址。** 两个区都住在 `galaxy/<工程标识>/` 之下，靠 `release` 那一段并排（`assets/`、`text/` 是私有区）。先按工程分组的代价必须写清楚：**跨工程不再共享同一份字节**——两个工程用到同一张底图是两份对象、两份存储。换来的是"这些发布物属于哪个工程"在控制台里一眼可见，以及"按工程清理"这条路留着。

**公开区的键必须含内容类型，不能只有内容摘要。** 同一份字节可以以两种类型出现（同一张图标成 PNG 或 JPEG、同一段文本是 `.html` 还是 `.txt`），而一个对象只能带一个内容类型——只按摘要寻址会让后一次上架覆盖前一次的类型，表现是某个页面拿到错的内容类型。媒体那一边"类型由上传方声明"这个取舍因此也在这条上被钉住：**类型是键的一部分**。

三处前缀都是**常量，不是配置项**。做成配置项只会多出一种失败方式：改了前缀，存量对象在一瞬间全部变成孤儿。它们在**同一个桶**里共存，互不干扰：`galaxy/<工程标识>/` 之下，`assets/` 与 `text/` 落在私有区、`release/` 落在公开区；工程标识恒以 `prj_` 开头，因此 `release` 那一段不会与某个工程相撞。

**公开区与私有区在同一个桶里，靠逐对象的公开读区分。** 私有对象不设任何公开读；公开区对象在**上架那一步**被设成公开读，且只由服务端的上架路径设置。"这个对象是不是公开的"因此是**对象自己的属性**，不落在桶上——桶本身仍是默认私有读写。同一对 COS 密钥沿用，因为公开与私有本来就由对象权限决定，不由凭证决定。

**这条取舍的代价必须写清楚：响应头不再能把公开区与私有区分开。** 发布物的内容安全策略允许的来源是桶主机，而同一个主机上既有公开对象也有私有对象——"漏检的写法取不到东西"这条兜底因此不再是结构性的，边界落在**对象权限**上（见 [publication.md](publication.md) 的"允许的来源只有一个"）。由此得到两条硬性约束：

- **私有对象的权限恒为私有**，任何路径都不得改写它；
- **签发出去的临时凭证不得能声明权限**（不能设 ACL、不能让渡所有权）。否则"公开权限由服务端设置"这句话不成立，而它正是逐对象公开读赖以成立的前提；它同时是绕过发布校验的一条口子——引用完整性只约束上架那条路径，而一个能自己设公开的上传方可以完全不走它（见 [../objectstore/README.md](../objectstore/README.md)）。

### 编辑态下发：短时预签名

读取资产地址时，服务端生成**短时有效**的预签名读取地址；浏览器直接用它取图，服务端不代理字节。

这条**逐字沿用头像的下发模型**（见 [../profile/avatar-storage.md](../profile/avatar-storage.md)），包括它的取舍：**地址在有效期内是一份谁拿到都能用的凭证。** 对编辑态接受这一取舍，理由是它只下发给工程拥有者本人，且短时有效。**因此未发布的资产里不得承载秘密**——这个前提必须在界面上说明，而不是留给用户猜。

发布态用的是另一条路径（稳定公开地址），理由与形态见 [publication.md](publication.md)。**两者不是同一件事的两种实现**：编辑态的服务端要参与判权，发布态的读取完全不判权。

### 删除

删除一个资产做两件事：删私有区的对象，删元数据行。

**被任一版本的文件组引用时拒绝删除**，错误信息指出被哪些版本引用（理由见 [project-versioning.md](project-versioning.md) 的"删除语义"）。

**公开区的副本不因删除私有资产而消失。** 它是一份独立的对象，由发布形成，为已发布的页面服务。清理见 [publication.md](publication.md) 的待定决策。

### 未配置时

| 缺什么 | 行为 |
|--------|------|
| 桶（`cos_bucket_url`） | 资产、**内容（草稿与版本）**与发布都不可用——字节没有地方放。只有工程元数据可写 |
| 发布域（`galaxy_publish_base_url`） | 资产与内容照常可用，发布不可用 |

**桶是内容的前提，不只是资产的前提。** 这是把字节放进对象存储之后新增的一条：文件组的字节也在同一个桶里，因此没有桶就没有草稿、没有版本。前端据此不渲染对应的入口，而不是渲染一个点了报错的控件——与"未配置头像时不渲染头像上传区"是同一取向（见 [../profile/README.md](../profile/README.md)）。

## 边界与约束

- 资产字节**不进关系库**，也不进日志与错误信息。→ 与头像同级。
- **可编辑的只有说明层**（标题、标签、备注）。字节层没有任何更新入口——"改一下这个资产的图"在接口面上不存在。
- **不提供"列出桶里有什么"的能力**。库内的元数据行是"存在哪些资产"的权威；桶上可能留下无从被引用的孤儿对象（见"待定决策"）。
- **不代理字节。** 上传是直传（服务端不接触字节）；下发一律给地址——**发布态的文本除外**，那一步由服务端返回内容本身（见 [site-model.md](site-model.md) 的"取字节"）。服务端读回字节只有一处是常态、且是核对而不是转发：**写入内容对象**时核对摘要；另有一处是**回退**——资产提交时存储侧给不出摘要，才读回自己算（见 [../objectstore/README.md](../objectstore/README.md)）。
- **不做转码、不做缩略图、不做时长与像素校验。** 上传什么就分发什么。
- **资产清单只列调用者自己工程的资产**，且不提供跨工程的查询入口。
- 存储凭证不是配置文件的键，只从环境变量读（见 [../config/credentials.md](../config/credentials.md)）。

## 可验证性与长程执行

**非长程任务。** 上传、删除与地址生成都是即时的同步操作。长程的是发布，见 [publication.md](publication.md)。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 类型由声明限定 | 声明的类型不在白名单内时**拒于签发**，不产生凭证；签发的策略里带的就是**本次声明的类型**那一条（类型与它那一档绑在一起）（`internal/galaxy` 测试 + `internal/objectstore` 测试） |
| 白名单之外拒绝 | SVG、HTML 一类"看起来是图片"的类型被拒（`internal/galaxy` 测试 + 端到端测试） |
| 超限即拒绝 | 声明超过该类别上限时拒于签发；存储侧按策略再挡一道（`internal/galaxy` 测试 + 部署后冒烟） |
| 类别与上限对应 | 用视频的上限去卡图片不被接受：上限取自**声明的类型**那一档（`internal/galaxy` 测试） |
| 字体是一类一等资产 | `font/*` 在白名单内、按自己那一档上限卡；交付侧 `font-src` 允许公开域与发布域（`internal/galaxy` 测试） |
| 公开区键含类型 | 同一份字节以两种类型上架产生两个对象，各自回给浏览器正确的类型（`internal/galaxy` 测试） |
| 内容对象不覆盖已有键 | 对已存在的键再次写入被拒，原对象逐字不变（`internal/galaxy` 测试 + `internal/objectstore` 测试） |
| 内容对象按摘要去重 | 同一份字节出现在两个路径或两个版本下时只产生一个对象（`internal/galaxy` 测试） |
| 内容对象不进公开区 | 上架阶段不为文本条目写公开区对象（`internal/galaxy` 测试 + 部署后冒烟） |
| 提交核对真实字节数 | 声明合法、实际超限的对象被拒且被删掉（`internal/galaxy` 测试） |
| 摘要被核对 | 声明一个与实际字节不符的摘要：资产在上架时失败，内容对象在写入时即失败（`internal/galaxy` 测试） |
| 文件名不进对象键 | 用含路径分隔符与控制字符的文件名上传，对象键不受影响（`internal/galaxy` 测试） |
| 资产不可变 | 接口面上不存在"替换资产字节"的方法；同一资产重复读回摘要不变（`internal/server` 测试 + `internal/galaxy` 测试） |
| 元数据可变而不动字节层 | 改标题、标签、备注之后读回：内容摘要、媒体类型、类别、字节数与对象键逐字不变（`internal/galaxy` 测试） |
| 标签归一化一致 | trim、小写、去重并升序、拒绝空串 / 控制字符 / 路径分隔符 / 超限，三端读到的都是归一化之后的那一份（`internal/galaxy` 测试 + 端到端测试） |
| 标签筛选精确且为交集 | 用两个标签筛选只得到同时带这两个标签的资产；候选标签是整个工程的标签而非当前结果集的（`internal/galaxy` 测试 + 端到端测试） |
| 说明层不进产物 | 改过元数据后重新发布，产物清单与字节逐字不变（端到端测试） |
| 删除资产级联删标签 | 资产删掉后工程的标签集合里不再有它（存储契约测试 + `internal/galaxy` 测试） |
| 备注不进日志 | 元数据更新的留痕只出标识、不出备注原文（`internal/server` 测试） |
| 同一份字节同一摘要 | 两次上传相同字节得到相同内容摘要（`internal/galaxy` 测试） |
| 私有区不可匿名读 | 去掉签名参数直接访问私有区对象被桶拒绝（部署后冒烟）；签发的读取地址必带签名（`internal/objectstore/cosupload` 测试） |
| 地址带有效期 | 签发地址上有签名与有效区间，区间等于调用方给的 ttl（`internal/objectstore/cosupload` 测试） |
| 直传地址只许写、只对一个键 | 策略里的动作只有写入、资源只有那一个键（`internal/objectstore/cosupload` 测试） |
| 删除不因对象缺失而失败 | 对象已不存在时删资产仍成功（`internal/galaxy` 测试） |
| 被引用的资产不可删 | 见 [project-versioning.md](project-versioning.md) 的可验证性表 |
| 他工程资产不可见 | 用另一主体的凭证列资产清单得到空集；取其资产地址被拒（端到端测试） |
| 未配置时降级正确 | 桶未配置时资产、内容与发布都不可用而工程元数据可用；只缺发布域时发布不可用而资产与内容可用（`internal/config` 与 `internal/galaxy` 测试） |
| 密钥不入日志 | 描述这项配置时只出桶地址、不出密钥（`internal/config` 测试） |
| 不联网即可测 | 对象存储访问藏在接口后面，测试注入假实现；签发本身不发起请求（`internal/galaxy` 与 `internal/objectstore` 测试） |

| 发布 | 把资产搬上公开区见 [publication.md](publication.md)；本文件只定义两区的键规则 |

| 服务端配置 | 桶地址沿用 `cos_bucket_url`；发布域由配置给出；密钥只走环境变量（见 [../config/server-config.md](../config/server-config.md)） |
| 部署 | 桶的创建、默认私有读写、子账号最小权限，以及**桶的跨域规则**（浏览器直传需要它）（见 [../../deploy.md](../../deploy.md)） |
| 可观测性 | 上传与删除的留痕**不含字节与文件名**（见 [../../observability.md](../../observability.md)） |

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 是否收 SVG | 作为**资产**暂不收：需要先论证它在公开区下发时的隔离足够（**未定**）。作为**文件组里的文本条目**它已被服务——那里 `img` 不执行脚本，`object` 与 `frame` 被策略禁掉（见 [site-model.md](site-model.md)） | 只影响资产白名单与类型判定；若收，要同时决定"仅可引用、不可内联"如何强制 |
| 跨工程复用资产 | 暂不做（**未定**） | 对象键、归属与删除拦阻都要改；公开区已按工程切分，复用还要先回答"键上那一段工程标识怎么办" |
| 视频转码与缩略图 | 暂不做（**未定**） | 引入一条异步处理流水线（本模块第一个真正的后台任务），发布阶段划分要跟着改 |
| 像素尺寸与时长校验 | 暂不做，需要引入解码依赖（**未定**） | 只影响写入校验 |
| 工程级配额（数量与总量） | 暂不做（**未定**） | 需要一个计量点与超限策略；单拥有者下当前不是瓶颈 |
| 私有区孤儿对象回收（含内容对象） | 暂不做。库内清单为权威，孤儿无从引用（**未定**） | 需要一个对账动作；内容对象按摘要共享，一个对象可能被多个版本引用，回收要按引用计数或对账——与头像的同类问题合并处理 |
| 恢复"服务端看见每一个字节" | 暂不做。那要求字节先过服务端（或直传后由服务端读回校验），代价是带宽与内存（**已定**，见 [../objectstore/README.md](../objectstore/README.md)） | 上传路径与校验位置；类型从"被验证"退回"被声明"这条代价随之消失 |
| 服务端嗅探类型（即便直传） | 暂不做。要读回每个字节，等于把直传省下的带宽花回去（**未定**） | 类型重新变成"被验证"的，白名单的论证可以收紧 |
