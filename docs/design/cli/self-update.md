# 命令行 — 自更新

> 安装与升级的定位见 [README.md](README.md)。本文件是**升级行为**的唯一信源；产物怎么产生、叫什么名字见 [../../release.md](../../release.md)。

## 背景与目标

命令行散在使用者各自的机器上，没有人能替他们更新。自更新把"取回产物—校验—替换本机二进制"这三步收进一条命令，使升级不需要人工下载与解包。

它同时是一件**有破坏力**的事：它替换的是一份可执行文件。因此本文件里"什么情况下不做"与"什么情况下做"同等重要。

成功的衡量标准：

1. 一条命令把本机二进制升到最新发布版本，并说清楚升到了哪个版本。
2. 校验不通过的产物**永远不会**被放到可执行的位置上。
3. 升级失败时本机二进制一个字节都没变。
4. 不是由发布产物安装的二进制被拒绝，且理由是用户能看懂的。
5. 权威发布源**暂时**不可用（限频、短暂故障、网络不通）时，升级仍然能完成。

## 功能行为

### 触发方式

**只有显式执行升级命令时才访问发布源。** 其它命令（含 `version`）保持纯本地，不做任何版本探测、不写任何缓存——命令行是别人脚本里的一个环节，它不该在无关的调用里顺带联网。

命令另有一个**只报告不替换**的形态：用于"我想知道有没有新版本"以及"我想让它出现在 CI 的检查里"。

### 两个源，顺序固定

升级材料有两个来源：

1. **权威发布源**——本仓库的 GitHub Release。它才是"最新"的定义处。
2. **主站兜底镜像**——官方站点上一份只留最新的副本。

**先问权威源**，只有当它的失败属于**暂时性**时才落到主站。暂时性是指"等一等或换一路就好了"的那一类：限频（403/429）、服务端错误（5xx）、以及网络层失败（连不上、超时）。其余失败是确定的答案，**不回退**，原样报给人看——"发布源上没有找到任何发布"不该被镜像里的一份旧副本盖过去。

回退**只发生在取元数据这一步**。一旦选定了源，产物与校验和清单都从**同一个源**取：tag、清单、字节三者同代由构造保证，而不是靠两次请求之间"应该没变"的假设。因此不存在"用权威源给出的版本号 + 镜像里的字节"这种组合。

两路都不可用时，错误信息要**同时交代两路**，而不是只说"请稍后重试"——后者会让人以为等一等就好了，而实际是连兜底那一路也没通。回退真的发生时，命令还要说清楚这次的版本信息不是从权威源来的。

### 主站镜像的形态

镜像挂在**官方站点**上——就是发布产物默认连的那个站点，同源同主机。客户端从注入的默认地址推导出它，**不经过任何配置项**（理由见"边界与约束"）。

- **只留最新一份，覆盖写。** 主站不滚历史：历史版本仍然只在权威源上保留（见 [../../release.md](../../release.md)）。
- **路径固定，不含版本号字面量。** tag 只出现在元数据的内容里——把 tag 写进路径，等于每发一版都要换一个客户端写死的入口。
- **产物名与校验和清单原样照搬既有契约**：包名仍是 `aladdin_<tag>_<os>_<arch>.tar.gz`，清单仍是同一次发布的 `SHA256SUMS`（见 [../../release.md](../../release.md)）。镜像多出来的只有一份**版本元数据**，用来说明"现在是哪个 tag、主站上有哪些产物"。
- **元数据里的产物表只能收窄，不能改名。** 客户端仍然按契约从 tag 推出自己要的文件名，再要求它出现在表里——命名权威只有一处。
- 镜像**由服务器上的部署动作**在收尾时从权威源刷新（见 [../../deploy.md](../../deploy.md)）；发布流水线不产出它，也不往它推。

### 哪些二进制可以自更新

**只有发布流水线产出的二进制可以。** 发布产物在版本号之外多带一个标记，自更新只认这个标记。

判据**不是版本号的形态**。理由：本机构建与发布产物注入的是同一个版本号变量，在恰好处于某个 tag 的干净工作树上，`make build` 注入的同样是一个合法的 `vX.Y.Z`。按形态判断，就会把某人的工作副本当成发布产物替换掉——而这正是本节要挡住的事。

版本号的形态仍然被严格解析，但它只用来**比较**（本机版本 vs 最新发布），不再用来判断来源。发布产物里的版本号若解析不了，说明流水线出了问题，同样拒绝更新而不猜。

**不提供强制开关。** 一个"我知道我在做什么"的开关，一定会被用在不该用的地方——而它在这里的后果是：把某个人的工作副本（可能带着未提交的实验、带着本机的构建参数）无声地换成一份发布产物。本地构建的人从来不需要自更新，他需要的是重新构建。

被拒绝时要说清楚**为什么**：当前是什么版本、为什么这个版本不能自更新、以及他应该怎么做（重新构建，或从发布页重新下载）。

### 平台

只支持发布流水线产出产物的平台。当前平台上没有对应产物时，报错要**列出有哪些平台**，而不是让人对着一次找不到文件去猜。

### 版本比较

| 本机 vs 最新发布 | 行为 |
|-----------------|------|
| 相同 | 报告"已是最新"，不下载任何东西 |
| 本机更低 | 升级 |
| 本机更高 | **不降级**，如实说明本机版本更高 |

"本机更高"不是异常（本地打过更新的 tag、或者发布被撤回），但它不该由一次升级动作擅自把用户的二进制往回退。

### 校验

升级必须取得**与产物同一来源、同一次发布**的校验和清单，并核对本平台产物的摘要：

- 清单里**没有**本产物的条目 → 失败。不得退化成"找不到校验和就跳过校验"——那会让校验在最需要它的时候（产物被掉包、被截断）恰好不生效。
- 摘要**不符** → 失败，且不落到可执行的位置。

校验通过是替换的**前置条件**，不是并行的另一件事。**走的源是哪一个不影响这些语义**：经主站升级与经权威源升级，判定完全一致。

### 替换

- **原子**：从任何观察者的角度看，本机二进制要么是旧的、要么是新的，不存在中间态；失败的替换不改变本机二进制的任何字节。
- **按真实文件替换**：本机二进制是符号链接时，替换的是链接**指向的那个文件**，而不是把链接本身换成一个普通文件——把链接换掉会让使用者的目录布局被无声改掉。
- **可执行**：替换后的文件带可执行权限。
- 目标位置不可写时（例如装在系统目录、由别的用户安装）明确说明这一点，而不是给一个含糊的权限错误。

### 替换之后

**当前正在运行的进程仍是旧版本**——运行的影像是已经打开的那个文件，替换动作改不到它。命令要说清楚这一点，否则使用者会以为升级没生效。

不自动回滚：新二进制启动失败时，用户重新执行一次升级、或从发布页下载即可。保留旧二进制并自检属于独立决策（见"待定决策"）。

## 边界与约束

本模块**明确不处理**：

- 发布产物的构建、命名与保留策略：[../../release.md](../../release.md)。
- 命令行的安装方式（首次安装）：见 [install.md](install.md)。本模块只替换**已经存在**的那份二进制；由包管理器或容器镜像装出来的副本不受本模块管辖（且按上文判据会被拒绝）。

约束：

- **升级源不可配置。** 权威源固定指向本仓库的发布，兜底镜像固定指向官方站点。可配置的"从哪升级"等于一个把任意二进制装进使用者机器的开关——换一个地址写，并不会让它变成另一件事。
- **镜像地址由注入的官方地址推导，不是配置键。** 它跟着"官方服务在哪"走，不跟着"这次连哪个服务端"走：用 SSH 隧道连本机的人，依然应当从官方站点取升级材料，而不是去本机找一个不存在的镜像。
- **两个源被同等信任。** 校验和与字节同源，防得住传输损坏与清单之外的掉包，**防不住源本身被换掉**——这一点权威源与镜像完全相同。镜像不是新增的信任弱点，但主站因此多了一处需要守住的落点（见"待定决策"里的签名一项）。
- **镜像的新鲜度跟着部署走。** 它在部署收尾时刷新一次；发版之后没有部署，兜底路径看到的还是上一版。表现是"经主站时看不到那个新版本"，而不是任何一条报错——**因此它是兜底，不是替代**，权威源仍是唯一的"最新"定义处。
- **版本号只有一个来源**：构建期注入的那一个。自更新不得引入第二个版本号来源，也不得把"最新版本"写进任何本地状态。
- **不写缓存、不记录上次检查时间。** 没有缓存就没有"缓存过期后误判"这一类问题；检查只发生在显式调用时，本来也不需要缓存。
- **产物命名与校验和清单是对外契约**（由 [../../release.md](../../release.md) 记录）：自更新解析它们，改名即破坏升级。
- **不修改 PATH、不写包管理器的账本。** 自更新换的是它自己所在的那个文件；由包管理器安装的副本不受本模块管辖（且按上文判据会被拒绝）。
- **不需要二次确认。** 命令名本身已经表达了意图，而它只作用于调用者自己的那个文件；只报告的形态是给谨慎的人准备的出口。
- **升级动作留痕**，含版本前后；不含任何凭证（本模块用不到凭证）。命令行没有常驻的日志设施，因此这条"留痕"就是命令自己的输出：它必须把**从哪个版本换到了哪个版本**说清楚。

## 可验证性与长程执行

**非长程任务。** 一次升级是一个同步的过程，中间只有一次下载。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 非发布产物被拒绝 | 没有发布标记的二进制一律拒绝（**含版本号为 `vX.Y.Z` 的本机构建**），且**不发起网络请求**（`internal/upgrade` 测试 + CLI 测试） |
| 已是最新时不下载 | 版本相同时不下载任何产物（`internal/upgrade` 测试） |
| 不降级 | 本机版本更高时不做任何替换（`internal/upgrade` 测试） |
| 平台无产物时报可操作的错误 | 错误信息里列出支持的平台（`internal/upgrade` 测试） |
| 校验和不符即失败 | 摘要不符时替换不发生、临时文件被清掉（`internal/upgrade` 测试） |
| 清单里缺本产物即失败 | 缺条目时失败，**不**跳过校验（`internal/upgrade` 测试） |
| 替换是原子的 | 替换步骤失败时目标文件与替换前逐字节一致（`internal/upgrade` 测试） |
| 符号链接指向真实文件 | 以符号链接启动时，替换后链接仍是链接、指向的文件已是新版本（`internal/upgrade` 测试） |
| 只报告不替换 | 只报告的形态下目标文件不被改动、也不发生下载（CLI 测试） |
| 只有显式命令联网 | 发布源只有在升级命令里才被构造；其余命令（含 `version`）不引用本模块（CLI 测试断言命令集 + 代码装配上只有一处构造点） |
| 更新源不可配置 | 配置文件的键集合里没有承载更新源的键；镜像地址由注入的官方地址推导、不受 `--address` 影响（`internal/config` 测试） |
| 暂时性失败可走主站 | 发布源回 403/429/5xx 或网络层失败时，经主站完成只报告与升级（`internal/upgrade` 测试，注入假双源） |
| 确定性的失败不回退 | 发布源回 404（没有任何发布）时不回退，原样报出，且**不访问主站**（`internal/upgrade` 测试：假主站一旦被碰就让用例失败） |
| 回退只在取元数据这一步 | 选定源之后，产物与校验和清单都来自同一个源（`internal/upgrade` 测试） |
| 两路都不可用时报两路 | 错误信息同时交代发布源与主站镜像的原因（`internal/upgrade` 测试） |
| 主站缺本平台条目即失败 | 主站的清单里没有本产物、或摘要不符时失败，**不**跳过校验，本机二进制不变（`internal/upgrade` 测试） |
| 主站元数据形态与部署脚本一致 | 用一个字面量钉住元数据形态，并断言部署脚本写出它的那一行仍在（`internal/upgrade` 测试） |

测试**不得联网**：两个源都藏在可注入的地址后面，测试注入本机假发布源与假主站，覆盖上表每一条。

手工验证：

1. 从发布页下载当前版本的 CLI，放到一个可写目录。
2. 执行只报告的形态 → 应报告当前版本与最新发布版本，且不下载。
3. 执行升级 → 应完成替换；`version` 应显示新版本，且提示当前进程仍是旧版本。
4. 用本机构建产出的二进制执行升级 → 应被拒绝，并说明只支持发布产物安装的二进制。
5. 把二进制放到一个不可写目录再升级 → 应明确指出目标位置不可写。
6. 手工把假发布源里产物的字节改掉再升级 → 应报校验失败，且本机二进制不变。
7. 在一台 `api.github.com` 不可达的机器上（改 hosts 指到黑洞即可）执行只报告与升级 → 应说明本次经主站镜像，并照常给出结论、完成替换。

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 保留旧二进制以便回滚 | 暂不做（**未定**） | 需要额外的落盘位置与一次"新二进制能不能起来"的自检；不做回滚的代价是升级失败后要手工重下 |
| 发布扩展到更多平台（如 `linux/arm64`、`darwin/amd64`） | 暂不做（**未定**） | 改 `Makefile` 的 `PLATFORMS` 即可，工作流不用动（见 [../../release.md](../../release.md)） |
| 升级后的完整性自检（签名而非仅校验和） | 暂不做（**未定**） | 校验和只能防传输损坏与清单之外的掉包；防不了"清单本身被换掉"。现在有了两个源，这一点对**两个源都成立**：权威源是仓库自己的 Release，镜像是官方站点，都属于可信范围——但可信的落点从一个变成两个 |

## 依赖关系

| 依赖对象 | 交互方式 |
|---------|---------|
| 发布产物 | 消费其命名与校验和清单（见 [../../release.md](../../release.md)） |
| 主站镜像 | 权威源暂时不可用时的兜底；由服务器上的部署动作刷新（见 [../../deploy.md](../../deploy.md)） |
| 配置模块 | 只消费"官方站点"这一个派生值（由发布构建注入的默认地址推导）；**升级源仍不由配置提供**（见 [../config/cli-config.md](../config/cli-config.md)） |
| 身份认证 | **不消费**：升级不需要凭证，因此它是一条不需要登录的本地命令 |
| 可观测性 | **不消费**：本命令纯本地，除两个发布源外不产生出站请求，与 `version` 同类（见 [../../observability.md](../../observability.md)） |
