# 命令行 — 安装

> 安装与升级的定位见 [README.md](README.md)。本文件是**发行版命令行怎么到使用者手上**的唯一信源；升级行为见 [self-update.md](self-update.md)，产物怎么产生、叫什么名字、保留几个版本见 [../../release.md](../../release.md)。

## 背景与目标

本模块此前的文档只覆盖了"怎么把本机那一份换掉"（[self-update.md](self-update.md)），没覆盖"第一份怎么来"。而后者是前者的**前提**：自更新只认发布产物，`go build` / `make build` 出来的二进制升不了级。缺了这一节，走编译那条路的人会在第一次想升级时才撞上它——且那时的表现是"升级被拒绝"，看起来像工具坏了。

成功的衡量标准：

1. 使用者在**一个地方**读到"怎么装、怎么登录、怎么升级"，不需要先读仓库。
2. 界面上的命令**不含版本号字面量**。写死一个版本，下一个 tag 之后它就是一条复制了跑不通的命令，而这个页面不会因此报任何错。
3. 界面上的命令**不含部署实例的值**（域名、主机别名），与仓库"不含实例值"是同一条约束（见 [../../deploy.md](../../deploy.md) 的可验证性表）。
4. **内容与载面可分离**：现在挂在外壳内，将来挪到公开区时是承载方式的变更，不是内容重写。
5. 界面上的一段命令**整段可复制**：这些命令要么长、要么多行，逐行选中既容易漏掉续行，也容易把行首的换行带进去。
6. 安装命令把二进制放进**用户可写的目录**，不把人引向系统目录——理由见「装在哪里」。

## 必须回答的四件事

| 问题 | 要点 |
|------|------|
| 这是什么 | aladdin 的命令行客户端。判定发生在服务端，本工具不缓存也不复用任何判定结果 |
| 怎么装 | **只有发布产物可以装**——本机构建的二进制不能自更新，这条要在装的时候就说，而不是等他升级时才发现；落点是用户可写目录，见「装在哪里」 |
| 怎么登录 | 设备码（终端给短码、在自己已登录的浏览器里批准）与 `--token` 两条路径，后者是机器凭证 |
| 怎么升级 | `update` 与只报告的 `update --check`；升级换的是本机那个文件，**当前进程仍是旧版本** |

## 版本号不得出现在界面上

这是本页唯一一处与实现**强绑定**的要求，值得单独说。

产物的文件名里带着 tag（`aladdin_<tag>_<os>_<arch>.tar.gz`，见 [../../release.md](../../release.md)），因此把一条下载命令直接写进界面，就等于把当时的版本号也写了进去。下一个 tag 之后：tag 还在，产物地址还在，命令却指向一个**不再存在**的产物名——发布流程不会因此失败，页面也不会报错，只有一个复制了命令的人在终端里看到 404。

**取值只有一种写法：在运行时解析最新 tag。**

```
tag=$(curl -fsSL -o /dev/null -w '%{url_effective}' \
  https://github.com/poetlife/aladdin/releases/latest)
tag=${tag##*/}
```

`/releases/latest` 是一次重定向（`/releases/tag/<tag>`），`url_effective` 给出落地地址。**不自建"最新版本"的解析**：那是发布侧的事实，第二个实现只会在某天与它对不上。

> 这里与自更新是同一条取向：**"最新版本"不落任何本地状态**（见 [self-update.md](self-update.md) 的约束）。区别只是自更新在进程里解析，这里在界面上解析。

同理，**平台列表也不自建**：它取自 [Makefile](../../../Makefile) 的 `PLATFORMS`，而契约在 [../../release.md](../../release.md)。界面是这些事实的**消费方**，不是第二份定义。

## 装在哪里

界面给出的安装命令把二进制放进**使用者自己的可写目录**，而不是 `/usr/local/bin` 这类系统目录。

理由是自更新：升级替换的正是本机这一份文件，目标不可写时它只报告、不替换（见 [self-update.md](self-update.md) 的「替换」）。装进系统目录的那一份，此后每次升级都要 sudo——而"每次升级都要人工介入"恰恰是自更新要替掉的东西。安装这一步把人引到系统目录上，等于让他第一次升级时才撞上这堵墙；而那时的表现是"升级失败"，看起来又像工具坏了，与本节开头要避免的正是同一种。

非特权用户装系统目录还会直接报 `Permission denied`——一条照抄下来就跑不通的命令，与第 2 条要防的"复制了跑不通"是同一类问题。

因此默认落在用户可写的位置；`~/.local/bin` 是否已在 `PATH` 里因发行版而异，界面负责说清这一点，不假设它已就绪。

## 载面

它是站内文档区的第一章：`/docs/cli`（见 [../web/docs-area.md](../web/docs-area.md)）。挂在应用外壳内，准入只要**已认证**——与个人资料、设备码批准页同类，不要权限码。零权限的主体同样需要它：否则"要先装命令行才能登录、登录了才看得到怎么装命令行"这个环闭不上。

**将来放出去**（未认证也能读）时改变的是**准入**，不是宿主、也不是内容。这也是上面第 4 条底线：内容不依赖读者已经登录这件事。

## 边界

本模块**不**在这里回答：

- 命令怎么用、有哪些子命令：那是 `aladdin --help`，是命令自己的事，写第二份必然漂移。
- 接口怎么调：见 [../api-docs/README.md](../api-docs/README.md)。
- 服务端地址怎么配、生产怎么连：那是部署形态，见 [../../deploy.md](../../deploy.md)。**实例值不进界面**（第 3 条）。

## 可验证性与长程执行

**一次安装是同步的过程，但界面上的命令会随发布契约漂移**——因此第 2、3 条是长期项，不是一次性的验收项。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 不写死版本号 | 渲染结果里不出现 `vX.Y.Z` 形态的字面量（`CliPage` 测试） |
| 运行期解析最新 tag | 界面命令里解析出的 tag 能取到真实产物（发布后人工冒烟） |
| 命令整段可复制 | 每个命令块自带复制入口（`CliPage` 测试 + 人工冒烟） |
| 落点用户可写 | 两个平台的安装命令落点都是用户可写目录（`CliPage` 测试） |
| 入口可达 | 已认证即可打开（`CliPage` 测试 + 人工冒烟）；导航入口是**文档区**那一项，由 [../web/docs-area.md](../web/docs-area.md) 负责 |
| 不含实例值 | **人工核对**：界面文案里不出现域名与主机别名。这条**不写成测试**——写测试就得把实例值敲进测试文件，而那正好是它要防的事。它已在 [../../deploy.md](../../deploy.md) 的长期检查里 |
