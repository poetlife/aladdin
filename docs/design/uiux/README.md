# UI/UX 设计指导

> 本目录是 aladdin **前端界面取舍**的唯一信源。

## 背景与目标

呈现层有两个不同的问题，混在一处就谁都说不清：

- **机制**：颜色从哪来、图标从哪来、窄到什么程度算窄。这些是"唯一入口"类的问题，答案是一个函数名或一个常量。
- **取舍**：一个界面该长什么样、信息怎么组织、失败时说什么。这些没有唯一答案，但同一类界面必须有同一种答案。

后者原先无处安放，于是每加一个页面就重新即兴决定一次——同一个"重试"，这页叫刷新那页叫重新加载。

本模块**不发明新规矩**：下面每一条都是把已经落地的做法登记下来，供下一次改动对照。新增一条之前先问"现有界面是不是都这么做"，不是就说明它还不成其为规矩。

成功的衡量标准：

1. 动手改一个界面之前，能在这里找到同类界面已有的取舍依据。
2. 两个同类界面不会各写一套说法。

## 信息层级

- **一页一个主题，页内用卡片分区，一张卡片一件事。** 首页是「当前会话」一张卡，权限码明细收在同一页的高级展开区；资料页是「头像」「昵称与简介」「登录方式」三张。卡片标题就是这一块在回答的问题。
- **一页只有一个主操作。** 其余的降级为次要按钮或文字按钮：角色定义页只有一个「刷新」；资料页只有一个「保存」。
- **主次靠字号与文本色区分，不另造色值。** 次要说明走 antd 的次要文本色（`type="secondary"`），层级不靠自己调色。
- **表格的行内操作是一串文字按钮**（`type="link"`，破坏性的那个 `danger`），不用带边框的按钮、也不用 `type="text"`：一排带边框的按钮会把这一列变成视觉主体，而它只是次要操作；`text` 看上去则像普通的词，不成其为可以点的东西。图标只在破坏性的那个上加（如删除）。
- **一个动作挨着它作用的那一块**，不都堆到页头。页头只放"与这一页这个整体有关"的：刷新（重新读一遍）、以及流程上的主操作。改说明层的按钮在说明那一块、换封面的按钮挨着封面——堆在页头不只是挤：它让**"哪一颗在动哪一块"变成一个要猜的问题**，而紧挨着就没有这个问题。破坏性的那个也不因为放到块里而变显眼，它仍然是文字按钮加二次确认。

**工作台类页面不铺卡片。** 若一个页面有一条持续进行的处置流程、且"看"与"做"是并置的（galaxy 编辑页：看草稿渲染成了什么样、同时把它推到发布），就用**固定的分区骨架**——一条状态行说当前能不能推进、推进到哪了；主体是那个要看的对象，铺满；一批一批的东西（资产、版本）不常驻，从顶栏以弹层打开。卡片是自上而下逐块阅读的形态，而工作台的信息是同时参照的：包成卡片只会在每块外面加一圈留白与一行标题，把它们之间的位置关系吃掉；把清单类的东西常驻在侧边，则会让主体长期窄掉一截，去换一个多数时候不看的列表。骨架本身仍守上面三条——**分区依旧"一件事一块"，主操作任何时刻依旧只有一个**（工作台里"哪一个"由流程位置决定：缺版本时是存版本，有版本未发布时是发布）。窄屏下这套骨架不换，只折叠 chrome：**让"看"的那块面积仍是首屏主体**，低频入口收进「更多」与既有弹层（见 [../web/responsive.md](../web/responsive.md)）。

## 间距与节奏

- **间距只取少数几档**（4 / 8 / 12 / 16 / 24），不写这之间的中间值。多一档就多一种"这两处为什么不一样"的追问，而它通常没有答案。
- **页面四周的留白由内容区给，卡片内部不再自加一层。** 窄屏下内容区的留白收一档，见 [../web/responsive.md](../web/responsive.md)。
- **并排元素成组用 `Space` / `Flex`，并允许换行**，而不是把控件挤出容器。

## 弹窗

- **弹窗一律用 `AppModal`**（[web/src/ui/AppModal.tsx](../../../web/src/ui/AppModal.tsx)），不要从 antd 直接引 `Modal`。这不是包装癖：antd 默认让整屏那层遮罩自己滚，于是滚动条画在**窗口右缘**、标题与按钮跟着滚走——看起来就是"这个弹窗的滚动条坏了"。`AppModal` 把高度约束放到弹窗自己身上，头尾不动、只有中间滚；同时让**头、内容、尾三块的横向边界重合**，滚动条才是弹窗边缘的一部分，而不是从标题右缘外面"冒出来"插在角上的一根柱子。
- **这条规则的要害是"无法被忘记"。** 它在工作台的两个面板上被单独解过一次（一个本地的 `PANEL_BODY_STYLE`），而单独解一次的下场就是别的弹窗继续踩同一个坑。**能靠"只有一个入口"解决的，不要靠"记得每次写一遍"。**

## 空态、加载与失败

- **空态说清"现在是什么状态、为什么"**，而不是"暂无数据"。「当前作用域下没有角色」告诉人换个作用域看看；「本部署未启用头像功能。昵称与简介照常可用」还顺带回答了"那我还能做什么"。
- **进行中就地反馈，并挡住重复提交。** 按钮进 loading，列表用表格自带的 loading，不另起浮层遮住整页。
- **还什么都没有的地方可以铺加载态，但它只铺到内容开始出现为止。** 一块本来就是空的区域（一次跨源 iframe、一次整页取数）铺遮罩是在回答"这儿为什么什么都没有"；而**内容一旦开始出现就不能再盖着**——那时的遮罩挡住的恰恰是已经能看的东西，比空着更糟。浏览器给出的"加载完了"往往晚于"能看了"（子资源还没到），因此这类加载态要有**到点就撤**的一档：撤掉遮罩、只留一条不遮挡的可重试提示。
- **加载态一律"居中 + 一句话"，只有这一种形状**（[web/src/ui/LoadingHint.tsx](../../../web/src/ui/LoadingHint.tsx)，登记在 [docs/ssot-registry.md](../../../docs/ssot-registry.md)）。两处各写各的，就会漂移成两样——而其中一样很快就只剩一颗**没有居中的裸转圈**：位置由内容决定的地方（整页、会话判定期间）它只有一行高，于是一整块空白上只有左上角一颗小点，既不像在加载、也不像坏了。**"居中"要的是横向纵向都在中间**，不是"贴左边但稍微下来一点"。**一句话也是必须的**：孤零零一颗转圈与一次加载失败长得一样，而读者面对这两种情形该做的事完全不同。等待说的是同一件事，因此**全站同一句**，不按页面换说法。
- **失败要说人话并给出下一步**；诊断信息（追踪 ID）留在现场且可复制，但不占主体——需要它的是排查问题的人，不是正在做事的人。

## 文案

- **讲后果与原因，不只重复动作名。**「不能解绑最后一个登录方式，否则这个账号将再也进不来」比「无法解绑」有用得多。
- **同一个概念全站同一个词**，与字段名、权限码保持一致，不造同义词。
- 面向使用者的文字里不出现实现细节术语；确实需要转述给服务端的诊断信息除外。

## 破坏性操作

- **默认不突出**（danger 或文字按钮），**二次确认，并在确认框里说明后果**——解绑的确认框写清"登录时会登记出一个新的零权限主体"，因为那是使用者做这个决定时唯一需要知道的事。
- **做不到的事情在按钮上就禁掉并说明原因**，而不是等人点了才报错（只有一个登录方式时，解绑按钮直接禁用，理由就写在旁边）。
- 能撤回的操作不弹确认；撤回不了才弹。
