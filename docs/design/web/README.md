# Web 界面 模块总览

> 本目录是 aladdin 前端**呈现层约定**的唯一信源。

## 背景与目标

三端共享同一套权限体系，但只有前端是"被人看的"。配色怎么定、图标从哪来、用户选的明暗记在哪，这些属于呈现层的约定，需要一个落点，否则每一页各写一套。

本模块只管**呈现**，不回答"谁能看到什么"——那是 [../rbac/frontend-permissions.md](../rbac/frontend-permissions.md) 的事，且前端的一切裁剪都不是安全边界。

成功的衡量标准：

1. 使用者能按自己的环境选亮色、暗色或跟随系统，选择在刷新与下次打开后仍然生效，且系统偏好改变时「跟随系统」当场跟着变。
2. 换主题只换配色：任何一处判定结论、任何一页的结构都不因此改变。
3. 图标只有一个来源。
4. 颜色只有一个来源：界面各处不写死色值。

## 主题

三档，切换入口在页头：[AppHeader](../../../web/src/layouts/AppHeader.tsx)。

| 档位 | 含义 |
|------|------|
| 亮色 / 暗色 | 固定配色，不随环境变 |
| 跟随系统 | **默认**。跟随操作系统的明暗偏好，且在运行期跟随——用户在系统里切换时界面立即跟着变，不需要刷新 |

两条边界：

- **不随会话下发，只记在浏览器本地。** 它是使用者的环境偏好，不是主体属性，服务端没有理由知道它，因此也没有对应的接口与字段。读取与折算的唯一入口见 [SSOT 注册表](../../ssot-registry.md)。
- **不参与任何判定。** 偏好是呈现输入，与 [../config/README.md](../config/README.md) 的同名原则一致：配置与偏好都不得成为权限的来源。

颜色由 antd 从同一份主题种子推导：换主题只换算法，界面各处经 `theme.useToken()` 取值，不写死色值。页头与侧边栏的底色也来自同一处——antd 对页头给的默认底色是一个与算法无关的固定深色，直接用会在亮色主题下留一条深色带。

## 图标

统一取自 lucide-react，不引入第二套图标库。lucide 不含品牌图标，渠道入口（GitHub、Google 等）用通用图标表达，不描摹品牌图案。

## 外壳

侧边栏（品牌区 + 导航 + 账号）与页头（折叠开关、作用域、主题切换）构成外壳，业务页面挂在其内部。外壳本身只要**已认证**——零权限的主体也进得来，界面是空的（见 [../rbac/frontend-permissions.md](../rbac/frontend-permissions.md)）。

账号区（头像、展示名、退出登录）钉在侧边栏底部，与导航同处一侧：它与导航回答的是同一类问题——"我是谁、要去哪一页"；页头留给与当前视图相关的控件（折叠、作用域、主题）。侧边栏收起时账号区只留头像。

导航项按权限裁剪：无权限的入口**不渲染**而不是置灰，避免导航栏被大量无权项占据。
