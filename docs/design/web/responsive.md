# 响应式与窄屏

> 本文件是 aladdin 前端**窄屏行为**的唯一信源。

## 背景与目标

界面要能被人拿在手上看。手机不是"缩小的桌面"：桌面上侧边栏与内容区并排放下还剩不少，手机上再并排就只剩一条缝。需要一个落点回答"窄到什么程度算窄、窄了之后长什么样"，否则每一页各自猜一个断点，切换点会在页面之间对不齐——同一个窗口，这页还有侧边栏、那页已经变成抽屉。

本文件管的是**窄屏这件事本身**：断点取多少、窄屏下外壳换成什么、页面级的适配怎么写。

不管的是：[README.md](README.md) 的主题与图标（呈现机制）、[../uiux/README.md](../uiux/README.md) 的界面取舍（一个界面该长什么样）。

判定窄屏这一版做对了没有，只看一条：**手机上不出现整页横向滚动**——每一页都读得下来；管不着的操作可以不提供，但看得见的内容不能被切掉。

## 断点

**"是否窄屏"只有一个定义**：`useNarrowViewport()`（[use-narrow-viewport.ts](../../../web/src/layouts/use-narrow-viewport.ts)），断点取 antd 的 `lg`，即 `screen and (max-width: 991.98px)`。

取这个值不是随手挑的：它正是 antd Sider 自己拼查询串时用的那一档，于是"外壳换成抽屉"的切换点与 antd 认定的 `lg` 完全相同，不会出现"antd 认为该收起、我们认为还是宽屏"的错位。它与"是否窄屏"这个概念一起登记在 [SSOT 注册表](../../ssot-registry.md)。

两条边界：

- **不用 `Grid.useBreakpoint()`。** 它首帧返回空对象，手机上会先闪一帧错误布局；`matchMedia().matches` 是同步可读的，首帧就是对的。
- **不引入第二处 `matchMedia`。** antd 组件内部的响应式（如 `Descriptions` 的 `column`）不算——那是它自己的事；我们自己的代码里只此一处。

## 窄屏下的外壳

宽度不够时侧边栏**不渲染**，改由左侧抽屉承载同一份内容（品牌 + 导航 + 账号）。

不把侧边栏收成 64px 导轨了事，是因为导轨在手机上仍占着地方，等于白白压窄内容区——那点宽度手机给不起，不如整块让出去。因此宽窄两态渲染的是**同一个** `AppSidebar`，窄屏不出现第二份导航；两份就会各自演化，而"导航有哪几项、账号区长什么样"是同一件事。

页头那颗开关做的仍然是"切换导航的显隐"，但语义随宽窄变：宽屏收放导轨，窄屏开抽屉——图标、无障碍标签与行为都由外壳注入，页头自己不判断宽窄。

抽屉里**每一次跳转都会把它收起**——导航项与账号区都算。少接一条，人已经落到目标页了，抽屉还盖在上面。

## 页面级的适配

本仓库**没有 CSS 文件**，样式一律是内联对象加 antd 的属性与 token。这一条的直接后果是：页面**写不出 `@media`**。

于是页面级的适配只能用**与断点无关**的写法——它们在任何宽度下都成立，不需要知道当前宽窄：

| 场景 | 写法 |
|------|------|
| 固定宽度的卡片（登录、回调、设备审批） | `width: '100%'` 加 `maxWidth`，两侧留出内边距 |
| 可能很长的文本（渠道标识、externalId） | `wordBreak`，让它换行而不是撑破那一行 |
| 列宽按内容撑开的表格 | 交给 `Table` 的 `scroll`，让表格在自己的容器里横向滚动 |
| 一行里可能放不下的并排元素 | 容器加 `wrap` |
| 撑满视口高度的工作台页面（galaxy 编辑页） | **宽窄都**让主区吃掉视口剩下的高度（底部不留空）；主区的**高度下限**按宽窄不同（宽 240 / 窄 360），视口比下限还矮时整页滚动 |

确实需要按断点分叉时才走上面那个 hook——目前有外壳与 galaxy 编辑页两处：外壳用它决定侧边栏还是抽屉；编辑页用它决定**主区的高度下限**（窄屏给得更高：手机上本就没有并排要照顾，而下限决定的是「一屏里还看得出多少」）与 **chrome 的折叠形态**（窄屏把低频入口收进顶栏的「更多」、状态条压成一行，见下「工作台窄屏」）。**这件事不能靠 `wrap` 或纯 flex 代替**：结构宽窄是同一份，分叉的只是那两个布尔值（下限取多少、chrome 收不收），控件与逻辑本身只实现一份。

**下限而不是定高。** 定高在竖屏手机上会留出一条空底：那块面积之外没有别的东西可排，空出来的高度只能露出外壳的底色。让它吃掉剩下的高度、只留一个下限，才是「屏幕多高就用多高」；视口比下限还矮时照常滚动。

## 工作台窄屏

galaxy 编辑页的纵向 chrome 一多，真实手机高度下就把主体挤没了。窄屏（`useNarrowViewport()` 命中）打开工作台时，**chrome 折叠，预览（或源码）是首屏主体**。常驻的只有三样：**返回 + 工程标题 + 一颗主操作**——缺版本时是「存为版本」，有版本未发布时是「发布」，仍是一页一个主操作（见 [../uiux/README.md](../uiux/README.md)）。

收起来的入口去两处：**顶栏的「更多」**与**既有的弹层**。进「更多」的是资产、版本两个集合面板、槽切换（工程多于一个内容槽时）、加槽，以及**非主操作的那一个流程动作**（主操作是发布时它是存版本，反之亦然）。

其余两条 chrome 各自压法：

- **状态条压成一行**：结论 +「已发布 · 复制」+ 撤回。**长发布地址不常驻**——换成短标签与一颗常显的复制图标，复制出来的仍是那条真实地址（完整地址在工程信息弹层里也看得到）。撤回留在原处、仍是**按钮级**的次要动作——它紧挨着要作废的那个地址，这条不因宽窄而变（见 [../galaxy/authoring.md](../galaxy/authoring.md)）。
- **预览工具条**只留 文件选择、刷新、预览/源码 切换；「单独打开」收成图标按钮（预览侧的动作跟着预览走，不搬到顶栏）。

**外壳页头不参与压缩。** 它全站一致，收放的是导航；让某一页的页头为这一页的工具让路，会把"页头是什么"变成每页各自回答的问题。压缩只发生在编辑页内部。

验收：典型手机竖屏（约 667–844 CSS px 高）打开已发布工程，预览/源码明显大于 chrome；不滚动或少滚动即可完成——刷新预览、复制发布地址、看发布状态、触发主操作（存版本或发布）、撤回、打开资产/版本、切文件、单独打开。外壳页头在窄屏与别页一致。

## 非目标

手机端的定位是**"查看 + 轻操作"**：登录、看资料、审批设备在手机上要能完整走完；角色管理这类重页面只要求读得下来，不为手机重做交互。galaxy 编辑页同属这一档，但比"读得下来"更进一步：窄屏打开工作台时**预览（或源码）是首屏主体**，chrome 折叠（见上「工作台窄屏」），高度让给那块面积。仍不为它设计手机专属的可视化编辑、手势或底部导航。手势、底部导航、PWA、离线都不在范围内。
