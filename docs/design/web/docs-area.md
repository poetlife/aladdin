# Web 界面 — 站内文档区

> 呈现机制（颜色、图标、动效、外壳）见 [README.md](README.md)。本文件只管**站内文档区**：它是前端的哪一部分、准入是什么、章节怎么加。
>
> 它**对 agent 可读**的那三层（预渲染 HTML、每章 Markdown、`llms.txt`）见 [agent-readable.md](agent-readable.md)——那是另一件事，本文件只管"人从界面上的哪里读到它"。

## 背景与目标

"怎么装命令行""接口怎么调"这类内容面向的是**使用者**，不是读仓库的人。[../cli/install.md](../cli/install.md) 记下了命令行安装的事实，但它落在仓库里，界面上的使用者看不到。

本区回答的是"这些内容长在界面的哪里"。

成功的衡量标准：

1. 文档与外壳同源：同一套路由、同一套主题、同一套组件。**它不是另一个站点。**
2. 导航只占一项，加章节不需要动导航。
3. 准入只有一处声明（路由），准入变化时内容一个字节都不用改。

## 它是前端的一部分

**这是本节的核心。** 文档不是第二个站点，也不是 `web/public/` 下的静态文件：

- 它走路由表（与其它页面同一条），因此深链、导航高亮、外壳全都自动一致。
- 它经 `theme.useToken()` 取色、用 antd 组件，因此换主题时它跟着换。静态站做不到这一点——它会成为界面上唯一一个不随主题走的地方。
- 它以组件形式存在，因此"哪一章可见"由准入决定，而不是靠把文件从目录里挪走。

> 与 `/api-docs/` 的区别值得说清：那一页是**派生物**（由 proto 生成，见 [../api-docs/README.md](../api-docs/README.md)），内容不手写、也不需要随主题变，因此留在 `web/public/` 下当静态文件是合适的。文档区的内容是手写的、要进外壳的，形态因此不同。

## 准入：公开

**未认证也能读。** 零权限的主体最需要它——否则"先装命令行才能登录、登录了才看得到怎么装命令行"这个环闭不上。

准入写在路由表的**一处**（[web/src/routes.tsx](../../../web/src/routes.tsx)）：文档区的那条分支在 `RequirePermission` **之外**，也在 `AppLayout` **之外**。

它**不是**"把它从 `RequirePermission` 里挪出来就完事"。那两条现在是父子：只把它从前者挪出来，它会连外壳一起丢掉——没有品牌区、没有导航。放出去因此给它**一条自己的分支**，那条分支套的是**公开外壳**（[PublicDocsLayout.tsx](../../../web/src/layouts/PublicDocsLayout.tsx)）：品牌区 + 文档导航 + 主题切换，**没有账号区、没有管理范围**。那两样回答的是"我是谁、我在哪个范围下工作"，而访客没有这两样东西。

因此**登录用户从侧边栏点「文档」也会落到这层外壳上**（导航那一项保留，但点进去就离开了应用外壳）。公开外壳里因此有一条**「进入应用」**的回路，否则登录用户只能按浏览器后退。

### 它对内容的反向约束

放出去之所以能"只改准入"，前提是正文里**不依赖"读者已登录"**——"你当前的权限码"这类只有登录者才有的内容一旦进去，放出去就会变成一次内容重写。这一条只能靠人守，是上面 3 条衡量标准里唯一一条。

## 正文是一份 Markdown 源

正文写在 `web/src/pages/docs/chapters/<slug>.md`，页面渲染它。**章节源同时就是送给 agent 的 `/docs/<slug>.md`**——不为 agent 再手写第二份（理由与做法见 [agent-readable.md](agent-readable.md)）。

一章的形状：`## ` 开一行即起一节，页面上是一张卡片。它之前的属于引言。

> **通道那一章与其余两章不同，有两件事要说清楚。**
>
> **一是体裁：它是接口参考，不是介绍页。** 其余两章教的是创作动作（装命令行、推内容、引素材）；这一章回答的是"这条通道长什么样"——字段、取值、约束、适用边界。因此它**只写事实，不写背景与理由**（理由属于 spec），并且**用短句、一句一件事**。句子长度由测试钉住：这一页起初写成了带背景与理由的说明文，读起来像设计文档，而长句正是那种写法的痕迹——不钉住，它就会漂回去。
>
> **二是取值来源：它必须从实现里取，不能手抄。** 通道名、协议版本、消息类型都是**对外契约**（见 [../galaxy/site-model.md](../galaxy/site-model.md) 的"平台接入桥"）。正文里因此写的是 `{{frame.channel}}` 这样的占位符，由 [frame-channel.ts](../../../web/src/pages/galaxy/frame-channel.ts) 的常量在构建期填上；不认识的占位符直接抛错。

## 章节与外部入口

| 入口 | 路径 | 是什么 | 正文归属 |
|------|------|--------|---------|
| 命令行 | `/docs/cli` | **一章**：前端的一页 | `chapters/cli.md`（事实层面见 [../cli/install.md](../cli/install.md)） |
| 创作与发布 | `/docs/galaxy` | **一章**：前端的一页 | `chapters/galaxy.md`（事实层面见 [../galaxy/cli.md](../galaxy/cli.md) 与 [../galaxy/authoring.md](../galaxy/authoring.md)） |
| 页面与外壳的通道 | `/docs/frame-bridge` | **一章**：前端的一页 | `chapters/frame-bridge.md`（事实层面见 [../galaxy/site-model.md](../galaxy/site-model.md) 的"平台接入桥"） |
| 接口参考 | `/api-docs/` | **外链**：生成出来的静态页 | [../api-docs/README.md](../api-docs/README.md) |

导航**只有一项**（「文档」→ `/docs`）：东西是往区域里加，不是往导航里加。

### 为什么接口参考只是一条链接

它是 proto 的派生物，由 `make api-docs` 生成、由静态目录直接服务（见 [../api-docs/README.md](../api-docs/README.md)）：不随主题走，也不需要进路由。把它嵌成一页会**把它关进登录墙**——而它的读者恰恰是外部调用方，那些人没有 aladdin 账号。

**那条链接必须是普通 `<a>`，不能用路由的 `Link`。** `/api-docs/` 不在路由表里：`Link` 会让 React Router 接住这次跳转、匹配不到路由、落到 `*` 的兜底上，表现是"点了接口文档却回到了首页"——**而且没有任何报错**。

**路径写相对的 `/api-docs/`**：绝对地址会把部署实例的域名写进仓库（见 [../../deploy.md](../../deploy.md) 的可验证性表）。这条路径另有两处随它一起定：`web/public/api-docs/` 这个目录名，以及 dev 下 vite 的目录 rewrite（生产由 nginx 的 `try_files` 兜，dev 没有它就会落到业务前端的 SPA 兜底上）。

### 加一章

**只改一处**：在 `chapters/manifest.tsx` 里加一条，再放一个同名 `.md`。

索引页、路由表、预渲染的路径列表、`llms.txt` 全部从那份清单派生——它们此前各是一处手写，四处定义比一处更容易漂。

## 可验证性与长程执行

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 未登录也进得去 | 不带凭证按真实路由表渲染 `/docs/cli` 仍出正文（`routes.test.tsx`） |
| 公开外壳里没有登录者的东西 | 没有应用侧边栏、没有管理范围（同上） |
| 公开外壳里有回应用的入口 | 「进入应用」指向 `/`（同上） |
| 索引与路由不漂 | 索引页指向的路径就是清单里那一条（`DocsIndexPage` 测试） |
| 外链不被 SPA 接走 | 点接口参考那条链接不会落到路由的兜底上（`DocsIndexPage` 测试） |
| 通道那一章不漂回说明文 | 正文里的句子长度有上限（`frame-bridge.test.tsx`） |
| 通道取值来自实现 | 三个取值取自 `frame-channel.ts`（同上） |
| 正文里没有实例值 | 两章的正文都不含绝对地址（`galaxy.test.tsx` / `frame-bridge.test.tsx`） |
| 内容不依赖登录 | **人工核对**：正文里没有只有登录者才有的东西（这是"放出去只改准入"的前提） |
| 接口参考打得开 | 部署后人工冒烟：从索引点过去能看到 Redoc 渲染的接口列表 |
