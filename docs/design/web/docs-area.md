# Web 界面 — 站内文档区

> 呈现机制（颜色、图标、动效、外壳）见 [README.md](README.md)。本文件只管**站内文档区**：它是前端的哪一部分、准入是什么、章节怎么加、将来怎么"放出去"。

## 背景与目标

"怎么装命令行""接口怎么调"这类内容面向的是**使用者**，不是读仓库的人。[../cli/install.md](../cli/install.md) 记下了命令行安装的事实，但它落在仓库里，界面上的使用者看不到。

本区回答的是"这些内容长在界面的哪里"。

成功的衡量标准：

1. 文档与外壳同源：同一套路由、同一套主题、同一套组件。**它不是另一个站点。**
2. 导航只占一项，加章节不需要动导航。
3. 准入只有一处声明（路由），将来放宽准入时内容一个字节都不用改。

## 它是前端的一部分

**这是本节的核心。** 文档不是第二个站点，也不是 `web/public/` 下的静态文件：

- 它走 `createBrowserRouter` 的路由（与其它页面同一条），因此深链、导航高亮、外壳全都自动一致。
- 它经 `theme.useToken()` 取色、用 antd 组件，因此换主题时它跟着换。静态站做不到这一点——它会成为界面上唯一不随主题走的地方。
- 它以组件形式存在，因此"哪一章可见"由准入决定，而不是靠把文件从目录里挪走。

> 与 `/api-docs` 的区别值得说清：那一页是**派生物**（由 proto 生成，见 [../api-docs/README.md](../api-docs/README.md)），内容不手写、也不需要随主题变，因此留在 `web/public/` 下当静态文件是合适的。文档区的内容是手写的、要进外壳的，形态因此不同。

## 准入

现在：**已认证**（与个人资料、设备码批准页同类），不要权限码。零权限的主体最需要它——否则"先装命令行才能登录、登录了才看得到怎么装命令行"这个环闭不上。

**"放出去"（未认证也能读）改变的是准入，不是宿主**——但**不是**"把路由挪出去就完事"。文档区那几条路由现在同时挂在 `RequirePermission` 与 `AppLayout` 之下，前者是后者的父节点；只把它们从 `RequirePermission` 里挪出来，它们连外壳一起没了（没有品牌区、没有导航）。

所以放出去要给文档区**一条自己的分支**：不经过 `RequirePermission`，因此也不经过 `AppLayout`，于是需要一个**公开外壳**——品牌区 + 文档导航，没有账号区、没有作用域切换。内容仍然一个字节不动，变的是它外面套的那一层。

这条因此反过来约束内容：**任何依赖"读者已登录"的东西都不能写进文档区**——"你当前的权限码"这类只有登录者才有的内容一旦进去，那次放出去就会变成一次内容重写。这是 3 条衡量标准里唯一一条靠人守的。

## 章节与外部入口

| 入口 | 路径 | 是什么 | 内容归属 |
|------|------|--------|---------|
| 命令行 | `/docs/cli` | **一章**：前端的一页 | [../cli/install.md](../cli/install.md) |
| 接口参考 | `/api-docs/` | **外链**：生成出来的静态页 | [../api-docs/README.md](../api-docs/README.md) |

导航**只有一项**（「文档」→ `/docs`）：东西是往区域里加，不是往导航里加。

### 为什么接口参考只是一条链接

它是 proto 的派生物，由 `make api-docs` 生成、由静态目录直接服务（见 [../api-docs/README.md](../api-docs/README.md)）：不随主题走，也不需要进路由。把它嵌成一页会**把它关进登录墙**——而它现在的读者恰恰是外部调用方，那些人没有 aladdin 账号。所以在本区放出去之前，它只能是一条链接。

**那条链接必须是普通 `<a>`，不能用路由的 `Link`。** `/api-docs/` 不在路由表里：`Link` 会让 React Router 接住这次跳转、匹配不到路由、落到 `*` 的兜底上，表现是"点了接口文档却回到了首页"——**而且没有任何报错**。

**路径写相对的 `/api-docs/`**：绝对地址会把部署实例的域名写进仓库（见 [../../deploy.md](../../deploy.md) 的可验证性表）。这条路径另有两处随它一起定：`web/public/api-docs/` 这个目录名，以及 dev 下 vite 的目录 rewrite（生产由 nginx 的 `try_files` 兜，dev 没有它就会落到业务前端的 SPA 兜底上）。

### 加一章

**要同时改两处**：索引页的清单与路由表的子路由。两处各只有一行，因此不为它抽一层"章节注册表"——两份定义比一处手写更容易漂，等章节真的多起来再抽。

## 可验证性与长程执行

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 索引与路由不漂 | 索引页指向的路径就是路由表里那一条（`DocsIndexPage` 测试） |
| 外链不被 SPA 接走 | 点接口参考那条链接不会落到路由的兜底上（`DocsIndexPage` 测试） |
| 零权限也进得去 | 已认证即可打开（`AppLayout` 测试 + 人工冒烟） |
| 进子页时父项仍高亮 | 在 `/docs/cli` 上导航的「文档」是选中态（`AppLayout` 测试） |
| 接口参考打得开 | 部署后人工冒烟：从索引点过去能看到 Redoc 渲染的接口列表 |
| 内容不依赖登录 | **人工核对**：正文里没有只有登录者才有的东西（这是"放出去只改准入"的前提） |
