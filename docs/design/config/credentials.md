# 凭证

## 背景与目标

描述 CLI 侧凭证的**持久化与保护**：以什么形式存在磁盘上、权限要求是什么、什么情况下拒绝使用、什么时候被写入与清除。

凭证与配置同属"CLI 运行所需的外部输入"，但两者的保护级别不同，这是本子模块独立存在的原因：

| | 普通配置 | 凭证 |
|---|---------|------|
| 出现在版本库 | 可以提交 | 绝不可以 |
| 出现在容器镜像 | 可以 | 绝不可以 |
| 出现在日志 | 可以（用于确认生效值） | 绝不可以，任何级别 |
| 贴给别人排查问题 | 可以 | 绝不可以 |
| 文件权限 | 无强制要求 | 强制仅属主可读 |

把凭证降级为"配置里的一项"，等于让它继承配置的传播习惯——而配置的传播习惯就是共享。因此凭证单独存储、单独校验权限、单独规定不得外泄。

> 凭证的**来源优先级**（参数 > 环境变量 > 凭证文件）与来源缺失时的提示语义，其唯一信源是 [../rbac/cli-permissions.md](../rbac/cli-permissions.md)。本文件只描述凭证**落盘**这一形态：格式、位置、权限、写入与清除。

## 功能行为

### 存放位置与权限

凭证存放在用户配置目录下的 `aladdin/credentials.json`（与 CLI 的 `config.yml` 同目录，但不同文件）。

| 对象 | 要求的权限 |
|------|-----------|
| 存放目录 | 仅属主可进入与列出 |
| 凭证文件 | 仅属主可读写 |

权限不满足要求时，CLI **拒绝使用该凭证并以错误退出**，而不是"打印警告后继续"。警告在实践中一定会被忽略，而继续使用意味着宽权限窗口期内凭证可能已被复制——此时正确的动作是失效该凭证并重新登录，而不是假装没发生。错误信息中必须给出当前权限与期望权限，以及文件路径。

### 内容

凭证文件中包含：访问令牌、该令牌绑定的作用域、过期时间。

- 作用域**绑定在凭证上**，不来自配置文件。这是"配置不得授予作用域"这条约束在凭证侧的具体体现（见 [README.md](README.md) 的"配置不得成为权限的来源"）。
- 过期时间缺失时，该凭证被视为**不会因本地判断而过期**，其有效性完全由服务端判定。

### 写入

凭证在登录成功后写入。

行为要求：

- **写入要么完整成功，要么保持原值**。写入过程中断（磁盘满、进程被杀）不得产出内容截断的凭证文件——一个半截的令牌会以"未认证"的形式暴露，而用户无法从提示中看出真正原因是磁盘问题。
- **不产生短暂的宽权限窗口**。文件从被创建的那一刻起就必须是不可被其他用户读取的，不存在"先建好再收紧权限"的中间状态。
- 写入失败时，失败原因必须明确报告，且不得以"登录成功"提示收尾。

### 清除

- 用户在 CLI 侧登出时，本地凭证文件被删除。
- **本地删除不等于服务端撤销**：本地删除只是让 CLI 找不到凭证，已泄露的令牌在服务端仍然有效直到被服务端失效。因此登出完成后应提示这一点，避免用户误以为"登出即失效"。
- 服务端撤销令牌后，CLI 在下次调用时得到"未认证"结论；CLI 不缓存任何判定结果，因此不存在"服务端已撤销、CLI 仍放行"的窗口（见 [../rbac/cli-permissions.md](../rbac/cli-permissions.md)）。

### 不得外泄的位置

凭证值**不得**出现在以下任何位置：

| 位置 | 原因 |
|------|------|
| 任何级别的日志 | 日志会被采集、转发、长期保留 |
| 错误信息与堆栈 | 错误常被贴进工单与聊天窗口 |
| `--debug` 输出 | 该开关的使用场景恰是排查故障，此时最容易被整段复制 |
| 崩溃转储与调试输出 | 同上，且更难清理 |

命令行参数传入凭证这一来源被保留（CI 与无人值守场景需要它，见 [../rbac/cli-permissions.md](../rbac/cli-permissions.md)），但代价是**该值对同机的其他用户通过进程列表可见**。这是已知的取舍，因此附加两条约束：

- CLI 不得回显参数传入的令牌，也不得在提示用户改用其他方式时把值填进提示文本。
- `--debug` 输出凭证的**来源标识**（哪个文件、哪个环境变量、哪个参数）而不是**值**。

配置文件中**不得**出现令牌字段。凭证若可通过 `config.yml` 提供，就等于让它进入版本库与镜像。

## 边界与约束

本模块**明确不处理**：

- **令牌的签发与刷新**。属于身份认证模块；CLI 只消费凭证，过期后引导重新登录。
- **凭证的加密存储**。不引入密钥管理服务或本地加密：加密所需的密钥若与凭证同机存放，只是把问题推后一步。凭证的保护依赖文件权限与不落日志。
- **系统钥匙串集成**。接入平台钥匙串会引入平台相关实现与无人值守场景下的额外失败路径；CI 与容器环境仍须回退到环境变量，等于两套机制并存。（如后续引入，需先明确"无钥匙串环境"的降级语义。）
- **多环境凭证的并存**。同一时刻只有一个凭证文件，切换环境通过环境变量或命令行参数传入，不做凭证的按环境分组存放。

约束：

- 凭证的解析与落盘只有一处实现，其他模块不得自行读写凭证文件。
- CLI 不提供任何"忽略凭证检查"的开关。

## 可验证性与长程执行

**非长程任务，无需中途校验。** 凭证在一次命令执行内解析完成。需要长期保证的是保护措施不被绕过：

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 权限过宽即拒绝 | 放宽凭证文件权限后调用失败，且错误信息含期望权限（`internal/auth` 测试） |
| 创建即受限 | 凭证文件创建后权限即为 0600、目录为 0700（`internal/auth` 测试） |
| 写入不产出半截值 | 目录不可写时写入失败，且原凭证仍可用；不残留临时文件（`internal/auth` 测试） |
| 不落日志 | 解析失败的错误信息不含凭证原文（`internal/auth` 测试）；`--debug` 输出经冒烟检查 |
| 只报来源 | 来源标识不含令牌（`internal/auth` 测试） |
| 不在参数中回显 | 令牌不作为任何参数的默认值或帮助文本出现（静态检查） |
| 配置中无令牌字段 | 配置文件的键集合里没有承载令牌的键（`internal/config` 测试：键集合与示例一致） |
| 过期判定本地化 | 本地过期判断只依据凭证自身的时间字段；未设过期时间时不判过期（`internal/auth` 测试） |

## 依赖关系

| 依赖对象 | 交互方式 |
|---------|---------|
| 身份认证 | 登录时由服务端签发令牌；CLI 不实现签发与刷新 |
| CLI 配置 | 与配置文件同目录，但不共用文件；配置不承载凭证 |
| RBAC / CLI 接入 | 凭证的来源优先级与"未认证 vs 权限不足"的区分语义由 [../rbac/cli-permissions.md](../rbac/cli-permissions.md) 定义 |
| 配置加载（父模块） | 复用其"缺失与错误的处理"取向：默认位置缺失不报错、格式非法必须报错 |

|------|---------|-------------|
| 凭证文件权限过宽时的退出码类别 | 归入"未认证"（**已定**）：脚本重新登录即会以正确权限重写文件，可自愈 | 只影响退出码映射；若归入"用法错误"则脚本不会自动重试 |
| 是否引入系统钥匙串 | 不引入，保持单一文件 + 环境变量两条路径 | 影响凭证读写入口与 CI 场景的降级语义 |
