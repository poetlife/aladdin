# 服务端配置

## 背景与目标

描述服务端进程在启动时读取哪些配置、从哪读、读不到时用什么值，以及什么情况下**拒绝启动**。

服务端的配置有一个与其他模块不同的特点：它在进程启动的最开始被消费，因此配置错误必须在启动阶段就终止进程并给出可操作的提示，而不是"带着半套配置启动，等第一个请求进来才暴露问题"。一个配置错误导致服务端监听在错误的地址上，比直接启动失败危险得多——后者立刻可见，前者要等到有人发现连不上。

## 功能行为

### 配置项

| 配置键 | 含义 | 内置默认值 |
|--------|------|-----------|
| `address` | **监听**地址（`host:port`） | `127.0.0.1:9090` |
| `log_level` | 日志级别，取值集合与 [observability.md](../../observability.md) 一致 | `info` |
| `log_file` | 日志文件路径；为空表示写标准错误 | 空（写标准错误） |
| `database_driver` | 数据库后端，取值集合见 [../persistence/README.md](../persistence/README.md) | `sqlite` |
| `database_dsn` | 数据库连接串，形状随后端而异 | `aladdin.db` |
| `cos_bucket_url` | 头像存放的 COS 桶地址（含 APPID 与地域的完整主机名）；为空表示**未启用**头像 | 空 |
| `google_client_id` | Google 登录的客户端标识；为空表示**未启用**该登录方式 | 空 |
| `github_client_id` | GitHub 登录的客户端标识；为空表示**未启用**该登录方式 | 空 |
| `public_base_url` | 服务端的**对外地址**，用于构造重定向型登录的回调与回跳地址；配置了重定向型渠道时必填 | 空 |
| `bootstrap_admin_subject` | 引导时用来指认主体的**主体标识**；与 `bootstrap_admin_email` 互斥 | 空 |
| `bootstrap_admin_email` | 引导时用来指认主体的**邮箱**，按已登记身份查、恰好命中一个才生效；与 `bootstrap_admin_subject` 互斥 | 空 |
| `bootstrap_admin_scope` | 引导授予的作用域；写 `<global>` 表示全局作用域 | 空 |
| `otel_endpoint` | OTLP/HTTP 端点（`host:port`）；为空表示不上报，只生成与传播链路标识 | 空 |
| `otel_insecure` | 是否用明文 HTTP 连接该端点 | `false` |
| `otel_sample_ratio` | 采样比例，取值 0–1 | `1` |

后三项与 CLI 同名同义，见 [observability.md](../../observability.md) 的"配置项"。它们的存在不使上报成为必需：端点为空时服务端照常生成、传播与回写链路标识，只是 trace 与指标不上报。

默认监听 `127.0.0.1` 而不是 `0.0.0.0`：默认配置下服务端**不对外暴露**，要对外提供服务必须显式改动这一项。这个默认值的取向是"忘记改的后果是连不上，而不是被扫到"。

`database_driver` 与 `database_dsn` 描述进程把数据存在哪。它们的取值集合、连接串的两种形态与失败语义见 [../persistence/schema.md](../persistence/schema.md)。

**连接串可能含口令，因此它不进日志。** 这一项与配置模块的"配置可以进启动日志、凭证不可以"是同一条规则的两面：连接串在本端的地位等同于 CLIENT 端的凭证文件。启动日志里出现的是脱敏摘要——后端类型与不含口令的定位信息，足以回答"我改的那一行到底有没有被读到"。

### 头像存储

`cos_bucket_url` 指向一个腾讯云 COS 桶，头像字节存在那里（见 [../profile/avatar-storage.md](../profile/avatar-storage.md)）。它是完整的桶主机名，形如 `https://<桶名>-<APPID>.cos.<地域>.myqcloud.com`。

**密钥不是配置键，只从环境变量读。** 需要两项：`ALADDIN_COS_SECRET_ID` 与 `ALADDIN_COS_SECRET_KEY`。

把它们做成配置键，就等于允许它们出现在 `config.yml` 里，而那个文件会进版本库、进镜像、被贴给别人排查问题——这正是 [credentials.md](credentials.md) 划出的界线："配置文件中不得出现令牌字段。"桶地址不是秘密（它只是一个主机名，没有签名取不到东西），因此它留在配置文件里。

这与开发种子旁路"只从环境变量开启、不在 `config.yml` 提供键"是同一种做法，理由也相同：**一个开关一旦能写进配置文件，它就会在某个人手上的生产环境里被写进去。**

| 情形 | 行为 |
|------|------|
| 桶地址与密钥都为空 | 不启用头像。这是默认情形，服务端照常启动 |
| 桶地址非空，两项密钥都在 | 启用头像 |
| 桶地址非空，缺任一项密钥 | **拒绝启动**，信息里指出缺的是哪一项 |
| 两项密钥都在，桶地址为空 | **拒绝启动**：密钥有主、桶没主 |
| 桶地址不是合法的 https 地址 | **拒绝启动** |

> 头像未启用**不影响**昵称与简介：档案的其余部分照常可用，前端只是不渲染头像上传区（见 [../profile/README.md](../profile/README.md)）。

**密钥不进启动日志，也不进任何错误信息与脱敏摘要。** 桶地址进启动日志——它与数据库的定位信息同类，用来回答"我改的那一行到底有没有被读到"。

### 登录方式

登录渠道分两类，它们的配置要求不同（见 [../identity/channel-login.md](../identity/channel-login.md)）。

**搬运型（Google）**：`google_client_id` 为空表示**未启用** Google 登录，前端据此不渲染登录入口。这个值明文出现在浏览器里，**不是秘密**——这是这类登录方式的设计前提，不是疏漏。因此它放在配置文件里不违反"配置中不得出现凭证"：真正需要保密的是客户端密钥，而这条路径不使用它（见 [../identity/google-login.md](../identity/google-login.md)）。

**重定向型（GitHub）**：需要三项，见下。

**浏览器来源白名单没有对应的配置键，也不应该有。** 它只配置在渠道侧的控制台（Google 控制台的来源白名单、GitHub 的授权回调地址）。理由是它不改变服务端的任何行为——来源不匹配时请求根本到不了服务端。在这里再放一份，只会得到一份永远不会被读到、却会在迁移部署时被误改的副本。部署到新域名时改的是渠道控制台，这一条要写进部署说明，否则表现为"换了域名之后登录按钮点了没反应"。

#### 重定向型渠道

`github_client_id` 为空表示**未启用** GitHub 登录。启用它还需要另外两项：

| 取值 | 从哪来 | 是不是秘密 |
|------|--------|-----------|
| `github_client_id` | 配置文件 | 不是。它明文出现在浏览器里 |
| `public_base_url` | 配置文件 | 不是。它只是一个主机名 |
| `ALADDIN_GITHUB_CLIENT_SECRET` | **只从环境变量读** | **是**。它是真密钥 |

**客户端密钥照头像密钥那一套办**（见"头像存储"）：不做成配置键、不进启动日志、不进任何错误信息与 `--debug` 输出。理由逐字相同。

`public_base_url` 是服务端的**对外地址**，用来构造交给渠道的回调地址与回跳前端的地址。它必须由配置给出，**不得由请求头推导**——用请求头构造跳转目标等于给攻击者一个把会话凭证送到任意主机的原语（见 [../identity/github-login.md](../identity/github-login.md)）。

| 情形 | 行为 |
|------|------|
| 三项都为空 | 不启用 GitHub 登录。这是默认情形 |
| 三项齐全 | 启用 GitHub 登录 |
| 只给出其中一部分 | **拒绝启动**，信息里指出缺的是哪一项 |

取值本身的要求：必须是**绝对 URL**、有主机名、不带用户信息、不带查询串与 fragment，且**路径必须为空或只有 `/`**——带路径前缀会衍生出一个同样要登记在渠道控制台里的回调地址，是一个只在部署时才暴露的陷阱。协议必须是 https，**唯一例外是本地回环主机**（`localhost` / `127.0.0.1` / `::1`）允许 http，使本地开发无需证书。

### 引导第一个管理员

身份指认（`bootstrap_admin_subject` 或 `bootstrap_admin_email`）与 `bootstrap_admin_scope` 在**存储中不存在任何角色绑定**时，建立第一条绑定。

**它不是判定路径的输入。** 建立的是真实的角色绑定，判定路径只读存储、从不读配置；生效之后这些键就可以删掉，删掉**不**撤销已经建立的绑定。四条边界见 [README.md](README.md) 的"唯一例外：引导"与 [CLAUDE.md](../../../CLAUDE.md) 第 7 条。

#### 怎么指认主体

两种写法，**互斥**：

| 写法 | 取值 | 生效方式 |
|------|------|---------|
| `bootstrap_admin_subject` | 主体标识 | 原样使用，不推导、不规范 |
| `bootstrap_admin_email` | 邮箱 | 在该邮箱**已登记的身份**里查，取用其主体 |

邮箱那条是**引导专属的窄口子**，要满足三个条件才算成立：

1. **只认已登记的身份。** 邮箱与主体的对应关系是登录时才产生的，所以用它指认主体**必须先有一次真实登录**。它不去凭空造一个主体——写下邮箱就等于授权给一个还不存在的身份，那种"看起来生效了"正是要避免的。
2. **命中数必须恰好是一个。** 同一个邮箱字符串可以分别挂在两个身份上（刻意允许，见 [../identity/README.md](../identity/README.md)），所以按邮箱查主体可能得到 0 个或 2 个。**不是恰好一个就拒绝启动**并说明命中了几个——猜一个等于把一次配置错误变成一次无声授权。
3. **绑定落在主体上。** 解析只发生一次，写入的是主体标识上的绑定，此后邮箱不参与任何判定。它不构成"身份可以按邮箱确定"的先例：登录与绑定两条路径仍只认渠道签发的不可变标识。

登录后主体标识**界面上就显示**（侧边栏账号区与首页各一处），不必去日志里找。

#### 作用域怎么写

`bootstrap_admin_scope` 必须显式给出。全局作用域在内部的值是空串，而空串在配置里表示"没填"——两者不能共用一种写法，否则一次手滑漏填就会静默变成全局管理员。因此全局作用域写成字面量 **`<global>`**，与 `rbac.Scope.String()` 的输出一致。

| 情形 | 行为 |
|------|------|
| 身份指认与作用域都为空 | 不引导。这是默认情形 |
| 都给出，且存储中没有任何绑定 | 解析主体、建立绑定，并以 `warn` 级别留痕 |
| 都给出，但存储中已有绑定 | **不生效**。已有绑定不受影响 |
| 两者只填一个 | **拒绝启动** |
| 两种身份指认同时给出 | **拒绝启动** |
| 邮箱命中 0 个或多个已登记身份 | **拒绝启动**，信息里含命中数 |

取值必须是**主体标识**，或是**已登记身份的邮箱**；不是渠道上的身份标识（Google 的 `sub`）——理由见 [../identity/channel-login.md](../identity/channel-login.md)。

"两者只填一个即拒绝启动"与下面种子旁路"四项齐全才生效"是同一取向：**半套配置一律拒绝启动**。半套引导的失败方式是"看起来生效了"——它要么建了一条作用域不明的绑定，要么建了一条主体不明的绑定，而这两种都不会在启动时说任何话。

### 配置文件的查找

按以下顺序确定要读的文件，先命中者胜出：

1. 命令行参数 `-config` 显式指定的路径
2. 环境变量 `ALADDIN_CONFIG` 指定的路径
3. 启动时的工作目录下的 `config.yml`
4. 以上都不存在视为"无配置文件"，全部使用内置默认值启动

查找顺序不包含系统级路径（如 `/etc` 下的固定位置）。理由是：读一个用户没有显式指定的、位于启动目录之外的文件，会让"配置为什么不生效"变成一个需要猜的问题。需要在生产环境从固定位置读取时，由服务单元的启动参数显式指定。

服务端除配置文件路径外**没有取值类参数**——需要临时改地址或日志级别时用环境变量或配置文件。这是刻意的：服务端进程通常由编排系统拉起，多一条只在手工启动时用得上的参数，就多一条与部署配置不一致的路径。

### 校验与拒绝启动

配置在监听端口打开**之前**完成校验。校验失败时进程以非零退出码终止，错误信息中必须包含出错的配置键与当前取值。

以下情形必须拒绝启动：

- `address` 不是合法的 `host:port`、端口不是数字、端口超出 0–65535、或**主机名为空**
- `log_level` 不在允许的取值集合内
- `database_driver` 不在允许的取值集合内，或 `database_dsn` 为空
- `cos_bucket_url` 不是合法的 https 地址
- `cos_bucket_url` 非空而 COS 的任一项密钥缺失（半套头像配置）
- COS 的两项密钥都存在而 `cos_bucket_url` 为空（半套头像配置：密钥有主、桶没主）
- `public_base_url` 非空但不是合法取值（见"重定向型渠道"）
- 重定向型渠道的三项（`github_client_id`、`public_base_url`、客户端密钥）只给出其中一部分（半套登录配置）
- `bootstrap_admin_subject` 与 `bootstrap_admin_email` **同时给出**（不知道以谁为准）
- `bootstrap_admin_email` 与 `bootstrap_admin_subject` 都为空，而 `bootstrap_admin_scope` 非空（作用域有主、主体没主）
- 身份指认非空而 `bootstrap_admin_scope` 为空（半套引导）
- 显式指定的配置文件不存在
- 配置文件格式非法、顶层不是键值映射、或含有无法识别的键
- 配置文件中出现**只对 CLI 有意义**的键（如 `timeout`）

数据库后端与连接串的**深层校验**（路径是否可用、连接串能否解析、能否连上、结构版本是否落后）发生在建立连接与执行迁移时，仍在监听端口打开之前。校验失败同样是拒绝启动，错误信息包含后端类型与脱敏后的定位信息。

主机名为空（`:9090`）被拒绝而不是解释成"监听所有网卡"：后者是 Go 的语义，但读起来像是"随便哪个网卡"，与"默认配置不对外暴露"的取向冲突。要对外提供服务就显式写 `0.0.0.0:9090`。

端口允许为 0：它表示"由系统分配端口"，端到端测试依赖这一点。

以下情形**不**拒绝启动：

- 默认位置的配置文件不存在（全部使用内置默认值）
- `log_file` 指向的路径暂时不可写——这一项在进程内首次写日志时才会暴露，且日志系统自身的失败不得导致服务端退出（否则"日志写不进去"会升级为"服务不可用"）

### 生效值的可见性

启动时必须输出一条包含最终生效配置的日志（**不含凭证，配置中也不应有凭证，环境变量里的凭证同样不出现**），至少包含监听地址、日志级别、数据库后端与脱敏后的定位信息、头像存储是否启用（含桶地址，不含密钥），以及**已启用的登录渠道与对外地址**。这条日志的作用是回答"我改的那个文件到底有没有被读到"——这是配置类问题排查中最高频的疑问，而它无法从"服务能启动"这个事实中推断出来。数据库这一项尤其如此：连到另一个库的表现形式是"数据看起来全丢了"，不写出来就只能靠猜。

### 开发用种子数据不属于配置体系

`make dev` 使用的开发种子数据通过一组**独立命名的环境变量**开启，不在 `config.yml` 中提供对应键。理由：

- 它是一个绕过真实认证的旁路，把它做成配置文件里的一个布尔开关，等于让"生产环境误开旁路"变成一次误编辑。
- 它同时要求"令牌、主体、角色、作用域"四项齐全，缺一即启动失败。半套种子数据比没有更危险——开发者会以为权限已经生效。
- 开启时必须以 `warn` 级别留下显著记录，使得"生产日志里出现这条"本身就是一个可告警的信号。

**它与引导的分工，在数据落库之后必须说清楚。**

种子旁路曾经是纯内存的：进程重启，写进去的东西就没了，因此"生产环境误开"的后果止于本次进程的生命周期。**现在不是了。** 主体与绑定会落库，一次误开在库里留下的是长期存在的真实数据，而且**取消环境变量不会清除它们**——下一次启动什么都不会发生，看起来像是"没有生效"，实际是"早就写进去了"。

| | 种子旁路 | 引导 |
|--|---------|------|
| 面向 | 本地开发要一个假环境 | 生产建立第一个真管理员 |
| 主体来源 | 环境变量里写死的假标识 | 认证流程登记的真实主体标识（见 [../identity/channel-login.md](../identity/channel-login.md)） |
| 生效条件 | 四项齐全 | 存储中无任何绑定，且两个键都非空 |
| 是否留痕 | `warn` 级 | `warn` 级 |
| 如何撤销 | 删掉库文件重建 | 无需撤销：它本就只该生效一次 |

**本地开发想要一个干净的环境时，删掉库文件再启动，而不是指望取消环境变量。** 这一条要写进开发说明，否则"我明明取消了种子变量，为什么这个角色还在"会是第一个被问到的问题。

该旁路在接入真实认证后应整体删除。

## 边界与约束

- 不处理配置热重载：修改配置后需要重启进程。
- 不提供任何"跳过鉴权""信任该来源"的开关。
- 不读系统级固定路径的配置文件。
- 配置项只描述"进程如何运行"：数据库**存在哪**由本端决定，数据库**里存的是什么结构**由 [../persistence/](../persistence/README.md) 决定。集群拓扑、副本数这类部署形态的编排内容不在这里。

## 可验证性与长程执行

**非长程任务，无需中途校验。** 配置解析在启动时一次完成。需要长期保证的是"校验在监听之前发生"这一顺序：

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 校验先于监听 | 逻辑上成立：校验发生在装配服务端与打开监听之前。校验失败时进程在 `Listen` 之前就已返回错误 |
| 默认不对外 | 内置默认地址断言为回环地址（`internal/config` 测试） |
| 默认值可启动 | 无配置文件、无环境变量时配置加载成功，且默认后端为 sqlite、默认路径在工作目录（`internal/config` 测试） |
| 生效值可见 | 启动日志中含最终监听地址、日志级别、数据库后端与脱敏定位信息（启动冒烟检查） |
| 错误信息可操作 | 校验失败的提示包含出错的键名（`internal/config` 测试） |
| 键集合严格 | 拼错的键、只对 CLI 有意义的键、顶层不是映射，均报错（`internal/config` 测试） |
| 后端取值封闭 | 未登记的 `database_driver` 取值被拒绝，错误信息含取值与合法集合（`internal/config` 测试） |
| 连接串不入日志 | 含口令的连接串不出现在启动日志、错误信息与脱敏摘要中（`internal/database` 测试 + 启动冒烟） |
| 种子数据四项齐全 | 只设置部分种子变量时启动失败（待补自动化测试，当前为人工约定） |
| 引导半套拒绝启动 | 身份指认与作用域只填一个时启动失败，错误信息指出缺的是哪一个（`internal/config` 测试） |
| 两种身份指认互斥 | 主体标识与邮箱同时给出时启动失败（`internal/config` 测试） |
| 引导一次性 | 存储中已存在绑定时引导不生效，且已有绑定一字不变（`internal/server` 测试） |
| 引导物化 | 引导生效后删掉配置键重启，已建立的绑定仍然存在且判定结果不变（`internal/server` 测试） |
| 引导按主体标识 | 主体标识被**原样**使用，不经过任何推导或规范化（`internal/server` 测试） |
| 引导按邮箱解析 | 邮箱恰好命中一个已登记身份时取用其主体；命中 0 个或多个一律拒绝启动，信息含命中数（`internal/server` 测试） |
| 引导不凭空造主体 | 邮箱未命中已登记身份时**不登记**任何主体（`internal/server` 测试） |
| 全局作用域可表达 | `bootstrap_admin_scope: "<global>"` 解析为全局作用域并建立全局绑定（`internal/config` 与 `internal/server` 测试） |
| 引导留痕 | 生效时产出 `warn` 级日志，含被授予的主体与作用域（`internal/server` 测试） |
| 登录方式可缺省 | `google_client_id` 为空时不构成一条可用的登录方式，且不影响其余配置加载（`internal/config` 测试） |
| 头像可缺省 | 桶地址与密钥都为空时不构成一条可用的头像存储，且不影响其余配置加载（`internal/config` 测试）；此时昵称与简介照常可用（`internal/profile` 测试） |
| 头像半套拒绝启动 | 只配桶地址、或只配密钥时启动失败，错误信息指出缺的是哪一项（`internal/config` 测试） |
| 密钥不入日志 | 启动日志、错误信息与脱敏摘要中不出现 COS 密钥与 GitHub 客户端密钥（`internal/config` 测试 + 启动冒烟） |
| 密钥不可由配置提供 | 配置文件的键集合里没有承载 COS 密钥或 GitHub 客户端密钥的键（`internal/config` 测试：键集合与示例一致） |
| 重定向型渠道半套拒绝启动 | 客户端标识、客户端密钥、对外源三者只给出一部分时启动失败，信息里指出缺的是哪一项（`internal/config` 测试） |
| 对外源不得带路径 | 对外源带路径前缀时启动失败；本地回环主机允许 http、其它主机要求 https（`internal/config` 测试） |
| 登录配置是否被读到 | 启动日志里列出已启用的登录渠道与对外地址，且不含任何密钥（启动冒烟） |
