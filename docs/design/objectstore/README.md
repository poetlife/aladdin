# 对象存储直传

> 本文档是**"用户上传的字节怎么进对象存储"**的唯一信源，被个人档案（头像）与 galaxy（资产）两处消费。
> 它描述的是**一个公共机制**，不是某个模块的特性——两处各写一份的表现是"换一个模块上传，安全性质就变了一套"。

## 背景与目标

头像与 galaxy 资产都要把一段用户给的二进制放进对象存储。原本的做法是**字节经服务端转存**：请求体带字节，服务端收下来再写进桶。

这条路有三个代价，随着上限提高（头像 2 MiB、资产最高 100 MiB）而被放大：

1. **服务端带宽翻倍**：同一份字节被收一遍、再送出去一遍。
2. **服务端内存被整份占住**：一个 100 MiB 的视频上传要在服务端内存里放一份完整副本，并发上传时线性叠加。
3. **两处各写一遍**：头像与资产是同一个动作的两个实现，差别只在键规则与上限，而"上传这条链路怎么走"本该只有一处。

因此改为**直传**：服务端用长期密钥向对象存储的临时凭证服务换取一份**被策略限定过的临时凭证**，交给客户端；字节从浏览器直接进入对象存储。

成功的衡量标准：

1. 上传的字节**不经过服务端**：服务端只在签发与提交两步参与，不接触字节。
2. 临时凭证**只对一个键、只允许写、短时有效**：拿到它的人不能读、不能写别的键、不能替换别的对象，**也不能对那个对象声明任何权限**（不能设为公开、不能授权给他人）。
3. 每一次上传的键都由服务端分配且**不复用**，因此"替换一个已存在的对象"在存储层就不成立。
4. **超过大小上限、或类型不在白名单内的上传被存储侧拒绝**，不产生任何对象。
5. 提交时服务端对键做一次存在性与字节数的核对，核对不通过则该对象被删除。
6. 未提交的对象不会进入任何清单，也不会被任何读取路径看到。

## 功能行为

### 三步：签发、直传、提交

| 步骤 | 谁做 | 做什么 |
|------|------|--------|
| 1. 签发 | 服务端 | 分配一个键，向临时凭证服务换取一份**只对该键、只允许写、带类型与大小条件**的短时凭证 |
| 2. 直传 | 客户端 | 用那份凭证把字节写到那个键上（服务端不参与） |
| 3. 提交 | 服务端 | 对那个键做一次 Head，核对存在性与字节数，写入元数据行 |

**签发与提交各自都要过鉴权**：签发决定"谁可以往哪个键写"，提交决定"这条上传记到谁的名下"。两者是同一个资源上的两次操作，不是一次拆成两半。

**第 2 步在两端各有一份实现，共享的是形状而不是代码。** 直传发生在客户端与对象存储之间，而客户端有两个：浏览器与命令行（见 [galaxy/cli.md](../galaxy/cli.md)）。两者读的是**同一份凭证定义**（`DirectUploadCredential`），实现在各自的语言里——跨语言共享不了代码，能共享的正是那份形状。**不得出现第三种形状**：换一个端上传就换一套凭证字段，是这条链路最贵的漂移。

**约束落在存储侧，不落在客户端自觉。** 类型与大小上限写进临时凭证的策略里，由对象存储执行：不合规的请求根本进不了桶。客户端是**不可信**的一方——这正是"服务端嗅探"被换掉之后仍然要有约束的原因。

### 键由服务端分配，且不复用

键的形状由各模块决定（头像一个主体一个键；资产一个工程一个标识），但**分配权在服务端**，且每次上传分配一个新的键。

由此得到两条：

- **临时凭证被钉死在一个键上**：策略的资源表达式就是那个键，客户端改不了它，因此拿到凭证的人只能写这一个键——写不了别人的、也写不了别的工程的。
- **"替换一个已存在的对象"在存储层不成立**：要覆盖就得写中另一个键，而凭证不是为那个键签发的。资产"不可变"由此多了一层存储侧的保证，而不是只靠服务端不提供替换接口。

这也是对象存储官方给出的防覆写指引：**由服务端决定上传路径**，而不是由客户端给文件名。

头像是这套规则的一个**明确例外**：一个主体一个键，替换就是原地覆盖。因此签发时对头像的键是"允许覆盖"的，而对资产的键是"只许创建一次"。这个差别属于各模块的键规则，不改本机制。

### 能读写什么：策略限定的动作与资源

临时凭证的策略只写一条允许项，其余一律默认拒绝：

| 项 | 取值 | 挡住什么 |
|----|------|---------|
| 动作 | 只允许写入对象 | 不能读、不能列举、不能删除 |
| 权限 | 只允许写字节，**不得能对对象声明任何权限** | 不能把对象设为公开读、不能把对象的所有权让给别的账号 |
| 资源 | 恰好一个对象键 | 不能碰别的工程、别人的对象 |
| 条件 | 见下 | 不合规的上传被拒绝 |

**"只允许写"是刻意的。** 能取字节的凭证在有效期内是一份谁拿到都能用的读取凭据，而上传路径不需要它。

**"不得能声明权限"是另一条独立的约束，不是"只允许写"的推论。** 对象存储把 ACL 与授权放在**写入请求的头**上（`x-cos-acl`、`x-cos-grant-*`），因此它们考的不是动作集合，而是同一动作上的请求头——只写 `PutObject` 并不自动涵盖它们（是否被单独判定由存储侧决定，见下面的核查表）。这条必须成立，是因为发布物的公开区与私有区在**同一个桶**里，"哪些对象是公开的"完全由权限声明决定：一旦上传路径能做这个声明，桶里就出现了一段没人审过的内容（见 [galaxy/asset-library.md](../galaxy/asset-library.md)）。

### 大小与类型：由存储侧对**声明**强制

策略里带两条条件，由对象存储执行：

| 条件 | 作用 |
|------|------|
| 请求体长度不超过该类别上限 | 超限的上传被拒绝，**不产生对象** |
| 声明的内容类型落在白名单内 | 白名单外的上传被拒绝，**不产生对象** |

**上限是分档的**：策略里可以按类型分别列条件，"图片档"与"视频档"各带自己的长度上限。因此"用视频的上限去卡图片"这件事在存储侧就不成立。

**关键限定：条件校验的是请求里声明的类型，不是字节本身。** 对象存储不做内容嗅探，因此一份字节完全可以顶着 `image/png` 的名字存进去。这条代价被白名单本身限制住：白名单里没有任何**可执行**的类型（没有 HTML、没有 SVG），而存下来的内容类型就来自这次声明——因此**公开区上的对象永远以一个无害类型下发**，浏览器不会把字节当作脚本执行。换句话说，白名单从"字节确实是图片"降级成了"下发时的类型必属一个无害集合"，而后者是这套链路仍然能成立的原因。

**它也不是"服务端看见过每一个字节"。** 服务端唯一一次读到字节是上架到公开区时（见下）。选择接受这一条，是因为带宽与内存的代价是**每次上传都付**，而类型被误声明的代价落在"用户看到一张裂图"——除非白名单里有可执行类型，而那是不允许的。

### 提交：存在性与真实字节数

签发之后，客户端传了什么、传没传完，服务端都不知道。因此提交做三件事：

1. **对键做一次 Head**：不存在则失败（上传没完成或已被清理）；
2. **取回真实字节数**并核对上限——存储侧已经挡过一道，这里是服务端自己的结论，用于写进元数据；
3. **写入元数据行**（摘要、类型、大小、原始文件名）。

核对不通过时**服务端删除那个对象**。

### 摘要（内容寻址的键）由上传方声明，上架时核对

资产的内容摘要是"同一份字节"的标识，公开区按它寻址。它同样由上传方声明——服务端没有字节可以算它。

**它在被使用之前会被核对**：上架到公开区时服务端必须读回私有区对象（它本来就要把字节搬到公开区），读回时算一遍摘要并与声明值比对，**不一致即拒绝发布**。因此一条假的摘要不会把公开区的地址指向别人的内容，它的表现形式是"这个版本发布不出来"。

### 未提交的对象

签发之后没有提交（客户端放弃、网络中断、页面被关掉）时，对象留在私有区，而**元数据行不存在**。由此：

- 它不出现在任何清单里，也不参与任何判定；
- 它无从被引用（引用用的是元数据行里的标识）；
- 它与本仓库已有的"孤儿对象"是同一类东西：库内的行是"存在什么"的权威，桶上可能留下多余的字节。回收见"待定决策"。

提交失败时服务端**主动删除**刚上传的对象；未提交则不会删——服务端不知道那次上传发生过，也不该去猜。

## 边界与约束

- **临时凭证只允许写**，不允许读、列举与删除，也不允许对对象声明权限（不能设为公开、不能让渡所有权）。
- **凭证短时有效**，量级为分钟到半小时（取值见各模块的键规则与"待定决策"）。
- **不提供"列出桶里有什么"的能力**：库内的元数据行是权威。
- **不做分片上传、断点续传**（见"待定决策"）。
- **上传方声明的一切都不构成判定输入**：类型、大小、摘要都不改变"谁能不能做什么"，它们只影响"这一份东西是什么"。
- **桶侧必须允许来自主应用源的跨域写入**：直传是浏览器发起的跨域请求，桶的 CORS 规则属于部署形态（见 [../../deploy.md](../../deploy.md)）。
- 存储凭证不是配置文件的键，只从环境变量读（见 [config/credentials.md](../config/credentials.md)）。

## 可验证性与长程执行

**非长程任务。** 签发与提交都是即时的同步操作；字节的传输发生在客户端与对象存储之间，不构成本模块的一次长程推进。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 凭证只指向给定的键 | 策略的资源表达式就是该对象键，不含通配到其它键的部分（`internal/objectstore/cosupload` 测试） |
| 凭证只允许写 | 策略的动作集合里只有写入对象（同上） |
| 凭证不得能声明权限 | 用当前策略签发的临时凭证，带 ACL 头（`x-cos-acl: public-read`）与授权头（`x-cos-grant-full-control`）各直传一次，两次都被存储侧拒绝，且对象未被设为公开（部署后冒烟） |
| 大小条件与类型条件都在策略里 | 策略含长度上界与白名单类型条件，且**按类别分档**（同上） |
| 凭证短时有效 | 换取时给出的有效期是分钟到半小时量级（同上） |
| 超出上限被存储侧拒绝 | 用一个声明小于实际的对象直传，存储侧拒绝且对象不存在（部署后冒烟） |
| 白名单外的类型被存储侧拒绝 | 用白名单外的类型直传被拒（部署后冒烟） |
| 类型不在白名单即拒绝签发 | 声明一个白名单外的类型时签发失败（`internal/profile`、`internal/galaxy` 测试） |
| 声明大小超过上限即拒绝签发 | 按声明大小早退，不产生凭证（同上） |
| 提交核对真实字节数 | 声明小于实际的对象提交失败且对象被删除（同上） |
| 提交核对存在性 | 对不存在的键提交失败（同上） |
| 摘要被核对 | 声明一个与实际字节不符的摘要，上架失败（`internal/galaxy` 测试） |
| 不联网即可测 | 对象存储访问藏在接口后面，测试注入假实现；测试断言的是**策略内容**而不是"桶真的照做了"（`internal/objectstore` 与两处模块测试） |
| 密钥不入日志 | 描述这项配置时只出桶地址、不出密钥（`internal/config` 测试） |

> **"桶真的照做了"只能在部署后冒烟里验。** 策略是否被存储正确执行，取决于桶侧与临时凭证服务的实现，离线测试只能固定"我们发出的策略是什么"。这两条边界必须分开写，否则会得到一份"测过了"的错觉。

## 依赖关系

| 依赖对象 | 交互方式 |
|---------|---------|
| 个人档案 — 头像 | 消费本机制：键为 `avatars/<主体标识>`，替换即原地覆盖（见 [profile/avatar-storage.md](../profile/avatar-storage.md)） |
| galaxy — 资产库 | 消费本机制：键为 `galaxy/<工程标识>/<资产标识>`，一次上传一个新键（见 [galaxy/asset-library.md](../galaxy/asset-library.md)） |
| 命令行 — galaxy | 消费本机制做资产直传：读的是与浏览器同一份凭证定义，实现在 [cmd/aladdin/direct-upload.go](../../../cmd/aladdin/direct-upload.go)（见 [galaxy/cli.md](../galaxy/cli.md)） |
| 腾讯云 STS（`GetFederationToken`） | 用长期密钥换取被策略限定的临时凭证 |
| 腾讯云 COS | **一个桶**：临时凭证的直传、Head、删除、签发读取地址；发布物的公开区对象也在这个桶里，靠逐对象的公开读与其余对象区分（见 [galaxy/asset-library.md](../galaxy/asset-library.md)） |
| 服务端配置 | 桶地址与启用与否；密钥只走环境变量 |
| 可观测性 | 签发与提交的留痕**不含字节与文件名** |
| 部署 | 桶的创建、**默认私有读写**、子账号最小权限、**桶侧 CORS**（浏览器直传需要它允许来自主应用源的写入）；公开读不由桶级策略给出，由发布的上架路径逐个对象设置 |

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 临时凭证的有效期取值 | 暂取换取接口的默认值（半小时量级）。要更短需自行调用凭证服务（该默认值在客户端库里是固定的，见"代码实现索引"）（**未定**） | 有效期越短，"凭证被转发出去"的窗口越小；代价是多一次换取 |
| 分片上传（大视频断点续传） | 暂不做（**未定**） | 引入多段提交与段合并，键的生命周期与孤儿判定跟着变 |
| 过期未提交对象的自动清理 | 暂不做。库内为权威，孤儿无从引用（**未定**） | 需要一个按前缀列举与对账的动作，与头像、资产的同类问题合并处理 |
| 上传进度与失败重试的呈现 | 归各端界面（**未定**） | 只影响界面 |
