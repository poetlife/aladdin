# skill — 纳管与同步

## 背景与目标

一个技能的内容来自**远端仓库**，不是平台里写出来的。本子模块定义"这一份远端内容怎么变成平台里的一个技能"，以及它此后怎么更新、怎么退回去、怎么消失。

它要回答的是四个具体问题：

1. 一个技能包**最少要有什么**才算数（否则纳管进来的会是一堆说不清用途的文件）；
2. 管理员给出的那个地址**凭什么可信**（服务端要按它发起出站请求，这是本仓库第一个由用户输入决定目标主机的路径）；
3. 更新与回滚的语义是什么；
4. 一次失败的纳管**留下了什么**。

成功的衡量标准：

1. 管理员给一个仓库地址（可选引用、可选子路径），拿到一个可检索的技能。
2. **校验失败时库里不留任何痕迹**：没有新技能行、没有新版本行、桶上没有为它写的新对象。
3. 一个版本一旦产生就不可变：同步产生新版本之后，旧版本读回来逐字不变。
4. 校验失败的错误**点名那一处**（哪一个路径、违反了哪一条），而不是"包不合法"。
5. 服务端只认 `github.com` 的仓库根形状，**取字节的地址由服务端自己拼**。
6. 整个过程**不往磁盘写任何东西**。

## 功能行为

### 一个技能包是什么

一个技能包是**一棵文件树**加**一份清单文件**。清单文件必须是包根的 `SKILL.md`：

```
SKILL.md                 ← 必需，且在包根
---
name: mono-color
description: 单色/双色编辑印刷风出图。当用户要…时使用。
---

正文……
```

`SKILL.md` 以一段 YAML frontmatter 开头（首行 `---`、下一个 `---` 之间的部分）。平台从中读两项：

| 字段 | 必需 | 约束 | 用途 |
|------|------|------|------|
| `name` | 是 | ≤ 64 字符，取值 `[a-z0-9-]` | 没有标题时的回退展示名（见 [catalog.md](catalog.md)） |
| `description` | 是 | ≤ 1024 字符 | **触发说明**：没有简介时的回退，也是"这个技能什么时候该被用上"的唯一答案 |

**其余 frontmatter 字段原样保留、不做解释。** 平台既不校验也不因它们而拒绝——它们属于这个技能的读者，不属于平台。frontmatter 之外的正文更是**逐字存储、逐字取回**，平台不解析它（见"边界与约束"）。

**包根以外的东西不属于这个包。** 指定了子路径时，子路径之上的一切（README、LICENSE、CI 配置、别的技能）都不进包。

### 收得下的文件

| 规则 | 判据 | 为什么 |
|------|------|--------|
| 是文本 | 合法 UTF-8，且不含 NUL 字节 | 平台分发的是能被读的字节。这条判据**按内容判**，不按扩展名判——扩展名白名单要回答的是"下发什么类型"，而这里要回答的是"这些字节是不是文本"，两个问题不是一件事 |
| 路径合法 | 相对路径、`/` 分隔、只含 URL 非保留字符、不含 `.` / `..` / 空段、不以 `/` 起止、≤ 512 字节 | 路径会出现在命令行参数与界面上；字符集收在非保留字符里，等于顺带消掉"同一个文件有两种写法"（`%2E` 与 `.`）这条只能靠规范化去覆盖的问题 |
| 路径唯一 | 互不相同，且**大小写不敏感地唯一** | 包会被取到大小写不敏感的文件系统上，两条只差大小写的路径在那里是同一个文件 |
| 没有链接 | 不接受符号链接与硬链接 | 链接把"这棵树"变成一张图，而包是一棵树（见"取回"） |

**大小与数量有上限，且是常量不是配置项**：≤ 200 个文件、单个文件 ≤ 256 KiB、全部合计 ≤ 2 MiB。做成配置项只会让"这个部署收得下的包"变成一个要在别处解释的事实，而它与任何部署形态无关。

**脚本类文本照收**（`.sh`、`.py`……）。收不收得下由"它是不是文本"决定，不由"它像不像会被执行"决定——**平台从不执行它**（见"边界与约束"）。按后者判会得到一条自相矛盾的规则：一份写着"运行 `build.sh`"的 README 与那个 `build.sh` 本身，没有任何理由前者收、后者不收。

### 来源的形状

| 项 | 必需 | 形状 |
|----|------|------|
| 仓库地址 | 是 | `https://github.com/<owner>/<repo>` |
| 引用（`ref`） | 否 | 分支 / 标签 / 提交标识，≤ 256 字符。**缺省是仓库的默认分支** |
| 子路径 | 否 | 包在仓库里的位置；缺省是仓库根 |

**仓库地址只认这一个形状，这是本模块的安全边界。** 服务端会按它发起一次出站请求，因此允许的取值必须窄到可以逐条列举：

- 主机必须是 `github.com`（**大小写不敏感，且不接受别的任何主机**——包括形如 `github.com.evil.example` 的取值，那是按后缀匹配会漏掉的一类）；
- 协议必须是 `https`；
- 路径必须恰好是两段（`owner` / `repo`），每段走字符白名单，非空且有长度上限；结尾的 `/` 与 `.git` 后缀允许；
- **不接受**用户信息、端口、查询串与 fragment；
- `https://github.com/<owner>/<repo>/tree/<ref>/<path>` 这类"网页上看来的地址"**明确拒绝**，并在错误信息里指出要改填 `ref` 与子路径——它看着合法，直接放行只会得到一句"仓库不存在"。

**取字节的地址由服务端自己拼。** 调用方给的是"哪个仓库的哪一段"，不是"去哪里取"——这条一旦松动，上面整张白名单就白写了（这正是 SSRF 的经典形态：校验的是用户给的那个地址，请求的是另一个）。

`ref` 与子路径也各有一层校验：`ref` 走字符白名单，子路径走与包内路径**同一条**形状校验（唯一入口），因此它不可能解析出包根之外的位置。

### 纳管：五步，前四步不写任何东西

```
① 解析地址 ─▶ ② 解析引用 ─▶ ③ 取回树 ─▶ ④ 校验包 ─▶ ⑤ 落地
   形状白名单      远端解析      流式解压      全过才走      字节 + 行 + 指针
   不发请求        提交标识      只取子路径                    （一个事务）
```

1. **解析地址**：按上一节的形状拆出仓库；不合法即拒，**这一步不发生任何出站请求**。
2. **解析引用**：把 `ref` 解析成一个提交标识（缺省用默认分支）。远端不可达、仓库不存在、引用不存在是三种不同的结论，要分开报。
3. **取回**：按那个提交取回整棵树的压缩包，**流式解压**，只保留子路径之下的条目。压缩包本身与解压后的内容都**不落地到磁盘**，且都有上限（压缩包 ≤ 32 MiB，解压累计 ≤ 8 MiB）——上限的意义是让一次纳管的最坏内存占用与最坏耗时都是有界的，而不是"看看远端有多大"。
4. **校验**：包契约的全部规则（见上）。任何一条不满足即拒，错误里**点名那一处**。
5. **落地**：按内容摘要写字节（仅当不存在时写入）→ 写技能行、版本行、标签行 → 指针指向新版本。**第 5 步是一个整体**：库里的三件事在同一个事务里完成，中途失败则技能仍处于"从未纳管"。

**桶上可能留下无引用的对象**：字节先写、行后写，若行写失败，那些对象就成了孤儿。它与"删除技能不删字节"是同一种残留，回收方式也相同（见 [README.md](README.md) 的待定决策）——**不为此引入两阶段提交**：孤儿对象的代价是几个字节，而两阶段提交带来的是一个要长期维护的中间状态。

### 同步：追远端，不删历史

同步的输入只有技能标识——**来源取自技能行，不接受调用方另给一个**（见下"来源不可改"）。

```
   解析引用 → 提交标识 ──与记录的相同──▶ 没有变化：不产生版本、不切指针、不留痕
                     └──不同──────────▶ 取回 → 校验 → 落新版本 → 切指针（一个事务）
```

- **没有变化时不产生版本。** 让"同步"在无事发生时也留一条记录，会让"这个技能上次真的更新是什么时候"变成一个看不出答案的问题。
- **有变化时旧版本留着。** 版本不可变且不删（见 [README.md](README.md) 的模块边界）。
- **失败时指针不动。** 校验没过、远端挂了，都只是"这一次没同步成功"，当前对外的那一份原样。
- **`ref` 是标签或提交时，同步永远得到"没有变化"**——它不是缺陷，是这种来源的应有之义。想持续跟进就用分支。

### 回滚：切指针

回滚把当前指针指向该技能的另一个版本。版本必须属于这个技能——不是"任意技能任意版本"。

**回滚之后再同步不会把指针挪回去。** 同步只在**远端有新提交**时动指针，而回滚不改变"已同步到哪个提交"（那是来源的记录，不是指针）。这条是刻意的，而且是一条安全性质：**一次习惯性的同步不该悄悄撤销一次刚做的回滚**。要回到最新就用回滚指向最新那一版——版本列表里它排在最前面。

反过来说，若把同步定义成"让指针追上远端"，那么任何一个跑 `sync` 的人（或将来某条定时任务）都能在无人察觉时取消一次回滚。代价只是"回最新"要多一条命令，而那条命令本来就有。

### 删除

删除一个技能，删掉它的全部行（技能、版本、标签、收藏、使用日次），**桶上的字节不删**。

**没有"停用"这个状态。** 要让它不可见就删除，要让一部分人看不见就用权限——一个"停用但保留数据"的状态会立刻引出"停用的技能还能不能取用旧版本""已收藏的人看到什么"这些没有好答案的问题（见 [README.md](README.md) 的状态流转）。

### 来源不可改

**接口面上没有"改来源"这个方法。** 换仓库、换引用、换子路径都要**重新纳管**，得到一个**新的技能**（新标识、新收藏、新使用记录）。

理由是版本与来源的关系：一个技能的历次版本被要求"是同一条来源的不同时间点"，否则"回滚"就变成"切到另一个东西的某个版本"，而那个语义没有人能解释。重新纳管而不是原地改，也让"我把这个技能的来源改坏了"这件事永远只影响一个新的技能。

### 超时与失败

**纳管与同步是同步操作，不是长程任务**：一次请求一次结论，没有进度、没有检查点、不重试。要重试就再发一次——它是幂等的（同样的来源与提交得到同样的版本内容）。

时长的边界由三处给出：单次远端请求的超时、压缩包上限、解压累计上限。三者合起来让最坏耗时与最坏内存都是有界的，而**不需要为整条流程再设一个总超时**——总超时会把"远端慢"与"远端挂了"变成同一个结论。

失败分三类，**它们在错误信息里必须分开**，因为应对完全不同：

| 类别 | 例子 | 应对 |
|------|------|------|
| 形状不合法 | 不是 `github.com` 的地址、ref 含非法字符 | 改调用参数（用法错误） |
| 远端侧不可得 | 仓库不存在、引用不存在、远端不可达、限频 | 稍后重试，或改引用 |
| 内容不通过 | 缺 `SKILL.md`、有二进制文件、超上限 | 改远端仓库 |

### 远端凭据

平台按环境变量 `ALADDIN_GITHUB_TOKEN` （可空）访问远端。它带来两件事：更高的限频额度，以及能读取私有仓库。

**它不是权限。** 拿不到它不影响任何人读目录、取用技能；它只影响"平台能不能把某一份远端内容拿进来"。因此它不落在权限目录里，也不是配置文件的键——理由与对象存储密钥相同（见 [../config/credentials.md](../config/credentials.md)）：**一个凭据一旦能写进配置文件，它就会在某个人手上的生产环境里被写进去。**

它不进日志、不进错误信息、不进任何脱敏摘要。

## 边界与约束

- **不往磁盘写任何东西。** 拉取与解压都在内存的流上进行（见 [agent-access.md](agent-access.md)：不落盘这条保证在取用面与纳管面是同一条）。
- **不解析、不执行正文。** 只读 `SKILL.md` 的 frontmatter 中的两项（`name`、`description`）；其余字节一律当作不透明的文本。模块内不引入任何执行入口。
- **不接受调用方给的取字节地址。** 见"来源的形状"。
- **不做重试、不做定时同步。** 见"超时与失败"与 [README.md](README.md) 的待定决策。
- **不做增量同步。** 每次同步取的是整棵树；"只拉变化的文件"要先回答"远端给的这些变化是不是完整的"，而那份答案只有远端有。
- **不校验正文里写的东西**（引用是否有效、命令是否存在、描述是否属实）。平台能做的是"这份字节是从哪个提交来的"，做到这一条，剩下的属于**读者**的判断。
- 被纳管的仓库地址、引用与子路径**不作为检索字段**，也不出现在列表里（列表要短）。它们出现在**详情**里——"这份内容是谁写的、从哪一版来的"是一个正当的问题，而且它让读者能自己去看原仓库。

## 可验证性与长程执行

**非长程任务。** 见"超时与失败"。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 只认 github.com | 别的任何主机（含 `github.com.evil.example` 这类后缀伪装）、`http://`、带端口或用户信息的地址在**解析阶段**被拒，且不发生任何出站请求（`internal/skill` 测试） |
| 网页地址被明确拒绝 | `/tree/<ref>/<path>` 形状被拒，错误信息里提到应改用引用与子路径（`internal/skill` 测试） |
| 取字节地址由服务端拼 | 调用方给的地址只被用来解析出（仓库、引用、子路径）三元组；出站请求的地址由这三项派生（`internal/skill` 测试） |
| 子路径不逃出仓库 | 子路径为 `..`、`/etc`、`a/../../b` 一类取值时在解析阶段被拒（`internal/skill` 测试） |
| 必需文件缺失 | 没有 `SKILL.md` 的包被拒，错误点名它（`internal/skill` 测试） |
| frontmatter 不合法 | `name` 或 `description` 缺失 / 超长 / 形状不对的包被拒，错误点名是哪一项（`internal/skill` 测试） |
| 二进制被拒 | 一份含 PNG 字节的文件被拒，错误点名那个路径（`internal/skill` 测试） |
| 非法路径被拒 | `..`、绝对路径、空段、超长、大小写重复的路径被拒（`internal/skill` 测试） |
| 链接被拒 | 含符号链接的包被拒（`internal/skill` 测试） |
| 上限被拒 | 文件数、单文件字节、总字节各自超限时被拒，错误点名是哪一档（`internal/skill` 测试） |
| 校验失败不留痕迹 | 一次被拒的纳管之后，技能列表为空、桶上没有新增对象（`internal/skill` 测试 + 端到端测试） |
| 落地是一个整体 | 行写入中途失败时，技能仍处于"从未纳管"（存储契约测试） |
| 版本不可变 | 同步产生新版本后，旧版本的文件清单与字节逐字不变（`internal/skill` 测试） |
| 同步无变化不动 | 远端提交与记录一致时不产生新版本、不切指针、不留痕（`internal/skill` 测试） |
| 同步失败指针不动 | 取回或校验失败后，当前版本与失败前是同一个（`internal/skill` 测试） |
| 来源不可改 | 接口面上不存在"改来源"的方法（`internal/server` 测试：遍历 method descriptor） |
| 回滚不改内容 | 回滚之后读到的正文是目标版本那一份，且所有版本都还在（`internal/skill` 测试 + 端到端测试） |
| 回滚不被同步撤销 | 回滚之后同步（远端无新提交）不动指针；远端有新提交时同步**才**前移（`internal/skill` 测试 + 端到端测试） |
| 删除只删行 | 删除之后桶上仍有那些字节，且被别的技能引用的字节照常可读（`internal/skill` 测试） |
| 不落地 | 纳管与取用之后，进程工作目录与 HOME 下不出现任何技能相关文件（端到端测试） |
| 正文不被执行 | 含 `#!/bin/sh` 的文件被当作字节处理，读回来逐字不变（`internal/skill` 测试） |
| 不联网即可测 | 远端拉取藏在接口后面，测试注入假实现；另有一条默认跳过的真实 GitHub 冒烟（`internal/skill` 测试） |
| 凭据不入日志 | 描述远端凭据时只出"有没有配"，不出取值（`internal/config` 测试） |

| 可观测性 | 纳管、同步、回滚与删除各留一条痕（含来源三元组与提交标识，**不含正文**），见 [../../observability.md](../../observability.md) |
| 远端（GitHub） | 由本模块自己的一个出口访问，藏在接口后面。它不是"另一个模块"，见下 |

**远端拉取为什么不登记成独立模块。** 它只被本模块消费，且要暴露给测试一个注入点（"不联网即可测"是硬要求）。把它做成一个跨模块的公共包，只会让"这份代码服务谁"变得含糊；它作为本模块的一个**出口接口**存在，测试注入假实现，生产实现是唯一一处出站请求。

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 定时同步 | 暂不做（**已定**）。自动把远端变更带进来，等于把远端仓库的写权限变成平台内容的写权限——而技能正文会被 agent 当作指令消费 | 引入本模块第一个后台任务，以及一套"自动生效"的信任论证 |
| 增量同步 | 暂不做（**已定**） | 需要远端提供可比对的变化集，并回答"这份变化集完不完整" |
| 私有仓库 | 接口上已经成立（凭据只从环境变量读），第一版不作验收项（**未定**） | 只影响凭据的运维与文档 |
| 大于上限的包 | 直接拒绝（**已定**）。分片、分卷、外链都不做 | 会引入一套"包的多个部分怎么组成一棵树"的规则 |
| 原地换来源 | 不做，改为重新纳管（**已定**，见"来源不可改"） | 版本与来源的对应关系、回滚语义都要重新论证 |
| 纳管进度的可见性 | 不做（**已定**）。一次请求一次结论，界面给的是"进行中"而不是百分比 | 要走长程任务那一套（阶段、检查点、恢复） |
