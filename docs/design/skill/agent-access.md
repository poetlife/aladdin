# skill — 取用面

## 背景与目标

技能的价值在于**被用上**。本子模块定义"一个 agent 或一个人怎么把平台上的技能拿到自己的工作里"，以及那条最要紧的约束：

> **平台是真相源，本机不装副本。**

要说清楚的不是"能不能取到"——那是 [catalog.md](catalog.md) 的检索与 `SKILL.md` 的正文——而是**取到之后东西在哪**。社区里的做法是把技能装进 agent 自己的 skill 目录（`~/.claude/skills`、Cursor skills 等），平台跟着变成"又一个分发渠道"；那正是本模块要避开的形态。

成功的衡量标准：

1. 一个 agent 用**一条命令**搜到技能、再用**一条命令**把它的正文拿到自己的会话里。
2. **调用方的文件系统上不会因此出现任何技能文件或技能目录。**
3. 平台里的一次改动（同步、回滚、改标题、删除）**对下一次取用立刻生效**，不存在"我这里还是老的"。
4. 取用走的是**调用者已有的凭证**，不引入第二套主体、第二套令牌。
5. 取用失败的原因能分清：没有权限、技能不存在、服务端不可用——三者不是同一句话。

## 功能行为

### 取用面只有两条路

| 面 | 谁用 | 形态 |
|----|------|------|
| 平台接口 | Web 工作台、命令行、将来别的前端 | Connect RPC：`SkillService` 的检索、详情与**取正文** |
| 命令行 | 外部 agent（Claude Code、Cursor 等）与人在终端里 | `aladdin skill …`，取用侧那几条命令 |

**刻意没有第二个协议。** 不新增 MCP、不为 agent 单开一条 HTTP 入口——命令行本来就是"所有 agent 都有的那个面"（agent 能跑 shell），而多一条协议就多一套鉴权接线、一套错误映射与一套要跟着改的边（理由与 [../events/README.md](../events/README.md) 拒绝"第二种推送协议"相同）。

### 命令

**取用侧**（`skill.catalog.read`）：

| 命令 | 做什么 | 计一次取用 |
|------|-------|-----------|
| `aladdin skill list [关键词] [--tag <标签>]… [--favorite]` | 列出 / 搜索目录。只读元数据 | 否 |
| `aladdin skill get <技能标识>` | 说明层 + 来源 + 文件清单 + **`SKILL.md` 的正文**。这是 agent 的主入口 | 是 |
| `aladdin skill cat <技能标识> <路径>` | 下一条文件的字节 | 是 |
| `aladdin skill favorite <技能标识>` / `unfavorite <技能标识>` | 收藏与取消 | 否 |
| `aladdin skill versions <技能标识>` | 列出该技能的版本与当前指针 | 否 |

**维护侧**（`skill.catalog.write`）：

| 命令 | 做什么 |
|------|-------|
| `aladdin skill add <仓库地址> [--ref <引用>] [--path <子路径>] [--tag <标签>]… [--title] [--summary]` | 从远端纳管一个新技能 |
| `aladdin skill sync <技能标识>` | 追远端：有新提交则产生新版本并生效 |
| `aladdin skill rollback <技能标识> <版本标识>` | 把当前指针切到某个已有版本 |
| `aladdin skill update <技能标识> [--title] [--summary] [--tag]…` | 改说明层 |
| `aladdin skill delete <技能标识>` | 删除技能 |

**`delete` 是危险操作**（要 `--yes` 才在非交互式环境下执行），与 `galaxy project delete` 同一档：它一次性带走这个技能的全部版本、标签、收藏与使用记录。

### stdout 是给取用者读的

命令行的输出分成两股，**分界固定**：

- **stdout 只有内容**：`get` 打的是说明层与正文，`cat` 打的是那一条文件的字节，别的什么都不打。
- **stderr 才是给操作者看的**：提示、进度、错误。

这条分界让 `aladdin skill cat <技能标识> theme.css` 的输出可以直接被管道接走，而不用先剥掉一行"正在读取…"。它是"命令行是一个可以被合成的工具"这条的落点——agent 读 stdout，人读两个。

**`get` 的输出里，正文之前的部分是"这个技能是什么"**（有效标题、有效简介、标签、来源、文件清单），正文之后不再有任何东西。agent 因此不需要第二次调用来判断"这个技能是不是我要的"。

### 不落盘这条保证

**平台从不向调用方的文件系统写任何东西。** 具体到三件事：

| 不做 | 说明 |
|------|------|
| 不安装 | 命令行里**没有**"装到某个目录"这样的命令形态 |
| 不认识任何 skill 目录 | 平台不读也不写 `~/.claude/skills`、Cursor 的目录，或任何别的位置。它不知道那些位置在哪，因此也不可能"顺手写一下" |
| 不做本地缓存 | 不落"上次取回来的那份"，不做增量拉取 |

**这条区别要写清楚：平台能做的是"不写"，不能做的是"禁止别人写"。** 调用者当然可以把 stdout 重定向到一个文件，也可以自己拼一份 `SKILL.md` 放进某个目录——那是**调用方**的动作，平台不参与、也无法阻止。平台能保证的是：**它这一侧没有任何一条会创建文件的路径**，以及它的命令里没有诱导这种用法的形态（比如一条叫 `install` 的命令）。

**为什么这条值得当硬约束。** 装了本地副本之后，真相源就有了两份，而分叉的表现不是报错：它是"同一条指令在两台机器上得到不同的结果"。这种问题不会自己浮出来，只会让人反复怀疑是模型的问题。

### 缓存边界

**缓存只在服务端。** 字节按内容摘要存放在对象存储里，那一层天然就是缓存（同一份内容只有一个对象），而"现在对外是哪一份"由库里的指针回答——**没有第二层缓存**，也没有"这个技能的正文缓存在进程里多久"这类问题。

因此：同步、回滚、改说明层、删除，**对下一次取用立刻生效**。代价是每一次取用都是一次服务端读取，没有"离线也能用"这回事——而它换来的是"平台里看到的"与"取到的是同一份"这句话不需要任何限定条件。

**明确不做**：不做技能包的本地缓存目录，不做"最后一次取用的副本"，不做离线可用。

### 鉴权：用调用者自己的凭证

取用走**命令行已有的那条凭证链**（参数 > 环境变量 > 凭证文件，见 [../config/credentials.md](../config/credentials.md)），权限判定在服务端，与别的命令没有任何差别。

**没有"agent 专用的令牌"。** 一个 agent 用的是它所在那个人的凭证——那意味着"这个 agent 能取到什么"与"这个人能看到什么"是同一个答案。给它单独一套主体，会立刻引出三件没有好答案的事：谁给 agent 授权、agent 的动作记在谁的账上、以及"人离职了 agent 还在吗"。

**命令行不做本地权限判断**（见 [../rbac/cli-permissions.md](../rbac/cli-permissions.md)）：它不因为"我记得这个主体没有权限"而不发请求，因此管理员的授权改动不需要任何一端重新登录。

### 失败要分得清

| 结论 | 表现 |
|------|------|
| 没有读权限 | 服务端拒绝，命令行按既有方式转成权限提示（不能是"技能不存在"） |
| 技能不存在 | 与"已删除"同一个结论 |
| 正文里的那一条路径不存在 | 与"技能不存在"**不同**的结论：技能在，是那个路径不在 |
| 服务端不可用 | 故障，可重试 |

**"没有权限"与"不存在"必须分开**（见 [AGENTS.md](../../../AGENTS.md) 的硬性约定第 5 条）。这里与 galaxy 不同：技能目录**不是**"地址即凭据"的那类资源（它没有不可猜的公开地址，可见性完全由权限码表达），因此区分两者不构成一条枚举通道。

## 边界与约束

- **不做增量取用**：一次取一条文件，或一次取整份。没有"只取变化的部分"——那个概念要求一个跨会话的本地状态，而本地状态正是这一节要避开的东西。
- **不做"下载整包"**：没有一条命令把一棵文件树写成一堆文件。要遍历就 `get` 拿清单、逐条 `cat`。
- **不解释正文**：命令行不渲染 markdown、不抽取结构化字段、不校验正文里提到的别的东西。
- **不做交互式浏览**：没有分页器、没有 TUI。目录有上界（见 [catalog.md](catalog.md)），列表就是一屏。
- **不引入新的错误码体系**：复用既有的拒绝原因枚举与退出码（见 [../rbac/cli-permissions.md](../rbac/cli-permissions.md)）。

## 可验证性与长程执行

**非长程任务。** 每条命令一次请求一次结论。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 不落盘 | 跑完 `skill list` / `get` / `cat` 之后，临时 HOME 与工作目录下的文件清单逐项不变（端到端测试） |
| 没有安装形态 | 命令树里不存在名字含"install"的技能子命令（`cmd/aladdin` 测试） |
| 不认识 skill 目录 | 源码里不出现 `~/.claude/skills` 一类位置常量（`cmd/aladdin` 测试） |
| stdout 只有内容 | `cat` 的 stdout 与文件字节逐字相等（端到端测试） |
| 权限与不存在分开 | 无读权限时得到权限结论；技能不存在时得到"不存在"结论（端到端测试） |
| 路径不存在是第三种结论 | 技能在、路径不在时的错误与"技能不存在"不同（端到端测试） |
| 改动立刻生效 | 取用一次 → 回滚 → 再取用，第二次拿到的是目标版本的字节（端到端测试） |
| 没有 agent 专用凭证 | 凭证解析只有既有的那一条链；接口面上不存在"为 agent 签发令牌"的方法（`internal/server` 测试：遍历 method descriptor） |
| 管理命令要危险确认 | 非交互式环境下不加 `--yes` 跑 `skill delete` 以用法错误退出（`cmd/aladdin` 测试） |

## 依赖关系

| 依赖对象 | 交互方式 |
|---------|---------|
| skill 总览 | 复用 [README.md](README.md) 的权限约定 |
| 目录、标签、收藏与统计 | 取用是使用量的**计量点**（见 [catalog.md](catalog.md) 的"使用量"） |
| 纳管与同步 | 取到的是**当前指针**指向的那个版本（见 [onboarding.md](onboarding.md)） |
| 命令行 | 凭证解析、错误映射、退出码、`--output` 等既有约定全部复用（见 [../cli/README.md](../cli/README.md) 与 [../rbac/cli-permissions.md](../rbac/cli-permissions.md)） |
| 身份认证 | 取用按调用者的凭证鉴权；本模块不签发凭证、不引入新的主体类型 |
| Web 界面 | 目录页与详情页提供同一批信息的另一种呈现；两者读的是同一批方法（见 [../web/README.md](../web/README.md)） |
| galaxy | **无交互**。技能不进文件组、不进产物（见 [README.md](README.md) 的待定决策） |

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| MCP 端点 | 暂不做（**已定**）。agent 从命令行取用（**未定**：将来真出现"给不了 shell 的 agent"时再单独论证） | 新增一个协议入口与一套工具描述；业务实现不变 |
| 一次性取整包 | 暂不做（**已定**）。整包要求一个落点，而"落点"正是本节要避开的东西 | 会引入"写到哪、谁清理"这两个问题 |
| agent 专用主体 | 暂不做（**已定**） | 引入第二套主体、授权与审计口径 |
| 本地缓存与离线可用 | 暂不做（**已定**） | 会让"平台里看到的"与"取到的是不是同一份"需要一个限定条件 |
| 命令行的交互式浏览 | 暂不做（**未定**） | 一个 TUI；与"stdout 只有内容"这条分界的关系要重新论证 |
