# RBAC 模块总览

> 本目录是 aladdin 权限体系的**功能行为唯一信源**。实现细节变更只改代码；权限的**行为**变更必须先改本目录。

## 背景与目标

aladdin 是前端（React + antd）、服务端（Go + gRPC）、命令行（cobra）三端一体的仓库。三端共享同一套用户、角色与权限数据，因此权限控制不能各自实现——三端各写一套 RBAC，必然出现"前端放行、后端拒绝"或更糟的"后端放行、前端以为拒绝了"。

本模块的目标是：**用一份权限模型、一个决策引擎，覆盖三端，且三端的判定结果永远一致。**

成功的衡量标准：

1. 权限码（permission code）在全仓库只有一处定义，Go 与 TypeScript 两侧由同一份定义派生。
2. 判定逻辑只有一处实现（服务端决策引擎）。前端与 CLI 的本地判断只用于体验优化，不作为安全边界。
3. 任一被拒绝的操作，都能从日志中还原：谁、在什么作用域、请求了哪个权限、为什么被拒。
4. 新增一个受权限控制的接口，只需在 proto 中声明权限码，不需要在拦截器里逐条登记。

## 三方职责矩阵

| 端 | 角色 | 是否安全边界 | 说明 |
|----|------|-------------|------|
| gRPC 服务端 | 决策与执行（PDP + PEP） | **是** | 唯一有约束力的判定点。所有请求在此被允许或拒绝 |
| Web 前端 | 展示裁剪（PEP，仅体验） | 否 | 决定"渲染什么"，不决定"能做什么"。隐藏按钮不等于禁止操作 |
| CLI | 凭证携带 + 结果呈现（PEP，仅体验） | 否 | 与服务端走完全相同的 gRPC 鉴权链路；本地校验只用于提前给出友好提示 |

三方关系：前端与 CLI 都是**客户端**，它们的权限码都来自同一次会话查询，判定都发生在服务端。

## 依赖关系

| 依赖对象 | 交互方式 |
|---------|---------|
| 身份认证（Authentication） | 本模块只消费"已确认的主体标识"，不负责登录、口令校验、令牌签发。认证失败在鉴权之前拦截。见 [../identity/](../identity/README.md) |
| 持久化存储 | 通过 `rbac.Store` 抽象读取角色/权限/绑定关系；本模块不关心底层是内存、SQL 还是外部目录服务。SQL 实现与库结构见 [../persistence/](../persistence/README.md) |
| proto 定义 | 受控接口、消息与拒绝原因在 `api/proto/` 中声明，经 `buf generate` 同时派生 Go 与 TypeScript 代码 |
| 权限目录 | 权限码全集在 `api/permissions/catalog.yaml` 中定义，经 `make gen` 派生 Go 与 TS 常量 |
| 可观测性 | 决策结果按 [observability.md](../../observability.md) 的鉴权强制字段留痕 |

## 传输方式（已定）

前端到服务端走 **Connect RPC**，参考实现 [usememos/memos](https://github.com/usememos/memos)。

一份 proto 经 `buf generate` 同时产出服务端 handler 与前端类型；服务端用 connect-go，**一个端口同讲 Connect / gRPC / gRPC-Web**，因此浏览器走 Connect、CLI 走原生 gRPC，两者共享同一份业务实现与同一条鉴权链路。

选择理由与替代方案的取舍见 [server-permissions.md](server-permissions.md)。这条已经定下来，不再是开放问题——**留一个"以后再说"的传输方式，实际代价是前端只能手写接口类型，与 proto 各写一遍必然漂移。**

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 决策结果缓存位置 | 进程内缓存 + 变更时主动失效 | 只影响 `internal/rbac` 的缓存实现 |
| 角色变更的传播延迟容忍度 | 秒级（可接受短暂不一致） | 影响缓存 TTL 与失效策略 |
| 凭证形态 | 服务端签发的**不透明会话令牌 + 会话存储**（**已定**，见 [../identity/session-token.md](../identity/session-token.md)） | 已不再是本模块的开放问题；改形态只影响认证模块 |
