# RBAC — 前端接入

## 背景与目标

描述 React + antd 前端如何获取权限、以及在什么位置使用权限做展示裁剪。

**先说清楚本子模块的定位**：前端不承担安全职责。前端隐藏一个按钮，只是让用户不必点击后才发现权限不足；它不阻止任何人直接调用接口。真正的判定发生在服务端（见 [server-permissions.md](server-permissions.md)）。

因此本子模块的目标是两件事：**准确性**（前端认为有权限的，服务端也应认为有权限，避免"能点但点了报错"）和**体验**（没权限的东西根本不出现，而不是出现后报错）。

## 功能行为

### 会话权限码

- 登录成功后，前端向后端查询**当前主体在其可及作用域下的权限码集合**，以及当前作用域。
- 权限码集合是前端所有裁断的唯一依据。前端**不得**自行拼接、推断或用角色名反推权限码——例如不得写"如果角色是管理员就显示"。
- 会话失效、主体变更、作用域切换后，权限码集合必须重新获取；不允许沿用旧集合。

### 作用域

- 前端持有"当前作用域"。所有权限判断都在这个作用域下进行。
- 切换作用域（如从某租户切到另一租户）等同于会话权限变更：必须重新获取权限码集合并重新计算全部裁剪结果。
- 页面不得硬编码作用域值。

### 三层裁剪

| 层级 | 位置 | 行为 |
|------|------|------|
| 路由级 | 进入路由前 | 无权限则不进入目标页面，重定向到无权限提示 |
| 页面级 | 页面挂载后 | 无权限的数据区块不请求后端，直接显示为空或占位 |
| 控件级 | 按钮/菜单项渲染前 | 无权限的控件不渲染 |

补充约定：

- 路由级裁剪依赖的是"该页面所需的基础权限"，是一个显式声明的清单，而不是"页面里所有控件的权限之并集"。
- **控件级裁剪不渲染而非禁用**，除非需要向用户传达"这个功能存在但你没权限"。默认不渲染，避免界面被大量灰按钮占据。
- 列表类结果的裁剪**必须由后端完成**（见 [server-permissions.md](server-permissions.md) 的"权限不足的部分返回"）。前端不得先拉全量再过滤——那等于把无权数据下发到了浏览器。

### 与后端的一致性

一致性有两层保障：

1. **接口类型**：请求与响应的类型、service descriptor 全部由 proto 经 `buf generate` 生成，前端不手写任何接口类型。
2. **权限码**：前端权限码常量与服务端常量都从 `api/permissions/catalog.yaml` 生成，不允许任何一侧手写字符串。

**拒绝原因**同理：它是对外契约，定义在 proto 中，前端解码后得到的是与服务端、CLI 完全相同的枚举取值（见 [server-permissions.md](server-permissions.md)）。旧实现里前端手写一份原因枚举、与服务端各写一遍，是典型的漂移来源，已移除。

判定**语义**的一致性由 [enforcement.md](enforcement.md) 保证：前端的本地判断只做"我是否持有这个权限码"的集合成员判断，不重复实现通配、继承、作用域包含等逻辑——这些在获取权限码集合时已由后端展开完毕。**前端拿到的就是展开后的最终权限码集合。**

### 无权限时的表现

- 路由级拦截：显示明确的"无权限"页面，并提供返回入口；不做静默跳转回首页（用户会以为点击失灵）。
- 接口返回权限不足时：即使前端判断有误也要正确处理，提示应说明是权限问题而非网络问题。提示文案由拒绝原因枚举驱动，不做错误文本匹配。
- 接口返回未认证时：走统一的会话失效流程，由传输层统一处理，不在各页面重复实现。

## 边界与约束

本模块**明确不处理**：

- 登录界面与凭证存储的细节（属于身份认证模块）。
- 服务端判定逻辑的任何副本。

约束：

- 权限码集合在**应用启动或登录后获取一次**，不在每次路由切换时重新请求。
- 前端代码中**不允许出现权限码字符串字面量**；一律引用生成的常量。
- 裁剪逻辑不得散落在各页面重复实现：路由级、控件级各只有一个统一入口。

## 可验证性与长程执行

**非长程任务，无需中途校验。** 前端的权限裁剪是渲染期的同步计算，不涉及多阶段推进，也不存在中途失败需恢复的场景。

需要保证的是**与服务端的一致性**，这通过测试而非运行时机制保证：

| 核查项 | 判据 |
|--------|------|
| 无字面量 | 前端源码中不出现权限码字符串字面量（静态检查） |
| 同源 | 前端权限码常量确实由 proto 生成，生成产物未被手工修改 |
| 一致 | 对同一组权限码集合与作用域，前端判断与服务端判定的结果一致（集成测试） |

## 依赖关系

| 依赖对象 | 交互方式 |
|---------|---------|
| 服务端 gRPC 接入 | 经传输层调用，获取权限码集合；消费其拒绝语义 |
| proto 定义 | 权限码常量与消息类型由 proto 生成 |
| 鉴权决策 | 复用其语义，但不复用其实现 |
