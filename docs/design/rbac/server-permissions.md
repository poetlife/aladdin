# RBAC — 服务端接入

## 背景与目标

描述一次 RPC 调用在服务端如何被认证与鉴权，以及拒绝时如何返回。

本子模块是 [enforcement.md](enforcement.md) 的决策语义在服务端接入层的落地。它**不重新定义**任何判定规则；一旦发现这里描述的规则与 enforcement 冲突，以 enforcement 为准。

三端对称：本文件对应 [frontend-permissions.md](frontend-permissions.md) 与 [cli-permissions.md](cli-permissions.md)。

## 功能行为

### 传输层与协议

服务端用 **Connect**（connect-go）暴露接口。一个 handler 在同一个端口上同时支持三种协议，因此：

| 调用方 | 协议 | 说明 |
|--------|------|------|
| Web 前端 | Connect | 浏览器端用 `@connectrpc/connect-web` |
| CLI | 原生 gRPC | grpc-go 客户端，`pkg/client` |
| 第三方 / 调试 | gRPC-Web、gRPC、Connect | 同一地址，无需额外网关 |

**三者共享同一份业务实现与同一条鉴权链路**。不存在"REST 走一套判定、gRPC 走另一套"的可能——这是选择 Connect 而不是 grpc-gateway 的核心理由（见 [README.md](README.md) 的传输方式决策）。

接口契约、前端类型与服务端 handler 全部由 `api/proto/` 经 `buf generate` 派生，两侧不可能漂移。

### 处理链路

每个请求依次经过三段，顺序不可调换：

| 顺序 | 处理 | 所在层 | 职责 | 失败时的结果 |
|------|------|--------|------|-------------|
| 1 | 链路追踪 | HTTP 中间件 | 校验并继承入站 `traceparent`，起 server span，回写响应头 | 不失败；非法入站值丢弃后新起一条链路，这是为了后续所有日志可串联 |
| 2 | 认证 | HTTP 中间件 | 从请求头提取凭证并确认主体 | 以"未认证"拒绝 |
| 3 | 鉴权 | RPC 拦截器 | 解析所需权限码与作用域，执行判定 | 以"权限不足"拒绝 |

三条约定各自都有理由：

- **链路标识必须排在最前**：被拒绝的请求同样需要留痕，否则无法回答"是谁在反复尝试越权"。
- **认证放在 HTTP 层，而不是 RPC 拦截器里**：拦截器在请求体读取并解压**之后**才执行，把认证放那里意味着未认证的请求也会先被完整读一遍。放在 HTTP 层可以在读取任何字节之前拒绝。未认证的请求是最不需要被解析的请求。
- **鉴权放在 RPC 拦截器里**：判定需要读取请求消息中的作用域字段，只有过了协议层才拿得到。

因此 HTTP 中间件在拒绝时，必须按客户端所用的协议编码错误——用 Connect 提供的错误写出器完成，它对 Connect / gRPC / gRPC-Web 分别编码（gRPC 走 trailer）。**这不是实现细节而是行为要求**：若中间件对所有协议都写 JSON，grpc-go 客户端会把拒绝当成传输层故障，CLI 就拿不到正确的退出码了。

### 受控方法到权限码的映射

- 每个受控方法的权限码与作用域来源**声明在 proto 中**（方法选项，见 `api/proto/aladdin/rbac/v1/annotations.proto`），不在拦截器里逐条硬编码。
- 方法必须**三选一**：`public`、`authenticated_only`、`required_permission`。三者皆无的方法由鉴权层默认拒绝，并由构建期测试提前捕获。不允许"没声明就默认放行"。
- 作用域从请求中解析的方式也在 proto 中声明（来自请求消息的哪个字段、请求头，或凭证自身）。解析不到时以"作用域不符"拒绝，而不是退化为全局作用域。

公开方法（无需认证）是**白名单**，必须显式维护且尽可能短。登录与刷新是仅有的成员；任何业务方法进入该清单都是缺陷，有构建期测试固定其数量。

健康检查与反射这两类基础设施服务不参与业务鉴权。它们由显式的、极短的清单放行——这与"未声明注解即默认拒绝"并不矛盾：那条规则针对的是**业务方法**。

### 拒绝语义

拒绝通过 RPC 错误码表达，客户端据此区分处理：

| 场景 | 错误码语义 | 客户端应有的表现 |
|------|-----------|-----------------|
| 未携带凭证 / 凭证无法解析 | 未认证 | 引导登录 |
| 已认证但无对应权限 | 权限不足 | 不应重试 |
| 请求中的作用域不合法或缺失 | 参数非法 | 不应重试，属于调用方缺陷 |
| 存储不可用导致无法判定 | 服务不可用 | 可退避重试 |
| 方法漏写鉴权注解 | 服务内部错误 | 不应重试，属于服务端配置缺陷 |

**关键约定一：不得把"无权限"与"未认证"混为一谈。** 混用会导致客户端在权限不足时反复尝试刷新凭证，把一次权限配置错误放大成登录风暴。

**关键约定二：拒绝原因必须是可被机器读取的枚举，而不是一句文本。** 它随错误一起返回，三端都从**同一份 proto 定义**解码（见 `api/proto/aladdin/rbac/v1/errors.proto`），因此不存在"前端按文本猜、CLI 按枚举判"的分裂。

**关键约定三：注解缺失属于服务端缺陷，不是调用方的问题。** 它返回独立的错误码并在详情里带上方法名，使排障的人一眼知道该找谁，而不是去查自己的角色配置。

拒绝时**不返回**主体是否持有相邻权限之类的信息，避免通过错误信息探测权限布局。

### 流式 RPC

- 客户端流与服务端流在**建立流时**做一次鉴权。
- 流式方法不得把作用域来源声明为"请求消息字段"：不消费首条消息就拿不到它。这类声明视为服务端配置错误并直接拒绝。
- 流建立后不再逐条消息鉴权，因此**同一条流内不允许跨越作用域边界**。需要跨作用域的批量操作必须拆成多条流。

### 权限不足的部分返回

列表类接口在作用域过滤后可能返回空结果。此时**返回空列表而非拒绝**——"你在该作用域下没有数据"与"你无权调用此接口"是两件事。这一区分必须保持，否则前端无法区分"没数据"与"没权限"。

## 边界与约束

本模块**明确不处理**：

- 前端与 CLI 各自的客户端接入方式：分别见 [frontend-permissions.md](frontend-permissions.md) 与 [cli-permissions.md](cli-permissions.md)。
- 审计日志的持久化与检索：本模块只保证决策留痕被产出。
- 认证后端本身（口令校验、令牌签发）：本模块只定义认证**发生的位置**与失败的语义，具体实现可替换。

约束：

- 鉴权层**不得**包含业务判断。任何"如果是某类用户就放行"的写法都说明权限模型缺少一个角色或权限码，应在权限目录与 proto 中补声明。
- 高频方法的判定必须命中缓存，否则每次调用都访问存储。
- 明文 gRPC 依赖服务端启用非加密 HTTP/2。降级 Go 版本或改用 TLS 终止时需重新确认这一条。

## 可验证性与长程执行

**非长程任务，无需中途校验。** 单次请求的认证与鉴权都是同步的即时判定，不跨阶段推进。

需要长期保证的是**映射的完整性**与**协议间的一致性**，这是持续性的核查而非运行时进度：

| 核查项 | 判据 |
|--------|------|
| 受控方法声明完整性 | 每个方法都能被归入三类之一；存在既未声明注解又不在基础设施清单中的方法即为缺陷。由构建期测试执行 |
| 公开方法收敛 | 公开方法数量只减不增；新增需在评审中说明理由。由构建期测试固定 |
| 协议间判定一致 | 同一个请求无论走 Connect 还是 gRPC，结论必须相同。由端到端测试双向验证 |
| 拒绝原因可解码 | 两条协议路径上都能从错误详情解出结构化的拒绝原因 |

最后两条是本模块特有的：**选择了"一个端口三种协议"就必须证明三条路径没有分叉**，否则这个选择带来的就不是便利而是不可预测。端到端测试同时用 grpc-go 客户端与 Connect 客户端打同一个端口，断言结论一致。

## 依赖关系

| 依赖对象 | 交互方式 |
|---------|---------|
| 鉴权决策 | 调用决策引擎，消费其结论与原因 |
| 身份认证 | 经 HTTP 中间件获得已确认的主体标识 |
| proto 定义 | 读取方法上的权限码与作用域声明选项；拒绝原因枚举来自同一处 |
| 可观测性 | 产出决策日志与决策指标；链路标识经 `traceparent` 请求头透传并在响应头回写 |
