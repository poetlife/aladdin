# 个人档案 — 头像的存放与下发

## 背景与目标

头像与昵称、简介有一个根本区别：它是一段**二进制**，几百 KB 量级。

把它放进关系库有两个后果。一是每一次读取主体相关的行都会带上一个大字段，而库是被判定路径读的；二是库的体积被图片支配，而库的备份策略是"按天做快照、保留最近若干份"（见 [../../deploy.md](../../deploy.md)）——图片会让这份快照迅速变大，而快照变大意味着恢复变慢。

因此头像字节存在对象存储里，库里只留一个指向它的**对象键**。

本子模块定义这段字节怎么存、怎么取，以及这条路径上最容易出错的两处：**谁能决定这个文件是什么类型**，以及**取图的地址算不算一份凭证**。

成功的衡量标准：

1. 桶保持**私有读写**：任何未签名的请求都取不到头像。
2. 上传时服务端**看到了真实字节**，不接受上传方声明的类型。
3. 界面拿到的地址是**短时有效**的，过期后重新读取能拿到新的地址。
4. 未配置对象存储时，服务端照常启动，档案其余部分照常可用。

## 功能行为

### 对象键

```
avatars/<主体标识>
```

前缀是**常量**，不是配置项。做成配置项只会多出一种失败方式：改了前缀，存量头像在一瞬间全部变成孤儿。

**一个主体一个键，替换即原地覆盖。** 由此得到两条结论：

- 替换头像不产生孤儿对象——覆盖写不需要先删后写。
- 一张**旧的**取图地址在过期前指向的是**新**头像。这不泄露被替换掉的那张。

主体标识用作键的一部分是安全的：它不是秘密，也不参与任何判定（见 [README.md](README.md) 的"边界与约束"），而桶是私有的，知道键也取不到东西。

### 上传：字节过服务端

上传请求携带图片字节，由服务端转存到对象存储。

**请求里没有"声明类型"这个字段。** 服务端对收到的字节做内容嗅探，只接受一张白名单——PNG / JPEG / GIF——并以**嗅探结果**作为存储的类型；不在白名单内一律拒绝。

**为什么不让客户端直传。** 直传意味着服务端从未见过这些字节，也就无从判断它到底是不是一张图片：一段 HTML 或一段脚本可以顶着 `image/png` 存进去，之后以一个看起来合法的地址被分发到浏览器。**内容类型是安全属性，不能由上传方自证。** 顺带地，把类型从请求里去掉比"让上传方声明、再由服务端比对嗅探结果"更省事——后者要回答"不一致时以谁为准"，而前者让这个问题不存在。

**大小上限 2 MiB**，超限拒绝并说明上限。上限只约束字节数，不含像素尺寸（见"待定决策"）。

### 下发：预签名地址直连

读取档案时，服务端为头像生成一个**短时有效的预签名读取地址**随档案下发；浏览器直接用它取图，服务端**不代理**图片带宽。

**这个地址是一份在有效期内谁拿到都能用的凭证。** 这是本设计的已知取舍，不是疏漏：桶是私有的，地址只下发给本人；但本人一旦把地址转出去，拿到它的人在有效期结束前都能取到这张图。

对头像接受这一取舍，理由是头像本来就是要显示给人看的东西。**把它写进 spec 而不是留成隐性假设，是因为它直接决定了一条约束：头像里不得承载任何秘密。** 一条只对本人可见的私密图片，与这个下发方式不兼容。

地址有效期取**分钟量级**。因此一个长时间开着的页面可能在过期后显示不出图片——重新读取档案即得到新地址。缓存失效是自然的：地址每次生成都不同，无需额外的版本参数。

### 删除

删头像做两件事：清掉档案行上的对象键，删除对象。

**对象删除失败不影响"档案已清空"这一结论。** 库内是"这个主体有没有头像"的权威；对象存储上可能因此留下一个孤儿对象，而它无从被引用、没有功能影响。回收见"待定决策"。

### 未配置时

对象存储未配置时（见 [../config/server-config.md](../config/server-config.md)）：

| 方面 | 行为 |
|------|------|
| 服务端启动 | **照常启动**。头像不是启动的必需品 |
| 昵称与简介 | 照常可用 |
| 档案响应 | 明确标出"头像功能未启用" |
| 前端 | 据此**不渲染**头像上传区，而不是渲染一个点了报错的控件 |

最后一条与"未配置 Google 客户端标识时不渲染登录入口"是同一取向（见 [../identity/google-login.md](../identity/google-login.md)）：能力由服务端下发，前端不猜。

**半套配置拒绝启动。** 只配了桶地址没给密钥、或给了密钥没配桶地址，一律拒绝启动并指出缺的是哪一项。这与引导的"半套配置一律拒绝启动"同一取向：半套配置的失败方式是"看起来配好了"，而它在第一次上传时才以一次权限错误暴露。

## 边界与约束

- 头像字节**不进关系库**，也不进日志与错误信息。→ [README.md](README.md) 的"留痕"。
- **对象存储的凭证不是配置文件的键**，只从环境变量读。依据见 [../config/credentials.md](../config/credentials.md)："配置文件中不得出现令牌字段"——配置会进版本库、进镜像、被贴给别人。桶地址不是秘密，可以进配置。
- 服务端**不代理**图片字节：下发只给地址。上传是唯一一次字节经过服务端的场景，而那次必须经过嗅探。
- 本模块不提供"列出桶里有什么"的能力。
- 桶的创建、私有读写、子账号最小权限与密钥文件的权限属于部署形态，见 [../../deploy.md](../../deploy.md)。

## 可验证性与长程执行

**非长程任务。** 上传、删除与地址生成都是即时的同步操作。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 未签名取不到 | 去掉签名参数直接访问对象地址被桶拒绝（部署后冒烟）；签发的地址必带签名（`internal/profile/cosstore` 测试） |
| 类型由嗅探决定 | 用真实签名的字节样本判定类型；非图片字节一律被拒——请求里没有可声明的类型，能钻的空子只剩字节本身（`internal/profile` 测试） |
| 白名单之外拒绝 | HTML 与 SVG 一类"能顶着 image/png 存进去"的字节被拒（`internal/profile` 测试 + 端到端测试） |
| 超限即拒绝 | 超过字节上限的输入被拒，且**不产生对象**（`internal/profile` 测试） |
| 一个主体一个对象 | 连续上传两次后，该主体在存储里只有一个对象，且内容与类型都是后一次（`internal/profile` 测试） |
| 删除不因对象缺失而失败 | 对象已不存在时删头像仍成功（`internal/profile` 测试） |
| 地址带有效期 | 签发的地址上有签名与有效区间，且有效区间等于调用方给的 ttl（`internal/profile/cosstore` 测试） |
| 未配置时可用性不变 | 全空即未启用，且不构成一条可用的存储（`internal/config` 测试）；未启用时昵称与简介读写照常（`internal/profile` 测试） |
| 半套配置拒绝启动 | 只配桶地址、或只配密钥时启动失败，错误信息指出缺的是哪一项（`internal/config` 测试） |
| 密钥不入日志 | 描述这项配置时只出桶地址、不出密钥（`internal/config` 测试） |
| 密钥不可由配置提供 | 把密钥键写进配置文件会被当成无法识别的键拒绝（`internal/config` 测试） |
| 不联网即可测 | 对象存储访问藏在接口后面，测试注入假实现；预签名本身不发起请求，因此地址的正确性可以离线断言（`internal/profile` 与 `internal/profile/cosstore` 测试） |

## 依赖关系

| 依赖对象 | 交互方式 |
|---------|---------|
| 个人档案（父模块） | 提供"这个主体有没有头像、对象键是什么"；本文件只描述字节的存放与下发（见 [README.md](README.md)） |
| 腾讯云 COS | 私有读写的桶：写入、删除，以及预签名读取 |

| 部署 | 桶的创建与私有读写、子账号最小权限、密钥文件的权限（见 [../../deploy.md](../../deploy.md)） |

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 头像改为客户端直传（预签名 PUT） | 暂不做。会失去服务端类型嗅探，只能靠桶侧策略约束大小与声明类型（**未定**） | 上传路径与校验位置；"类型由服务端判定"这条前提消失 |
| 孤儿对象回收 | 暂不做。库内为权威，孤儿无从引用、无功能影响（**未定**） | 需要一个对账动作（列举桶、与库比对），是新的一类运维职责 |
| 像素尺寸校验 | 暂不做。需要引入图像解码依赖（**未定**） | 只影响写入校验 |
| 头像走 CDN 或改长效地址 | 暂不做，保持短时预签名（**未定**） | 影响下发语义；"头像不得承载秘密"这条前提要重新审视 |
| 多区域 / 多桶 | 暂不做（**未定**） | 影响配置形状与对象键规则 |
