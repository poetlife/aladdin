# 身份认证 — 会话凭证

## 背景与目标

登录成功后，服务端必须给客户端一份可以反复使用的凭据。本子模块定义这份凭据的形态、签发、校验、撤销与回收。

它要同时满足两件互相拉扯的事：

1. **可撤销。** 一个被盗的凭据必须能被立刻作废，且作废无需等待任何超时。
2. **可持久。** 服务端重启不应该把所有人踢下线；多副本部署下，在 A 副本登录的会话在 B 副本必须可用。

## 功能行为

### 凭证形态：不透明随机串

凭证是一个**密码学随机数**，本身不携带任何信息。它的含义完全由服务端的会话存储给出。

**不使用自包含的签名凭据（如 JWT）。** 这是本子模块最重要的一个取舍，理由是它与上面第 1 条直接冲突：自包含凭据的整个价值在于"服务端不必查存储就能验证"，因此它在有效期内**无法撤销**——持有者手里的字符串自带"这是真的且未过期"的证明，服务端说它不是真的也没用。要做撤销，就得维护一份"已作废"名单，而**那份名单就是一个会话存储**——绕了一圈，存储没省掉，反而多出两套东西要同步：凭据里的有效期，和名单里的作废记录。

因此直接采用"服务端查"的形态，把撤销做成它天然支持的操作。代价是每次请求多一次存储读取，这个代价在当前规模下可以忽略，而且它是**可测量的**——自包含凭据省下的那点开销，换来的是"撤销不了"这个不可修补的性质，不划算。

凭证还需要有足够的长度，使穷举不可行。这个长度的量级由"猜中一个有效会话的概率可以忽略"确定，不由"看起来够长"确定。

### 签发

一次成功的登录产生一份新的会话凭证。同一份凭证**只被交付一次**——签发时返回给调用方，此后服务端再也拿不回来。

签发时确定三件事：**代表谁**、**默认作用域**、**有效期**。

默认作用域取自主体在主体表中的默认作用域，而后者来自主体的绑定关系（见 [../persistence/schema.md](../persistence/schema.md)）——认证模块不自行发明一个作用域，也不从配置里取。

**凭证与作用域的关系要说清楚：作用域不是权限，是一次请求的声明。** 请求携带的作用域最终仍要在判定时与主体的绑定关系比对，比对不上就是"无权限"。因此一个签发时作用域较宽、之后被管理员收窄了绑定的会话，**不会**因此获得超出其当前绑定的权限——它声明的宽作用域在判定时找不到对应绑定，只会被拒。这使得"签发时冻结作用域"是安全的，不需要每次请求重新推导。

### 校验

请求携带凭证时，服务端：

1. 算出该凭证的摘要，在会话存储中查找；
2. 找不到 → 未认证；
3. 找到但已过期 → 未认证，与找不到**结果相同**；
4. 找到且未过期 → 该会话代表的主体即为本次请求的主体。

**先做一次凭证形态的判断，再决定用哪条校验路径。** 系统里同时存在两种凭据——本模块签发的会话凭证，以及运维配置的机器凭证（见"与机器凭证的关系"）。两条路径的结论都映射到"已确认的主体"或"未认证"，调用方看不出区别；区别只在"能否撤销"与"能否过期"上。

任何一步失败都返回**未认证**。凭证无效、凭证过期、凭证不存在三者对调用方是同一件事，服务端不区分——区分它们等于告诉探测者"这个字符串曾经有效"。这与 [../rbac/server-permissions.md](../rbac/server-permissions.md) 的拒绝语义一致：未认证与无权限是两个类别，不可合并。

### 撤销与失效

| 触发 | 效果 |
|------|------|
| 主动登出 | 该凭证立即失效 |
| 换新（刷新） | 签发一份新凭证，旧凭证**同时**失效 |

**撤销是删除，不是标记。** 既然校验的唯一依据就是存储里的那一行，删掉它就是最彻底的失效——不需要一个"已作废"状态位，也就不存在"忘了检查那个位"的可能。

**刷新必须作废旧凭证。** 只发新不作旧，等于每次刷新都让一份旧凭证继续有效到自然过期，凭证的暴露面随刷新次数单调增长。刷新是"续期"，不是"再发一个"。

撤销**不区分**"凭证不存在"与"凭证已失效"：两者都返回成功。重复登出、登出一个早已过期的会话，结果一致。

### 有效期与过期行的回收

凭证有**绝对有效期**，到点即失效。有效期长度由"一次泄露的暴露窗口"确定：太长则撤销的意义被削弱，太短则用户体验被频繁重新登录破坏。默认值见"待定决策"。

**正确性不依赖回收。** 校验时已过期的行一律视同不存在，因此即使一行都还没回收，过期凭证也用不了。

回收只在**启动时**执行一次，清掉已过期的行。它存在的唯一目的是不让会话表无限增长——否则运行一年之后这张表里绝大多数是早就没用的行。

**不引入后台定时任务。** 那会新增一个需要被监控、被优雅关闭、在异常时可能静默死掉的进程内循环，而它换来的是"表在两次重启之间增长得慢一点"。服务端本来就会重启，启动时清理一次已经足够；真到了单次运行周期内就增长到需要中途清理的量级，那时正确的做法是重新审视有效期长度，而不是加一个循环。

### 与机器凭证的关系

系统里有两类凭据，必须分清：

| | 会话凭证 | 机器凭证 |
|--|---------|---------|
| 来源 | 登录成功后由服务端签发 | 运维在配置或环境变量中设定 |
| 有效期 | 有，到点失效 | 无，一直有效直到被换掉 |
| 能否撤销 | 能，立即生效 | 不能，只能改配置并重启 |
| 用途 | 人（Web 前端） | 程序（CLI、CI、服务账号） |

**机器凭证的现有行为在本模块引入后保持不变**：它仍然可以直接作为请求凭证使用。让它"只能用于换取会话凭证"是一个更干净的终局形态（长期密钥只在登录那一次出现在网络上，此后一律是短期可撤销的会话），但那是一次会打断所有既有 CLI 使用者的变更，应当作为独立决策来做，而不是搭在"接入 Google 登录"里顺手改掉。见"待定决策"。

## 边界与约束

本模块**明确不处理**：

- 登录本身（用什么方式确认身份）：见 [google-login.md](google-login.md)。
- 主体拿到会话之后能做什么：[../rbac/](../rbac/README.md)。
- 会话表的表结构与迁移：由持久化模块统一管（见 [../persistence/schema.md](../persistence/schema.md)）。

约束：

- **凭证原文绝不进入日志、错误信息与 `--debug` 输出。** 它与口令同级。可入日志的是主体的标识与"这次认证失败的原因类别"，不是凭证。
- **凭证只在交付那一刻存在于服务端内存中，不落库。** 库里存的是它的摘要（见 [../persistence/schema.md](../persistence/schema.md) 的会话表）。这条要一直成立：任何"顺便把原文也存一份用于排障"的改动都是把一次数据库泄露升级成一次全量会话接管。
- **摘要不使用口令哈希那类刻意放慢的算法。** 凭证是密码学随机数，不存在被猜中的风险；放慢只会让每个请求都白付一次昂贵的代价。这与口令的处理方式刻意不同，不可合并成同一个函数。
- 会话存储**只有一个可写副本**：进程内内存实现仅供测试，不得出现在生产装配路径上（见 [../persistence/README.md](../persistence/README.md)）。两份可写副本意味着一次撤销可能只落到其中一份上，而"撤销了但还能用"是认证里后果最重的一类错。

## 可验证性与长程执行

**非长程任务。** 签发、校验、撤销都是即时的同步操作。

| 核查项 | 判据（验证手段） |
|--------|----------------|
| 凭证原文不入库 | 直接读会话表，任何一列的值都不是签发出去的凭证（`internal/identity` 测试） |
| 签发即生效 | 刚签发的凭证可立即用于认证（契约测试） |
| 过期即失效 | 已过期的凭证认证失败，且失败类别是"未认证"（契约测试） |
| 撤销立即生效 | 撤销后同一凭证的下一次请求被拒（契约测试） |
| 刷新作废旧凭证 | 刷新后旧凭证失败、新凭证成功（契约测试） |
| 重复撤销幂等 | 撤销两次、撤销不存在的凭证，结果一致且不报错（契约测试） |
| 失效原因不泄露 | "不存在"与"已过期"返回同类结果（契约测试） |
| 重启后仍然有效 | 用同一个库文件构造两次存储，第二次仍认得第一次签发的会话（`internal/identity/gormstore` 测试） |
| 实现语义一致 | 内存实现与 SQL 实现跑**同一套**契约用例，得到相同的结论与**相同的错误类别** |
| 凭证不入日志 | 用一份凭证走完登录与认证，它不出现在任何日志行中（端到端测试） |

## 依赖关系

| 依赖对象 | 交互方式 |
|---------|---------|
| 持久化 | 会话的表结构与摘要存储；启动时的过期行回收挂在启动路径上（见 [../persistence/README.md](../persistence/README.md)） |
| RBAC 模块 | 会话代表的主体由 RBAC 判定消费；本模块不读角色、不参与判定 |
| Google 登录 | 是其签发会话的触发来源之一（见 [google-login.md](google-login.md)） |
| 服务端接入 | 认证发生在 HTTP 中间件层，早于鉴权（见 [../rbac/server-permissions.md](../rbac/server-permissions.md)） |
| 可观测性 | 签发、撤销、过期留痕，**不含凭证**（见 [../../observability.md](../../observability.md)） |

## 待定决策

| 决策 | 推荐默认 | 替换影响范围 |
|------|---------|-------------|
| 有效期的具体长度 | 一个以"天"为量级的绝对值（**未定**，落地时定） | 只影响签发参数与回收频率 |
| 是否支持滑动续期（临近过期自动刷新） | 不做。由客户端在过期后重新登录（**未定**） | 影响签发与刷新语义，不影响校验 |
| 机器凭证是否改为只能换取会话凭证（两段式） | 暂不改。保持现状以免打断既有 CLI 使用者（**未定**） | 影响 CLI 凭证语义与端到端测试；会话层本身不受影响 |
| 单主体同时在线的会话数上限 | 不限制（**未定**） | 只影响签发策略 |
| 会话是否记录发起方信息（IP、User-Agent） | 暂不记录。它属于行为留痕，不是"你是谁"（**未定**） | 表结构加列，需追加迁移 |
