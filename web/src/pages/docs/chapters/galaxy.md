放下一组文件——手写的一页、构建工具产出的整站、或者一组 markdown 文档——再放素材，然后发布成一个别人打开网址就能看的站点。

内容不是一个文件，而是**一组具名文件**：每个路径都有自己的地址（`/g/<工程标识>/<路径>`）。因此构建产物可以一个字节都不改地发布，文档也能一章一个网址、深链直接分享。

每一步各一条命令，没有「一条命令走完全流程」的形态——一次发布发的是**某一版**，而不是「文件现在的样子」。而且**网页端只读**：内容的写入只有命令行一条路，`push` 送上去的那一份就是全部。

## 选内容槽：站点、文档，或两个都要

建工程时**至少选一个内容槽**，此后**只增不删**——一个已经分享了站点的工程，可以再长出文档来，而不必另建一个工程。两个槽各有自己的草稿、版本、分享地址与发布状态，**互不影响**：推文档不会覆盖站点，撤回一个也不动另一个。

- `site` 槽：整站文件**原样服务**。覆盖手写单页与构建产物，入口是 `index.html`，地址是工程根 `/g/<工程标识>/`。
- `docs` 槽：一组 markdown **渲染成多页**，站点文件（CSS、JS、JSON）按原路径一并带上，入口是 `index.md`，地址是它下面的 `docs/`。

`docs` 槽**不收 HTML**：它的页面是渲染出来的，不是写出来的。两者的白名单因此不同，命令行会按槽告诉你哪些文件能进。也正因为 `docs` 这一段地址归文档槽，站点槽里不能有以它开头的路径。

## 引用素材：写记号，不写地址

图片、视频、音频、字体先用 `aladdin galaxy asset upload <工程标识> <文件>` 传进工程的资产库，手写内容里用记号引用它：

```html
<img src="asset://<资产标识>">
```

正文里**永远只有这个记号，没有真实地址**。真实地址由系统补上，而**补在哪些位置按槽给出**：

- `site` 槽：整份文本**逐字替换**。记号写在元素属性里、内联 CSS 的 `url()` 里、`srcset` 里都成立，不必照着属性列表挨个写对。
- `docs` 槽：替换发生在**渲染那一趟**。markdown 图片与链接，以及正文里写的 raw HTML（含其中的内联 CSS）都会解开；**代码块、行内代码与普通文字里的记号原样保留**——那是给人看的文本，不是一处引用。

补出来的地址在两处不同，而**两处都不进你的源文件**：

- **网页端预览**：短时有效的预签名地址，几分钟后过期，刷新预览即得到新的。
- **发布**：站点内的路径；访问它时媒体会跳到内容寻址的公开地址，CDN 因此缓存得住，而撤回发布仍然立刻生效。

为什么不直接把地址写进正文：编辑态的地址会过期，发布态的地址又不同——写死了，正文里就躺着一个会漂移、甚至哪天失效的字符串。而且「这个引用是不是本工程的素材」会退化成拿地址前缀去比对，能被相似域名、大小写、重定向绕开。记号把这两件事都变成确定的：地址由系统给；是不是本工程素材，就是查一次标识。

`asset://` 不是浏览器认识的协议，这是有意的：漏掉补地址的记号不会被静默放过——**发布前置校验会拒绝它**，而不是留到读者的浏览器里变成一张裂图。**构建产物不需要记号**——它写的就是路径，原样生效。

## 看素材、拿资产标识

```bash
aladdin galaxy asset list <工程标识>
```

列出资产库里的每一项：标识、类型、字节数、文件名，以及一个短时读取地址。上传（`asset upload`）成功时也会打印新资产的标识——把它写进 `asset://` 记号里。

那个读取地址是一份**短期凭证**：有效期内谁拿到都能打开，因此**未发布的素材里不要放秘密**。过期后重新执行本命令即得到新地址；内容里的记号不受影响，因为它本来就不存地址。

## 走一遍

```bash
# 建工程，记下它打印的工程标识
aladdin galaxy project create --slot site --name "我的站点"

# 把发布根交给构建命令，产物里的绝对路径才对得上
vite build --base "$(aladdin galaxy project base <工程标识> --slot site)"

# 整组推送一个目录（目录里没有的路径 = 删掉），再校验
aladdin galaxy draft push <工程标识> ./dist --slot site
aladdin galaxy validate <工程标识> --slot site

# 存成一个版本，发布它，拿到地址
aladdin galaxy version save <工程标识> --slot site
aladdin galaxy publish <工程标识> <版本标识> --slot site --yes

# 发布之后核对：按访客的路径把产物取回来，逐条复核引用有没有解开
aladdin galaxy publication verify <工程标识> --slot site

# 后来想加上文档：加一个文档槽，再往那个槽推（槽只增不删）
aladdin galaxy project slot add <工程标识> --slot docs
aladdin galaxy draft push <工程标识> ./docs --slot docs
```

`--slot` 在只有一个槽的工程上可以省略；两个槽都有时必须给，否则命令行不知道该打到哪一个。服务端始终要求显式的槽。

`validate` 校的是**已保存的草稿**（推送是唯一的写入路径），有问题时逐条列出文件与行号并以非零状态退出，所以 `validate && publish` 这类写法成立——「这份内容不能发布」是一个结论，不是一次调用失败。

`publish` 的返回值只说「发布成功了」：产物里的地址是渲染时补上的，源里、版本里都只有记号。所以发布之后还要能读回来核对——`publication verify` 按访客走的那条地址把产物取回来，复核取回的字节与发布记录是否一致、产物里有没有残留的记号、每一处引用是否都落在产物清单上、每一条素材是否可达；读清单用 `publication get`（加 `--path` 取其中一份的字节）。

把内容取回本地有三条路：正在编辑的那一份用 `draft pull`，某一版用 `version pull`，**已经发出去的那一份**用 `publication pull`——前两条取的是你推上去的源，最后一条取的是访客拿到的东西。

## 边界与危险操作

每一处**取资源**的引用都必须落在这一组文件里：指向外部地址、别的工程、或不存在的位置，发布会被拒绝，提示里带着文件和行号。链接到外部网站不受此限——那是你的意图，不是资源引用。`docs` 槽下文档之间的相对链接同理，指向不存在的位置即拒绝；页面内的锚点也要指得到——`#小节` 对不上目标那一页的标题即拒绝。

发布出去的站点是**公开匿名**的：拿到地址的人就能看，所以发布物里不要放秘密。正因如此，工程标识不可猜，也没有「列出所有已发布工程」的入口。

`publish` 与 `project` / `version` / `asset` 的删除是危险操作：交互式下二次确认，脚本里必须显式传入 `--yes`。撤回发布（`unpublish`）不是——它是发布的反向操作，一步就能让每一条地址都不可达，且不产生新的暴露。
